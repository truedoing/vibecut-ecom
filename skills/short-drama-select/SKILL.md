# 短剧选片 · 建包前的做 / 不做

> **命名（2026-11-10 20:1x 张老师定）**：对外叫「选片」，不再叫「选品」——
> 品类是「一类货」，可我们库里放的是一部部具体的剧，词和东西对不上。
> 存量实例 `docs/八零憨妻_选品决策书.md`、历史台账与过程文档**保留原文、不迁移、不删**；
> 机器字段 `select` 也保持不变。

> **轻重定位（2026-11-11 13:3x 张老师拍板）**：选片是漏斗第一道，处理「几十部里挑几部」。
> **第一道必须便宜**——一旦要抽帧、取字幕，就不是选片，是提前建了半个资料库。
> 所以本地素材包一律**看简介 + 看文件目录**就能判，**一部剧 30 秒**。
> 重活（抽帧、台词库）留给建包之后的索引环节，只花在已经决定要做的剧上。

**为什么必须有这一环**：踩过三次坑都在选剧判据上——任务页看着能领、
素材链接其实过期；按「最高收益」排序把最卷的剧排第一；任务介绍写【漫剧】其实是实拍。
选错剧，后面建包、抽台词、排段表全白做。

## 第 0 步：先问素材从哪来（2026-11-11 新增）

素材来源不同，能查到的东西完全不同，判据不能混用。

| 来源 | 特征 | 走哪套 |
|---|---|---|
| **平台任务** | 有任务页、素材链接、结算说明 | 下面 A 套（六条硬门禁＋官方四项指标） |
| **本地素材包** | 磁盘上一堆 mp4，可能带简介/剧本/角色图 | 下面 B 套（六条轻查） |

**别把 A 套的字段往本地包上套**，那些字段本地根本不存在；
也别拿 B 套去判平台任务，会漏掉结算和投稿数这两条真正致命的。

## 暂定定位（2026-11-11 张老师定）

**做家庭伦理类**：婆婆媳妇、亲子、婚姻、认亲、养老这些。
不是这个类型的，A/B 两套都不用走完，直接淘汰。

## A. 平台任务（原有流程，一字不改）

### 硬门禁：领任务前 30 秒，顺序别反

| # | 查什么 | 不过怎么办 |
|---|---|---|
| 1 | **先点素材链接**，能打开、能下载 | 立刻换剧，别耗时间 |
| 2 | 任务存在、能领、「去发布」按钮可用 | 否 |
| 3 | 投稿作品数（优先 <5 万） | 30 万说明已被剪烂，同质化限流 |
| 4 | 展开「任务介绍」+「必须完成以下要求」（指定片段/时长/字幕规范） | 漏了投稿驳回 |
| 5 | 点「点击试看」确认是**实拍** | 避开 AI 仿真人剧与漫剧 |
| 6 | 结算说明的计费口径（IAA 广告分成最干净） | 与角标矛盾要再确认 |

**第 1 条排第一是实盘换来的**：《明月曾照彩云归》任务截止 2028-12-31，
素材链接已过期，任务页完全看不出来。**任务有效期 ≠ 素材链接有效期。**

> 第 5 条「确认实拍」补一句（11-11）：**平台收不收 AI 剧二创，以任务页要求为准**。
> 本地包不受这条约束——本地这几部全是 AI 生成剧，张老师已明确不设卡。

### 官方四项指标（详情页逐项记数）

前 3 集留存（越高越好）/ 退款率（越低越好）/ 投诉率（越低越好）/ 小程序点击率（参考）。

- **别按佣金率选剧**：高佣常配高退款、高投诉。
- **「最高收益」是任务累计上限，不是可得收益**，别拿它排序。
- 奖池剩余比例**只判任务新旧，不单独用于选剧**。
- 字段口径对不上（0 投稿 + 0 支付，奖池却已消耗 9.2%）→ **只做定性判断，不做算术推算**。

### 信息层（平台任务仍按此做）

抽前 3–5 集帧 + 台词 OCR → 出一张信息提取卡，写清三件：
**剧情前提**（20 秒能交代完）、**人物关系**、**风格**（苦情 / 轻喜 / 爽剧反杀）。

**信息源优先级**：本地素材 ＞ 任务页实盘字段 ＞ 任务介绍模板文案 ＞ 离线打分 ＞ 外部搜索。
外部搜索实测无效且有害（登录墙 + 全网剧名返回同名不同剧），只标 `verified:false` 不当事实用。

> **抽帧取字幕统一归索引环节**（2026-11-11）：选片不再自己另写一份。
> 要提前看几集，也调索引那只脚本：
> `extract_lines.py --drama <剧名> --ep 1 2 3 --step 1`，产物落在索引该放的位置，
> 后面跑 `--all` 时自动跳过，不重复劳动。

### GO 的三条约束（平台任务口径，必须写进数据表口径）

1. 点击率只能做同剧 6 条之间的**相对比较**，不能当钩子能力的绝对分数（剧冷会系统性压低）。
2. 两周目标 = 跑通流程 + 钩子数据 + 单条耗时，**不是收益**，别用钱判成败。
3. W2 换一部投稿数高、已有支付记录的剧做横向对照，才能把「剧的影响」从「钩子的影响」里分开。

## B. 本地素材包（2026-11-11 新增，轻量版）

**输入只两样：简介文本 + 文件目录。不抽帧、不取字幕、不打分。**

| # | 查什么 | 怎么判 |
|---|---|---|
| 1 | **题材** | 是不是家庭伦理（婆婆 / 亲子 / 婚姻 / 认亲 / 养老）。不是 → 淘汰 |
| 2 | **冲突够不够** | 简介里有没有「当众不认亲 / 赶出门 / 抢婚 / 离婚 / 打脸 / 造谣陷害」这类硬冲突。只判**强 / 中 / 弱**，不打分、不算密度 |
| 3 | **一条线还是反复** | 一条因果链走到底 = **主线**，做长（4–6 分钟）；打压-反击反复 = **副线**，做短（2–3 分钟） |
| 4 | **素材能不能用** | 能不能解码、集数齐不齐、竖屏横屏。看一眼目录 + 一次 ffprobe |
| 5 | **资料厚度** | 只有视频 / 带简介 / 带简介＋剧本＋角色图。决定后面省多少工 |
| 6 | **风险一句话** | 有没有版权证明（承诺函、时间戳）、题材有没有踩线。**现在只写一句，慢慢丰富** |

**明确不做**（11-11 张老师拍板）：

- **不算钩子密度**：任何剧冲突都多，量化它等于把抽帧取字幕压到漏斗最前面。
  「前几集够不够撑几条片子」推迟到建包后，用索引出的台词汇总回头校验。
- **不分析商业价值**：本地剧没有分成协议，绝对值那一栏是空的，先不填。
- **不抽帧、不取字幕**：退出选片，归索引环节。
- **不查平台后台四项指标**：本地没有这些数据。

### 资料厚度怎么用（只记一笔，不建库）

| 有什么 | 后面省什么 |
|---|---|
| 只有视频 | 全部靠索引抽帧＋识别，最费工 |
| 带简介 | 故事线不用猜，省一轮试错 |
| 带剧本 | **实测只写到第 1 集**，只能当第 1 集的校准答案（切点准不准），不是台词库 |
| 带角色三视图 | 建角色资产时直接可用；**图里有脸，不能当参考图送审**，只能当造型参照 |

## 输出（2026-11-11 改）

**默认产出一张表，不是一剧一份文档。**

```
runs/选片候选表.md          # 一部剧一行：题材 / 冲突 / 线型 / 素材 / 资料 / 风险 / 结论
runs/<剧名>/选片结论.md      # 只有判 GO 的剧才写，半页：依据 + 定主线副线 + 待确认项
状态.json → artifacts.select # {rev, state, depends_on: [], decision: GO|NO-GO}
```

**NO-GO 就是终点**：不建包、不抽台词。表里留一行，等下一部剧。

> **路径口径（11-10 统一）**：选片结论是**全剧级**，一部剧一份，落 `runs/<剧名>/`，不带 task 层。
> 存量实例 `docs/八零憨妻_选品决策书.md` 是 11-08 首例，保留旧名不迁移、不删；
> 台账 `artifacts.select.path` 写它的真实路径即可。
