# 短剧集包创建

**造数据，不是写文案。** 一个剧集包 = 这部剧下所有解说视频共同依赖的只读知识层。

> **为什么与商品包分开**：短剧的「事实」不是厂商给的，是**从原片里挖出来的**——
> 没有剧集页、没有百科、没有剧评，信息只能靠抽台词。合规体系也不是《广告法》，
> 而是平台二创规则 + 素材授权范围。两者共用一个 schema 只会让字段互相说谎。

## 一句话区分：商品包问「这东西是什么」，剧集包问「这部剧讲了什么、哪里能断」

| | 商品包（light-food / book） | 剧集包（本技能） |
|---|---|---|
| 事实来源 | 包装标签、商品页、检测报告 | **原片台词、画面、平台任务页** |
| 核心资产 | 卖点话术转换 | **高能节点 + 可截断点 + 开场白** |
| 主要红线 | 广告法、标签法、功效宣称 | **平台二创规则、授权范围、剧透** |
| 下游消费 | 口播脚本 | 解说脚本 + 混剪清单 |

## 何时使用

- 开始推一部新短剧，手上只有原片素材和任务页
- 已有剧集包要补台词时间码、补人物关系、补合规条目
- 检查一个剧集包是否合格（跑 `scripts/validate_pack.py`）

**不要用它**：写解说词（那是文案技能）、剪片子、改任务状态、建商品/图书包。

| 文档 | 管什么 | 什么时候读 |

## 输入

| 参数 | 说明 |
|---|---|
| `drama` | 剧集 id，建议与素材目录同名 |
| `materials` | 原片（尽量带音轨、**无 BGM 版优先**）、平台任务页截图/字段、已有字幕文件 |
| `platform` | `kuaishou` / `douyin` / 其他；决定红线表加载哪份 |
| `license_scope` | 授权范围（任务内素材 / 厂商授权 / 无授权）。**无授权不得建包** |

**材料不齐不是停工理由**：不知道的写 `null` + `placeholder` + `pending`，绝不编。

## 三条剧集专属铁律

1. **不看结局，也不许把结局写进包。** 不知道结局的人写的悬念才是真的；平台也明确
   放结局画面会降转化、易判低质。`compliance.ending_policy` 固定 `do_not_use`，
   `asset_index.finale_episodes` 必须写明哪几集不能碰。
   > **v1.1 边界补充（2026-11-09，加 `story_arc` 时定）**：这条铁律管的是**面向观众的那一层**
   > ——`hook_map`、`elements.golden_quotes`、口播与字幕，结局一律不进。
   > `story_arc` 属于**内部知识层**（分幕必然覆盖到结尾），所以它的门禁不是「不写」，
   > 而是「写了必须关死出口」：`usable_in_copy` 强制 false，校验器对此判 ERROR。
   > 换句话说：**概要可以知道结局，但一个字都不许流到文案里。**
2. **每句台词必须可回溯到「第几集 + 秒」。** 没有时间码的金句不算证据，只是印象。
   `hook_map` 和 `elements.golden_quotes` 的每条都要带 `ep` 与 `t`。
3. **人群必须从剧情推，不能套模板。** `elements.audiences` 每条要带 `evidence`
   （哪句台词、什么设定支撑这个判断），禁止写「中老年女性」了事。方法见
   `references/audience-inference.md`。

## 材料分级（越靠前越能当事实）

```
原片台词/画面实核验 ＞ 平台任务页实盘字段 ＞ 任务介绍模板文案 ＞ App 内同剧视频 ＞ 外部搜索
```

短剧的坑几乎全在第二档和第五档之间，四条实盘教训：

- **任务有效期 ≠ 素材链接有效期**：任务挂到 2028，网盘链接可能几天就失效。先点链接。
- **任务介绍是模板文案**：见到【漫剧】不代表是漫剧（本剧标签写【漫剧】，实拍抽帧证伪）；
  片单文档标题常见「短剧&漫剧」通用模板。**以本地素材为准。**
- **外部搜索是污染源**：八零题材模板化，搜剧名返回的多是同名不同剧、人名雷同，
  会把别剧剧情当本剧。只在没有素材时用，且必须标 `external_search` + `verified: false`。
- **平台字段不同步**：0 投稿 + 0 支付 + 奖池已消耗 9%，三者口径对不上 →
  **只做定性判断，不做算术推算。**

## 工作流（9 步）

### 1. 素材体检（不写包，先确认能不能干活）
目录结构、集数是否齐、分辨率/帧率/音轨、有无 BGM、有无内嵌硬字幕、大结局是哪几集。
任一项缺失 → 进 `pending`，`blocking` 视影响标。

### 2. 抽台词（本技能最耗时的一步，也是唯一的真信息来源）
按 `references/extract-method.md` 跑。产出「第 N 集 + 秒 + 台词」的原始稿，
存为 `docs/<剧名>_台词稿_前N集.txt`，作为包的回溯底稿。**包不复制台词稿全文**，
只放索引与金句。

### 3. 建人物关系
至少 3 人，必须有 protagonist 与 antagonist。每人要有 `evidence`：
哪一集哪句台词能证明这个位置。**别按剧名猜人物功能。**

### 4. 写剧情概要（`story_arc`，台词抽完才能写）
分幕（至少 3 幕，铺满全集不重叠）+ 转折点 + 单集循环结构。每条都要带 `ep`/`t`/原台词。

**为什么值得单独一步**：`logline` 只有一句话，到「分幕」之间原本是空的。
下游要判断「这一集该点哪句题」「哪一段值得跨集取高光」，没有概要就得回去翻全部台词——
本剧 19 集 508 句，翻一次十几分钟。概要就是这层的缓存。

三条写法：
- **`payoff` 写「结果」不写「感想」**——它决定切点：切在 payoff 之前吊人，之后收情绪。
- **幕次缺口/重叠会被校验器 WARN**——那通常说明分幕是拍脑袋分的。
- **`usable_in_copy` 必须 false**，校验器判 ERROR。概要含结局，出口关死。

### 5. 定风格（决定叙述者口吻，也决定整包的调子）
三个判断：苦情 / 轻喜 / 爽剧反杀；冲突密度（密集小冲突 vs 大反转）；
结局走向（暖收 / 悬念 / 开放）。风格判错，王婶的口吻就全错——
本剧曾先判「苦情」、看到台词后推翻为「轻喜反杀」，同日两次翻案，见过程文档。

### 6. 挖钩子（写 `hook_map`，这是本技能的核心产出）
按「高能节点 → 可截断点 → 开场白」三件套写，一条一个节点，**至少 6 条**（要撑 6 条视频）。
`truncate_at` 必须是**一句话说完、观众自然想问「后来呢」**的位置，不是随便一刀。
禁止用结局画面做钩子。

### 7. 推人群（写 `elements.audiences`）
按证据表推，不套模板。结论要能回答：这个人在哪、多大、经历过什么、为什么会为这段剧情停下来。

### 8. 合规（写 `compliance`）
五类必查项一个都不能空，见 `references/platform-rules.md`。
短剧特有的一条：**「傻」「残」这类词，引用原剧台词可以，解说旁白里不能当描述用**。

### 9. 校验 + 人审
`python3 scripts/validate_pack.py packs/short-drama/<剧名>/drama-pack.json`
零 ERROR 后写 `剧集包说明.md`（人审版），再交人审。**未经人审不得上传 tdrive。**

## 输出

```
packs/short-drama/<剧名>/
├── drama-pack.json      # 机读源，10 块，只放值与开关
└── 剧集包说明.md         # 人审版：渲染本包结论，不放决策过程
```

> **JSON 只放「值 + 开关」**：`value` / `verified` / `usable` / `blocking` / `status` / `placeholder` / `ep` / `t`。
> 解释性文字（为什么这样判、方法论正文、翻案理由）一律进 `剧集包说明.md`。

## 自检三问（过了校验器还要问）

1. 一个没看过这部剧的人，拿这个包能不能写出钩子？——**不能就说明 hook_map 不够具体**
2. 每条台词能不能靠 `ep` + `t` 回到原片？——**不能就不是证据**
3. 删掉这部剧的名字，这个包还能用在该剧上吗？——**不能就说明没写具体，只写了套话**
