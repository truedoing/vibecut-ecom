# 台词提取工序（建包第一步，也是唯一的信息来源）

短剧没有剧集页、没有百科、没有剧评。**信息只能从原片里挖。**
本工序的产出是「第 N 集 + 秒 + 台词」的原始稿，它既是建包底稿，也是日后所有钩子的回溯凭据。

## 先判路线

| 素材形态 | 走哪条 | 成本 |
|---|---|---|
| 内嵌硬字幕（画面里有字） | **字幕 OCR**：抽帧 → 裁字幕区 → OCR → 去重 | 5 集约 2 分钟 |
| 无字幕、有对白音轨 | **ASR 转写**，再用时间轴对齐 | 取决于音频长度 |
| 有外挂 `.srt` / `.ass` | **直接解析**，最省事且时间码精确 | 几秒 |

先 `ffprobe` + 抽一帧看一眼，别凭想象选路线。

## 路线 A：字幕 OCR（本机实测可用）

```bash
# 1. 每 2 秒抽一帧，只裁字幕区（720×1280 竖屏实测坐标：y 820–1020）
ffmpeg -i "第1集.mp4" -vf "fps=1/2,crop=720:200:0:820,scale=1440:400" -q:v 3 -y "/tmp/subs/ep1_%04d.jpg"

# 2. OCR：本机无 tesseract / easyocr / paddleocr，但有 swift，用 macOS Vision
swiftc -O -o /tmp/ocrbin /tmp/ocr.swift
/tmp/ocrbin /tmp/subs/*.jpg > /tmp/ocr_out.txt
```

`ocr.swift` 要点：`VNRecognizeTextRequest`，`recognitionLevel = .accurate`，
`recognitionLanguages = ["zh-Hans"]`，`usesLanguageCorrection = false`（关掉纠错，保留原样）。

**裁字幕区的坐标必须自己抽帧确认**，不同剧的版式不一样（有的字幕在 y 940，有的 y 820）。
裁错的表现是"OCR 结果为空"或"只识别到半行"。

## 路线 B：直接复用去字幕管线的报告（更准，推荐）

`vibecut desub` 的检测阶段本来就在做逐帧 OCR，`report.json` 里有
`removed_texts`（去重后的整句）与轨迹时间。用它当台词稿，比另写一套脚本更准。

```bash
cd <repo> && /opt/anaconda3/bin/python - <<'PY'
from pathlib import Path
from vibecut.desub.pipeline import run_file
src = "/path/to/第1集.mp4"
r = run_file(src, 0, 132, Path("/tmp/ep1_check"), analyze_only=True)
print(r["subtitle_tracks"])
PY
```

实测：10 秒样本 34 秒跑完，`risk` 判定可靠，`texts` 数组就是整句台词。
**注意**：它给的是「出现过的句子集合」，不是严格时间轴；要精确秒数再看轨迹。

## 去重与整理

- 相邻帧同一句只留第一次出现。
- 被后一句完全包含的重复去掉（字幕换行会把一句话拆成两次识别）。
- 保留时间 = 帧序号 × 2 秒，**精度 ±2 秒**，够用但要在稿头注明。

产物格式（供 `hook_map` 回溯）：

```
=== 第1集（49 句，时间=帧序号×2秒）===
[ 62s] 建军哥！建军哥！我是小满！
[100s] 我不是傻姑娘，我叫苏小满。
```

## 已知误差（写包时必须承认）

1. **时间码 ±2 秒**：抽帧间隔决定精度。要精确到 ±0.5 秒就对目标段单独 `fps=2` 重抽。
2. **OCR 有错字**：实测「你小市点」= 你小心点、「妽子」= 婶子、「丟」= 丢。
   凡是要进口播的句子，**必须回原片听一遍**。
3. **多行字幕会拆句**：一句话被识别成两条是常态，整理时要合并。
4. **不看结局**：抽集数范围默认前 N 集，**不要抽大结局**，理由见 SKILL.md 铁律一。

## 覆盖多少集够用

**前 3–5 集足以建包。** 类型片套路固定，人物位置和冲突模式在 3 集内就立住了。
后面是变体，边际信息量低。超过 8 集再抽，收益已经很小。

> 反直觉但重要：**没有官方简介反而是好事**。平台若给统一简介，所有达人会写出同一套解说词，
> 直接撞同质化限流。信息不对称正是这套流程的壁垒。
