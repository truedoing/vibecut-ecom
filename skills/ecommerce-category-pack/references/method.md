# 建包方法论

规则是**从真实事故里长出来的**，不是事先设计的。每条下面都标了它防的是哪一次踩坑。

## 一、三条硬设计

### 1. `verified` 双来源标记 —— 防「用顺手了就当真」

厂商卖点图、竞品台词、我方旧脚本，是三种**口径**，不是三种证据。

实战：羽衣甘蓝包迁移时发现，「配料表就一行：羽衣甘蓝」在四个版本文案、三条脚本里
反复出现，但**从未拿正式包装核对过**。它不是事实，只是"我们一直这么说"。
已标 `verified: false` + `blocking: true`。

反例对照：虎坚果酱的「每 100g 膳食纤维 9.2g / 维E 7.32mg」在详情卖点图与
**包装背面正式营养成分表**上完全一致 → 这条可以 `verified: true`，直接念数字。

> 下游文案技能只读 `verified: true`；其余自动转占位符。
> 这一条从根上挡住"编造价格/规格/营养数值"。

### 2. `blocking` 分级 —— 防「待核实项一视同仁」

缺 SC 编号不卡配音；规格/价格/配料表缺了就是不能念。
不分级的结果是要么全部停工，要么带着三个占位符直接配音。

| blocking | 含义 | 例 |
|---|---|---|
| `true` | 不解决不能配音 | 【规格】【到手价】【单条价】、配料表全文 |
| `false` | 核不到就整段删 / 不影响出稿 | 承保编号、基地出处、专利号、T3 素材 |

### 3. 冲突不自动选值 —— 防「替人挑错 SKU」

实战：虎坚果酱 10 张图里规格出现 **150g / 230g / 108g** 三个数，品名出现
「虎坚果酱」与「油莎豆坚果酱」两种叫法。若自动取一个，另外两个 SKU 的文案全废。

做法：产出 `conflicts` 清单，`values` 每项带 source，`resolution` 写「待定」，
`status: open`。三类冲突都要列：

| 类 | 实例 |
|---|---|
| 多来源数值打架 | 虎坚果酱 150g / 230g / 108g |
| 口径冲突 | 羽衣甘蓝「仙女饮品」vs 实际投放中老年女性 |
| **厂商话术与正式标签自相矛盾** | 虎坚果酱「轻盈无负担 / 减脂期解馋」vs 标签脂肪 44.9g、能量 2449kJ |

第三类最容易被漏掉，因为它不是"两个来源不一致"，是**同一个厂商自己打自己**。
发现后草稿先绕开（改用别的话术），但 `status` 仍保持 `open` 交人裁决是否要求厂商改口径。

> 校验器会检查 `resolution` 里有没有「选定/采用」这类词，防止偷偷裁决。

## 二、材料分级（决定证据权重）

```
包装正式标签实拍  ＞  平台商品页 / 检测报告  ＞  厂商详情卖点图
                 ＞  竞品视频台词  ＞  我方旧脚本  ＞  推断
```

- **包装实拍最值钱**：正面标定品名与规格，背面标定配料表全文、营养成分表、
  SC 号、生产商、保质期、贮存条件、致敏物质。
- **详情卖点图是招商口径**：有数值、有产地故事、有工艺，但"0 添加""≈15 颗松子仁"
  "媲美橄榄油"属自述，未与标签核对前一律 `verified: false`。
- **竞品台词的正确用法**：不是拿来当事实，是拿来**穷举话术元素库**。
  羽衣甘蓝实测 90 条竞品画面严格筛后只有 6 条 / 23.6 秒可借（其中 5 条还是别人的产品），
  但 74 条 ASR 台词抽出了 8 个钩子型、9 个痛点、6 个场景、4 类价格话术。
  **画面几乎不可借，台词是金矿。**

## 三、话术转换：商家视角，促销优先

> 「你不要太严格，商家提供的卖点，你可以换种更合适合规的方式话术，
> 但不要直接不用，我们毕竟是商家不是监督局，首要任务还是促销。」（2026-11-03）

**默认动作是「原话保留」**：`usable_rewrite` = `vendor_claim` 逐字，
`status: conditional` + `condition` 写清前提。只有下面几类才动笔，
且每一类都必须**同一语义内核**：

| 动作 | 做法 | 正确例 |
|---|---|---|
| 等价降级 | 只去风险谓语 / 补依据，内核不变 | 富含高膳食纤维 → 每100g 9.2g 膳食纤维 |
| 去比较对象 | 只报自己的数 | omega-9 媲美橄榄油 → 每100g omega-9 33.1g |
| 补出处 | 加「按…折算」+ 出处 | 一勺≈15颗松子仁 → 按《中国食物成分表》折算… |
| 去绝对词 | 保留内核，去掉 100% / 0 添加 | 100% 天然甜 → 没加白砂糖，甜是油莎豆自己的 |

> ⚠️ **转换丢了内核 = 偷偷删了卖点**。「饱腹感强」≠「一勺能抹满一片面包」：
> 前者是体感，后者是用量/覆盖面积，两者没有关系，不能互为改写。
> 同理：专利 ≠ 耐吃、不上火 ≠ 低温慢烘、每日营养 ≠ 一日三餐场景、
> 健康能量 ≠ 家里常备一罐、饱腹 → 下午配茶。这些都是**另造了一个卖点**。
> 拿不准就不改，原话保留 + condition 约束，比换掉安全得多。

**有数值就别喊"富含"**，念数字比喊形容词更有信任感，也更合规。

**真正不能改写的只有四类**（详见 `compliance-base.md`）：
疾病功效、无依据虚假比较、无认证宣称、虚假价格稀缺。
外加一条安全底线：**过敏原反向宣称**（虎坚果酱包装写明生产线加工花生芝麻，
绝不能说「不含坚果」「坚果过敏也能吃」）。

**禁词表是兜底检查，不是写作起点。** 写作从 `usable_rewrite` 出发。
改写落点「场景/口感/配料/数字/产地」正好是视频号中老年最吃的五类——
把说服力从身体改善挪到生活场景，是挪到更容易成交的地方，不是削弱促销。

### 边界：创作金句 ≠ 卖点转换

「一勺就够，抹得开，一罐能吃很久」这类用量/性价比金句可以进
`elements.golden_quotes` 当创作素材，但**不能当作厂商卖点的转换写进
`selling_point_map`**——厂商原话里没有「耐吃」，它是另造出来的。

厂商话术与正式标签自相矛盾时（如「轻盈无负担」vs 脂肪 44.9g），
包的做法是**原话保留 + 标 `open` 交人裁决**，不替厂商改口径、也不删卖点。

## 四、七库怎么穷举

- **钩子 8 型**：跨品类可复用，标 `已用 / 可用 / ⚠️ 擦边 / ❌ 红线`
- **痛点与场景**：同品类矩阵的产能主体，**尽量穷举**（羽衣甘蓝 9 个痛点 / 6 个场景）
- **论据 L1–L4**：L1 参数（需核）、L2 体感（最安全）、L3 对比（需换算/价格）、L4 场景
- **信任 T1–T3**：T3 缺了明写 `❌ 缺口`，不要拿 T1 凑数。羽衣甘蓝无销量/复购/反馈，
  这是所有脚本共同的短板，靠写解决不了
- **CTA / 金句 / 价格话术**：竞品口径只作结构参考，数字一律不得编造

## 五、审核与发布

两层审核性质不同，**别混**：

| | 自己审 | 制作前审 |
|---|---|---|
| 谁 | 出包者自检 | 人在 vibecut UI 决定能否开工 |
| 审什么 | 结构、禁词、待填项、事实是否对上 | 包是否批准 |
| 落在哪 | `meta.review.self_check` + 校验器 | `meta.review.human_review` |

**技能不碰状态流转**——只标初始状态，UI 改状态（SQLite 唯一真源）。

发布顺序：**本地 draft → 人审 → 明确确认 → 上传 tdrive**。
品类包比文案更需要审：文案错一条是一条，包错一次是全品类。
`packs/` 是暂存不是共享源；`published_to_tdrive` 默认 false。

## 六、六条常见漂移

1. 把厂商卖点直接判禁用（监督局视角）→ 应先试改写
2. 把竞品台词当事实 → 它是话术库原料，不是 product_facts
3. 把旧脚本里反复出现的话当已核实 → 查有没有正式标签
4. 冲突里偷偷挑一个值 → 列清单交人
5. 把人群红线、方法论正文抄进包 → 写 ref，包只放品类专属
6. 产物膨胀 → 一份包配得上一个品类的分量；七库可以长，但别抄规则全文
7. 转换换成不相干卖点 / 说明写成决策记录 / 包里引用另一品类 → 原话保留、
   只渲染本包数据、包与包孤立
