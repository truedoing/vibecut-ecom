# 电商品类包创建

**造数据，不是写文案。** 一个品类包 = 这个品类下所有文案共同依赖的只读知识层。
流程一套、数据按品类注入；羽衣甘蓝和虎坚果酱用同一个技能，差别全在包里。

> **为什么独立成技能**：建包低频高杠杆——包错一次，这个品类下所有文案全错；
> 文案高频但单条影响有限。两者的判断类型也不同（事实判定/合规分级/冲突核对
> vs 角度/结构/举证配额），混在一起文案技能会重新变胖。
> 团队真正要共享的不是文件，是**造文件的能力**。

## 何时使用

- 新增一个带货品类，需要把厂商给的一堆资料变成可用知识
- 已有品类包要补正式标签、核数值、加新品类专属合规条目
- 检查一个品类包是否合格（直接跑 `scripts/validate_pack.py`）

**不要用它**：写具体口播脚本（那是 `ecommerce-script-gen`）、生成画面、剪片子、改任务状态。

## 开工前必读

| 文档 | 管什么 | 什么时候读 |
|---|---|---|
| `references/pack-schema.md` | 7 块结构、字段定义、模板 | 写 JSON 前 |
| `references/method.md` | 材料分级、三条硬设计、话术转换原则 | 全程 |
| `references/compliance-base.md` | 通用四类红线 + 兜底禁词 | 做话术转换时 |
| `references/platform-audience.md` | 平台×人群参数表（**共享参数，不进包**） | 判断人群口径时 |

> ⚠️ **跨会话调用前先 `ls -lT` 看本技能文件时间戳。** 换代时会改 schema，
> 手上加载旧版会导致写完才发现字段不对。

## 输入

| 参数 | 说明 |
|---|---|
| `category` | 品类 id，**必须与 `vibecut project list` 里的项目名完全一致** |
| `materials` | 包装实拍（正/背标）、详情卖点图、商品页文字、价格、检测/认证、参考视频台词、旧脚本 |
| `mode` | `vendor_provided`（厂商提供素材，新流程）/ `legacy_competitor_clips`（竞品截取，旧流程） |
| `reference_pack` | 可选，已有品类包**仅作结构参照**；参照包的品类名与数据不得写进新包 |

**材料不齐不是停工理由**：不知道的写 `null` + `placeholder` + `pending`，绝不编。

## 工作流（10 步）

### 1. 材料分级（决定 verified 的来源权重）

从强到弱，越靠后越不能当事实：

```
包装正式标签实拍 ＞ 平台商品页 / 检测报告 ＞ 厂商详情卖点图 ＞ 竞品视频台词 ＞ 我方旧脚本 ＞ 推断
```

**厂商卖点图 ≠ 正式标签。** 招商口径里的数值、"0 添加"、"≈15 颗松子仁"都属于自述，
只有与正式标签核对过才能标 `verified: true`。

### 2. 抽 `product_facts`

每条必带四样：`source`（type + ref）、`verified`、`usable_in_copy`、`blocking`。
常见 field：`product_name` / `product_type` / `ingredients` / `nutrition` / `net_weight` /
`price` / `origin` / `process` / `certification` / `allergen` / `storage` / `usage`。

> **最容易漏的一条**：旧脚本里反复出现的话（如「配料表就一行」）不等于核实过。
> 迁移旧资产时，凡只在脚本/竞品台词里见过的，一律 `verified: false`。

### 3. 做 `selling_point_map` —— 卖点尽量保留，转换必须同一内核

**商家视角、促销优先：厂商卖点尽量保留原话。**
`usable_rewrite` 默认 = `vendor_claim` 逐字（`status: conditional` + `condition` 写清前提）。
只有下面几类才动笔，且每一类都必须是**同一语义内核**：

| 动作 | 做法 | 例 |
|---|---|---|
| 等价降级 | 只去风险谓语 / 补依据，卖点内核不变 | 富含高膳食纤维 → 每100g 9.2g 膳食纤维 |
| 去比较对象 | 只报自己的数 | omega-9 媲美橄榄油 → 每100g omega-9 33.1g |
| 补出处 | 加「按…折算」+ 出处 | 一勺≈15颗松子仁 → 按《中国食物成分表》折算… |
| 去绝对词 | 保留内核，去掉 100% / 0 添加 | 100% 天然甜 → 没加白砂糖，甜是油莎豆自己的 |

> ⚠️ **禁止换成另一个不相干的卖点**：「饱腹感强」≠「一勺能抹满一片面包」
> （前者是体感，后者是用量/覆盖面积，两者没有关系）。同理，专利 ≠ 耐吃、
> 不上火 ≠ 低温慢烘、每日营养 ≠ 一日三餐场景、健康能量 ≠ 家里常备一罐。
> **转换丢了内核，等于偷偷删了厂商卖点**，比直接禁用更糟。拿不准就不改。

每条必须有 `usable_rewrite` + `condition`。
只有四类红线可以给 `usable_rewrite: null` + `status: blocked`：
疾病功效、无依据虚假比较、无认证宣称、虚假价格稀缺（外加过敏原反向宣称）。

### 4. 做 `compliance_ext` —— 只放品类专属

平台×人群的三张红线表属**人群属性**，在技能自带 `platform-audience.md`，
**不要复制进包**。品类包只收这个品类特有的：过敏原反向宣称、儿童表述、
品类易踩的功效暗示、换算宣称的依据要求、本品类认证要求。

### 5. 建 `elements` 七库

`hooks` / `pains` / `scenes` / `proofs`(L1–L4) / `trust`(T1–T3) / `ctas` / `golden_quotes`，
外加 `price_talk`。每条标 `source`（竞 epN / 自 TaskN / 厂商 / 推断）与 `status`。

**痛点池与场景池是同品类矩阵的产能主体**，尽量穷举；钩子跨品类可复用。
竞品视频里画面几乎不可借，但**台词转写是元素库的金矿**。
T3（销量/复购/真实反馈）缺了要明写 `❌ 缺口`，不要拿 T1 凑数。

### 6. 列 `pending`，按 `blocking` 分级

`blocking: true` = 不解决不能配音（规格、价格、配料表）；
`false` = 核不到可整段删或不影响出稿（认证编号、基地出处、T3 素材）。
每项写清 `owner` 与 `how_to_resolve`。

### 7. 定 `asset_index.mode`，填四层与硬约束

`vendor_provided`（新流程：厂商素材 `assets ingest` 入库）/ `legacy_competitor_clips`（旧流程）。

四层的**代号 A–D 固定，名称按 mode 调整**：

| 层 | `vendor_provided` | `legacy_competitor_clips` |
|---|---|---|
| A | 厂商提供素材（~45%） | 通用素材站 CC0（~45%） |
| B | 自有产品镜头（~30%，硬约束） | 自有产品镜头（~30%，硬约束） |
| C | AI 生成钩子（~15%） | AI 生成（~15%） |
| D | 自有录屏（~10%） | 自有录屏（~10%） |

**B 层硬约束不随 mode 变**——包装、配料表、堆头、撕开动作、并置，外部渠道拿不到，
用别人的就是虚假背书。一致性锚点（台面/光线/餐具/色温）也要记。
包里只放素材 id 与索引，**不放媒体本体**（媒体永不上传云端）。

### 8. 待裁决清单写说明.md，JSON 的 `conflicts` 固定 `[]`

**JSON 是给下一步生成脚本用的，不放「待定」信息。** 同一字段多来源多值时：

- 有明确优先来源（正式标签 ＞ 卖点图 ＞ 竞品台词）→ **直接取值，不列冲突**；
- 真要人裁决的（厂商话术与标签打架、价格档位口径、定位口径）→ 一行一条写进
  `品类包说明.md` 的「人审待裁决」节，JSON 的 `conflicts` 保持 `[]`。

**挑错一个值，其余 SKU 的文案全废**——但那是人审的判断，不是机读源该承载的。

### 9. 出双产物，同一数据源

| 文件 | 用途 |
|---|---|
| `packs/{category}/category-pack.json` | 机读源，下游技能与 UI 消费 |
| `packs/{category}/品类包说明.md` | 数据视图 + 人读质量附录（人审在这里看） |

**不要两边手写**——必然漂移。说明.md 是 **JSON 的数据渲染 + 人读质量结论**：
头部一张元信息表（含「N 条事实 / M 条已核实 / K 项卡配音」），正文按 7 块铺表格，
末尾放「人审待裁决」清单。

> ⚠️ **JSON 只放值 + 开关**：`value` / `usable_rewrite` / 七库 / 合规条目 / 素材索引
> 是数据；`verified` / `blocking` / `status` / `condition` / `placeholder` / `pending`
> 是下游要读的开关。凡是「为什么核实 / 为什么这样改 / 方法论 / 待裁决理由」这类
> **解释性文字一律不进 JSON**，脚本一行都不会读它们。
> ⚠️ **说明不是决策记录**：不写用途、验证目的、跨包对照、方法论正文、原则、
> 理由、反转案例、通用性结论。能一行写完就不写一段。
> ⚠️ **每个包孤立隔离**：包内不得出现另一品类的名字、数据或流程对照；
> 结构参照只发生在技能层，通用性结论写进技能文档或过程文档，不写进包。

### 10. 校验 → 自检 → 人审 → 上传

```bash
python3 scripts/validate_pack.py packs/{category}/category-pack.json
```

**必须跑，不要靠肉眼。** 校验过了只说明结构合格，不代表事实核实过——
`verified: false` 的条目校验器不会替你变成 `true`。

把自检结论写进 `meta.review.self_check`。**品类包比文案更需要审**：
文案错一条是一条，包错一次是全品类。

> ⚠️ **上传 tdrive 是项目资料库写操作：必须先给人看变更清单、拿到明确确认才执行。**
> 未经确认不得上传、不得覆盖。本地 `packs/` 只是 draft 暂存，不是共享源。

## 输出契约（下游怎么消费）

下游文案技能**只读 `verified: true` 的 `product_facts`**，其余自动转占位符；
写作从 `selling_point_map.usable_rewrite` 出发，不从禁词表出发；
`pending` 里 `blocking: true` 的项未解决前，涉及它的句子不得配音；
`meta.category` 用于对齐 vibecut 台账项目名。

## 边界 · 容易漂移的地方

1. **不记运行态** —— 角度占用、任务状态、run_id 属于 vibecut 台账，绝不进品类包
2. **不复制共享参数** —— 平台×人群参数表、通用四类红线在技能里，包里只写 `*_ref` 引用
3. **不放媒体本体** —— 只有 id / 索引 / 授权范围
4. **不替人裁决冲突** —— 清单写说明.md，JSON 的 `conflicts` 固定 `[]`
5. **不编数值** —— 价格、规格、营养数值不知道就留占位符
6. **产物别膨胀** —— 一份包配得上一个品类的分量；七库穷举可以长，
   但别把方法论正文、准则全文抄进包里，用一句话指向技能 references
7. **本地 draft 不等于已发布** —— `published_to_tdrive` 默认 false
8. **包与包孤立、说明只渲染数据** —— 不得引用另一品类包；不放决策过程、
   验证结论或方法论正文。通用性验证写在技能文档或过程文档里
9. **机读源不掺解释** —— `verified_note` / `basis` / `notes` / `note` / `rule` / `mode_note`
   一律不进 JSON；数据质量结论与人审待裁决放说明.md
