# ecommerce-narration

description: "生成成片级旁白：按角色音色锚用 MiMo voiceclone 出音，自动转中文读音、测语速、算 atempo、提亮、校准响度峰值，一条命令跑到「达标或明确不合格」。触发词：配音、旁白、解说、录音、女声、男声。"

> **本技能不是入口。** 调度、进度、多线并发、门禁与状态台账一律走 `ecommerce-supervisor`；
> 本技能只负责「文本进、达标 mp3 出」，不判断「现在该不该做、做完该接谁」。

## 边界：只管声音，不管画面

**进来的是文本，出去的是一个达标的 mp3。**不切画面、不算句边界、不合成——那些是 `ecommerce-mix` 的事。

**为什么独立成技能**：音色锚是"资产"（一次性，建角色时造好），正式旁白是"后期"（每片一次，出片之后才配）。两者时间点、失败代价、返工链长度都不一样——旁白错了要重录→重算边界→重合成，链条长；混剪错了本地 30 秒重跑。混在一起，Agent 改一句话就得翻 ffmpeg 参数。

## 前置：音色锚必须在

`assets/ai_assets/characters/ch_NNN_中文名/voice.mp3`。这个锚丢了嗓子就丢了（voicedesign 每次现造音色、不返回 voice_id，无法复现）。造锚在 `ecommerce-ai-assets` 技能里。

**⚠️ 2026-11-05 起，锚的首选来源变了**：voicedesign 造的锚是"标准朗读"，实测把 voiceclone
压在 ≈13 半音/0.5 跳变的念稿水平，提示词怎么写都顶不破——**瓶颈在锚不在模型**。
首选改用 `ecommerce-voice-anchor` 从过审 AI 钩子里按台词位置截取角色音样（表现力高、
与钩子音色天然一致、零成本）。旧锚流程保留作兜底，造出的锚记得先测 F0 跨度再上岗。

**⚠️ 2026-11-06 起，片内锚是标准链路（张老师定）**：**每个角色每一片，锚从本片钩子里提**
——同一张角色卡两次 Seedance 生成的音色本就不完全一样，拿上一片的锚配这一片的旁白，
源头就不是同一把嗓子（T2_006 实测：「悄悄话」钩子接旧锚激情旁白，前后判若两人）。
顺序固定：**钩子人审过 → `ecommerce-voice-anchor` 从本片钩子提锚 → `narration.py
--sample <片内锚路径>`**。卡片 `voice.mp3` 只是兜底，不再当默认输入。
锚的来源永远可回查（就在本片 run 目录），钩子重出 → 片内锚作废 → 旁白 stale，
这条用 `状态.json` 的 depends_on 表达，不靠记性。

**情绪档跟随钩子弧线**（2026-11-06 定）：悄悄话/自白钩子 → normal 档 + 标签往回收；
争执/真香等高冲突钩子 → 才用 high 档。别默认激情档——「压低声的悄悄话」后面接
激情解说，同一把嗓子前后劈叉。

**情绪控制用标签法**（写在 assistant 台词文本里，`(兴奋)` 开头、段中 `(语速稍快)`/`(激动)`/`(亲切)`），
实测是 MiMo 唯一有效的通道（12.8–12.9 半音）；user 人设/导演模式三条实测全落旧上限以内，
别再花时间调它。锚带剧情情绪底色（如抬杠）时，标签往回收。

## 一条命令

```bash
python3 skills/ecommerce-narration/scripts/narration.py \
  --card assets/ai_assets/characters/ch_001_林岚/card.json \
  --script-json <文案>.json --target-rate 4.86 --energy high \
  -o vo/女主解说_正式版.mp3 \
  [--style-extra "价格像替朋友算账，一口气报完"]
```

文本默认取 `--script-json` 里所有 `seq >= 2` 的段（钩子之后的解说段），空格分隔成一段连续旁白。

它自己完成：生成 → 数字转中文读法 → 测语速 → 算 atempo → 提亮 → 校准响度峰值 → 打指标表 → 判合格。不合格以 `⚠️` 列出原因并退出码 1。

**别再用 `gen_voice.py --clone` 手搓一遍再看指标**——那套流程一条旁白要五六轮。

## 三条硬经验（改脚本前先看理由）

**① 停顿密度 = 情绪起伏。约束连贯性，不要调语速。**
同一段文本，style 写「念数字放慢」→ 停顿 18.2%、LRA 1.6（比不加还平）；改成「句间不换气、数字顺势念过去」→ 停顿 7.4%、LRA 7.2。
TTS 断句一散，语气立刻变念稿。**任何"放慢 / 清晰 / 抑扬顿挫"字样都是 LRA 杀手。**

**② 先让 TTS 跑快，再用 atempo 降速。**
atempo 不改 LRA，所以是先拿到起伏再对语速；反过来（生成时就压慢）起伏直接没了。安全区 0.85–1.18；高起伏抽卡可显式 `--atempo-min 0.72` 放宽，配合 EQ 提亮，人耳确认不发闷。

**③ 响度和峰值一起管。**
-18.7 LUFS + 峰值 ≤ -1.0，取更严的那个增益。只管响度不管峰值，混剪 +3dB 就削波。

## 情绪档、抽卡与降速下限（11-04 实测，别靠手写 style 碰运气）

```bash
--energy high        # 带货激情档：语速不变，只把「收尾放平」改成「往前推」
--tries N            # TTS 抽 N 条自动择优（0=自动：high 3 条 / normal 1 条）
--atempo-min 0.72    # 显式放宽降速下限（默认 0.85）
```

对用户仍是一条命令：抽卡 → 按「达标优先 → LRA 高 → 停顿少 → 语速近目标」择一条 →
配速 / 提亮 / 响度校准 → 质检。

**14 次抽卡的结论**：同 style 同文本，raw 语速 4.20–6.70 字/秒、LRA 1.3–10.7 剧烈波动，
**方差来自抽卡本身，不是措辞**。而且 **LRA 与语速正相关**：唯一一条 LRA 10.7 的抽卡
raw 就是 6.70 字/秒，落回 4.86 需要 atempo 0.725。atempo 不改 LRA，所以
「放宽降速下限 + EQ 3kHz 提亮」能同时拿到高起伏和目标语速——本次 LRA 10.9 /
4.87 字/秒 / 全项通过就是这么来的。

**style 四条写法（全是踩过的坑）**
- 写「**音量**有强弱」，别写「语气有强弱」（后者实测 LRA 2.6，模型不动声学幅度）。
- 别写「重音落在 X」「这句加力」等局部强调指令 → 诱发换气，停顿 14.5%、LRA 2.9。
- 连「不要夸张的抑扬顿挫」这种否定写法也别写，TTS 对词本身敏感。
- 「精神头足 / 带劲 / 不塌」这类抽象形容词无效，别堆。

⚠️ **高起伏抽卡可能伴随发音变形**：本次 ASR 把「虎坚果」听成「福坚果」、
「咸甜口」听成「剪贴口」，降速后仍在。**指标全过 ≠ 咬字没问题，必须人耳试听。**

**别做**：不要为过验收线反复改 style，也不要偷偷调低阈值。没有一条达标时脚本会取
指标最好的一条并明确报「没达标」，把这个事实交给人判断。

## 验收线（脚本内置）

| 项 | 阈值 | 为什么这么定 |
|---|---|---|
| 停顿占比 | ≤ 15% | >20% 听感立刻拖沓 |
| LRA | ≥ 3.5 | 低于 3 就是念稿 |
| 语速偏离 | ≤ 6% | 偏离多了与画面时长对不上 |
| 峰值 | ≤ -0.5 dBFS | 混剪还要 +3dB |

**两套静音阈值不能混用**：验收用 `-38dB/0.28s`（只数真停顿），对齐句边界用 `-33dB/0.16s`（要抓字间小停顿）。同一版旁白前者 8 处 8.2%、后者 24 处 17.7%，混用会误报不合格。

## 调参不花钱

```bash
--from-audio <现成raw.mp3>
```

跳过 TTS，只重跑配速/提亮/校准。改 atempo、改 EQ、改响度目标都用这个，**不消耗 TTS 额度**——也是验证这条处理链最快的方式。

## 交给下游

出完给 `ecommerce-mix` 两样东西：mp3 路径、文案 JSON（句边界从 JSON 的段文本推）。句边界和段清单由 mix 技能算，本技能不产出。

## 别做

不切画面、不算边界、不合成（那是 `ecommerce-mix`）。
不改文案（那是 `ecommerce-script-gen`）。
不加 BGM、不做混响——TTS 保持干声，混音统一在混剪阶段做。
