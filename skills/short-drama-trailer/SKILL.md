> 本技能不是入口。调度、门禁、并发走 `short-drama-supervisor`（2026-11-10 已独立）。
> 本技能只负责「把编排好的 plan.json 装配成一条能看的纯剪预告」。
> **职责划清**：定轴 / 三拍选段 / 五幕重排归 `short-drama-script`，本技能不再宣称做这三件；
> plan.json 不齐就退回上游，不自己补。

# 纯剪预告装配

**零解说、零口播、原片原声混剪，唯一目标是勾人去看全剧。**
它不是缩短版原剧，是从全剧里抽出一条受力结构重新讲一遍——
每一帧都是原片，讲的顺序不是原片。

> 方法论完整版（含迭代史与全部判据出处）：仓库 `docs/纯剪预告方法论_v0.1.md`（正文已升 v0.2）。
> 王婶织入位配方：`references/wangshen-weave-in.md`。

## 何时使用 / 不要使用

- 使用：剧集包已建好，要出一条纯剪预告或第二条片子（换受力结构）。
- 不使用：建包/补台词（`short-drama-pack`）；定轴 / 选段 / 五幕重排（`short-drama-script`）；
  AI 织入片生成（`short-drama-video`）；带货混剪（`ecommerce-mix`，与本线无关）。

## 工序（四步，每步有判据）

> **编排在上游**：定轴 / 三拍选段 / 五幕重排由 `short-drama-script` 完成并产出 plan.json。
> 本技能从「拿到 plan.json」开始，不重新选段。

1. **复核 plan.json**：每段 `beats` 三拍注释齐不齐、`选段说明.md` 有没有五幕归属与
   But/Therefore 连接、砍场前因复述在不在；缺任一项退回 `short-drama-script`，不自己补。
   **存量批次例外（11-10 口径）**：`选段说明.md` 未落盘时，明确报「存量批次未落盘」并继续装配，
   不静默放行、也不倒推退回上游——定版用例 D5 属此情形，已在台账标注。
2. **装配**：跑 `scripts/mix_trailer.py`。它装前自动查两件，不合格**拒装**并说清哪一段：
   ① 出点 ≤ 视频流时长（防段尾黑帧）；
   ② 每个刀口落在原片停顿里（读 `assets/short-drama/<剧>/cuts/`）。**出点**差 0.3 秒以上判
   「切在说话中间」拒装，并给出「往前到 X / 往后到 Y」两个候选；**入点**只警告。
   没有停顿表时只提示不拦，`--no-cut-check` 可整体跳过。
   明知道有半句要削还非装不可，用 `--allow-mid-speech`。
   **段间转场**：段上的 `"out"` 字段（cut/black/card）由编排技能定，本技能照单执行——见下节。
   **字幕随转场自动平移**，不用手改 ASS 时间轴。
3. **验证三件**：抽单帧全尺寸看字幕切点（小拼图会看串行）；段界帧查黑帧；
   AI 织入段加 ASR 逐字比对台词。
4. **（可选）王婶织入**：见 `references/wangshen-weave-in.md`。织入位首选
   第一场后的黑场位（消化位+导航位），插完整 AI 段后原黑场取消。

## 硬纪律（违反必翻车，全部实测换来的）

| 纪律 | 原因 |
|---|---|
| 出点上限 = **视频流时长**，不是 format 时长 | 每集视频流比音频短 0.6–0.7s，超切带黑帧 |
| 刀口必须落在原片**停顿**里，不许靠「这句大概念完了」估 | 段表两头原来只按镜头切，跟这句话说完没说完毫无关系。实测三条片子 44+34+30 个刀口，一半下在说话中间 |
| 「这句说完没有」问**停顿表**，不问台词表 | 台词表只有「第几秒出现」，没有「说到第几秒」，且每秒采一帧、时刻晚半秒到一秒 |
| 切台词边界用原片硬字幕出现/消失（±0.3s） | silencedetect 在田间底噪下测不出人声 |
| 抽帧验证用**单帧全尺寸** | <300px 拼图看串行，误报时间戳错位 |
| 分段 loudnorm 后必须全局 alimiter | 叠化交叉区叠加超峰（实测 TP+1.24dB 削波） |
| SAR setsar=1 放 scale 之后；48k/fltp 统一 | concat 段间 SAR 不一致输出花屏 |
| 黑场/字幕卡先落地成图片文件 | lavfi 源不能直接进 concat |
| 砍场必须复述砍掉的前因 | 完整性 vs 时长是硬兑换，取舍要显性 |
| ffmpeg 版本必须是 8.0.1，放数据目录 `bin/` | 2018 老版读不了中文路径字幕（libass fopen failed），装配必炸；查找顺序已设为数据目录优先 |

## 刀口被拦了怎么办（2026-11-14 加）

装配器报「切在说话中间」，是**上游段表的问题，不是装配的问题**。三条路：

| 出路 | 怎么做 | 适合 |
|---|---|---|
| 自动挪 | `cut_index.py --snap <plan.json> --out <新清单>`，按停顿重定每个刀口，另存一份不动原件 | 批量、明显差半秒的 |
| 人定 | 看装配器给的两个候选（往前到 X / 往后到 Y）挑一个 | 挪一下会改段意的 |
| 放行 | `--allow-mid-speech` | 明知这点半句不影响，或者原片本身就这么切 |

**别在本技能里手改 a/b。** 选段与段表归 `short-drama-script`，装配技能只报不补——
自己改等于装配侧替编排侧做决定，出了错分不清是谁的。

**只有出点会被拦。** 入点落在连读中间（上一句尾接下一句头）只警告——原片自己就这么切，
观众不觉得断。真正难听的是「话没说完画面就换了」，那是出点。实测被指出的三处全是出点。

**贴边警告（差 0.3 秒以内）不用管**，那是刀口擦着停顿边下的，多半是浮点或采样抖动。
但里头会混进「婚礼音乐当成人声」的误报——那个得靠耳朵，程序分不出音乐和人声。

## 段间转场执行（2026-11-17 加）

转场的**决策**在 `short-drama-script`（选哪种、哪处加），本技能只**执行**段上的 `"out"` 字段。
装配器把转场段展开进时间轴（黑场/文字卡都是无声段），淡入淡出加在相邻段上，
**字幕事件按转场累计时长自动平移**（T1 实测：不平移的话黑场上会飘着字幕，已修）。

三种模式（缺省 `cut`，行为与以前完全一致）：

| `out` | 装配器做什么 | 注意 |
|---|---|---|
| `cut` | 什么都不加 | 默认 |
| `black` | 前段尾淡出(video 0.25s/audio 0.30s) → 0.45s 纯黑静音 → 后段淡入 | 时长 +0.45s |
| `card` | 1.2s 黑底两行字（剧名＋`out_sub` 悬念句）淡入淡出 | 文字卡由 drawtext 预渲染 PNG；字体要在 `transitions.card.font` 或 fontsdir 里 |

装配器完整字段说明（含 `plan.transitions` 默认值、`out_sub` 覆盖）见 `scripts/mix_trailer.py`
头部注释「段间转场」一节。**改转场只重拼成片，不重跑素材段/台词库**。
文字卡字体缺失会明确报错——四款中文字体需自己拷进 `修饰/字体/`（不随包分发）。

## 出片速度优化（2026-11-17 实测，20 条批量必读）

出一条 6 分钟片子的时间账：老单进程 medium 约 4 分钟。慢**不在画质档位**——
720p medium 和 360p veryfast 全片耗时几乎一样；瓶颈在「几十路 1080p 原片解码 + 滤镜链」。
据此定下的规矩：

| 项 | 结论 |
|---|---|
| **别指望降画质提速** | 360p 预览不比 720p 快多少，省不了时间还降质量。直接出 720p |
| **ffmpeg 版本** | 必须用 8.0.1（放数据目录 `bin/`，优先级最高）。插件目录那份是 2018 老版，**读不了中文路径的字幕**（libass fopen failed），装配必炸。5 个技能的查找顺序已改成数据目录优先 |
| **`--preset`** | 本机 `veryfast` 比 `medium` 快约 20%、体积还略小；要更快用硬编码 |
| **`--vcodec h264_nvenc --vq 21`** | 硬编码，30s 样片 2s 编完（软编 34s）。**单条只快约 10%**（编码本来只占几秒，瓶颈是解码/滤镜），需驱动 ≥570 |
| **`--jobs` 并行** | 本机（16 vCPU 无 AVX2）**默认关**——单路 x264 已吃满 CPU，4 进程并行反而慢一倍多。留给核多/硬编码的机器 |
| **批量真正解法** | 硬编码把编码甩给显卡后 CPU 腾出来，**多条片子并行**才划算：本机 3 路并行吞吐 2×（36s/条 vs 单条 72s），一条批 20 条约 35 分钟（串行 1 小时+）。甜点位 3 路是按本机性能标定的，**换机器要重新测** |

**测速度的规矩**：一律用 2 分钟级短片（前 10 段）对比，别跑全片——全片单次计时受后台
扫描干扰极大（同一配置 229s/448s 都出现过），不可比。音画校验用
`short-drama-supervisor/scripts/verify_fast.py`（自动找 ffmpeg、从清单读源片目录、
会跳过转场段；1 分钟跑完 29 段），别用老的 verify_strict（低对比度画面会锁错峰报假偏差，
得抽帧复核）：

```bash
python3 skills/short-drama-supervisor/scripts/verify_fast.py <plan.json> <成片.mp4> [--jobs 6]
```

> 实测详情：`WorkBuddy/2026-11-16-13-35-04/并行渲染实测_2026-11-17.md`、
> `bug修复清单_v0.4.1.md` K 类。硬编码、并行两个开关都已预埋进装配器，默认不影响现有出片。

## 输入 / 输出

| 项 | 说明 |
|---|---|
| 剧集包 | `packs/short-drama/<剧名>/drama-pack.json`（story_arc / finale 门禁） |
| 台词库 | `assets/short-drama/<剧名>/lines/lines_epNN.json` |
| 停顿表 | `assets/short-drama/<剧名>/cuts/epNN.json`（`short-drama-asset-index/scripts/cut_index.py --build` 产出；装配前体检刀口用，缺了只提示不拦） |
| plan.json | **由 `short-drama-script` 产出**；字段见 scripts/mix_trailer.py 头部注释。允许版本化命名 `plan_<tag>.json`（存量 `plan_v3ws.json` 即此） |
| 输出 | 成片 mp4 + 段落表打印 + （织入时）ASR 比对记录；成片文件名自定义，台账写实际路径 |

**时长预期（11-11 按主/副线分档）**：主线每场自洽的诚实代价是 4–6 分钟、五幕齐；
**副线 2–3 分钟、只取 Tease ＋ 三拍拒绝 ＋ Button 三幕**。
「占原片 40–50%」没写分母，实测同一条片子换分母能从 19% 跳到 41%，**不再当合格线**。
压时长的刀序：先砍功能重复场 → 再砍标签来源场（须用户拍板，前因会缺）。
砍场是编排决策，归 `short-drama-script`；本技能只报装配后的实际时长账。
