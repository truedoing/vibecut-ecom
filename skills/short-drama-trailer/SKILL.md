# 纯剪预告装配

**纯剪形态：零解说、零口播、原片原声混剪，唯一目标是勾人去看全剧。**
它不是缩短版原剧，是从全剧里抽出一条受力结构重新讲一遍——
每一帧都是原片，讲的顺序不是原片。

> **解说形态（11-22 定位翻案，取代「薄解说」旧口径）**：成片的大方向改成
> **解说为主、原剧片段辅助**——原声是证据，解说是叙事主线。
> 这不是把片子改成旁白片：**画面还是原剧画面，解说只补画面没有的**
> （动作、心理、前因、空间关系），精彩原剧片段**不许截断**。
> 一条 2 分 47 秒的片子可以是「9 段解说 85 秒 + 3 处留白 21 秒 + 原声画面」。
> 规矩见 `references/解说轨_音频闪避.md`；文案由编排环节写（`short-drama-script`）。
> **要不要走解说形态由人定，不默认加，也不为加解说回炉改清单**——
> 解说救不了一条讲不通的段子。
>
> **旧口径（11-18「薄解说」，已被取代，保留备查）**：当时定的是「原剧台词仍是主菜，
> 解说只当十几秒到几十秒的佐料」。现在解说是叙事主线，篇幅按片子长度走，
> 不再是「佐料级」。两者别混。

> 方法论完整版（含迭代史与全部判据出处）：仓库 `docs/纯剪预告方法论_v0.3_解说为主.md`。
> 王婶织入位配方：`references/wangshen-weave-in.md`。

## 何时使用 / 不要使用

- 使用：剧集包已建好，要出一条纯剪预告或第二条片子（换受力结构）。
- 不使用：建包/补台词（`short-drama-pack`）；定轴 / 选段 / 五幕重排（`short-drama-script`）；
  AI 织入片生成（`short-drama-video`）；带货混剪（`ecommerce-mix`，与本线无关）。

## 出片时间账（2026-11-23 实测，一小时里 80% 花在返工上）

D11 那条片子从「装配」到「成片」花了 **1 小时 24 分**（10:02 → 11:26）。
把时间摊开看，真正花在片子上的不到 20 分钟：

| 时段 | 干了什么 | 是不是白花 | 怎么根治 |
|---|---|---|---|
| 10:02–10:20 | 写 6 段解说（130 字，每段一句） | 是 | 解说按类型写段落，不是一句话 |
| 10:20–10:40 | 扩到 7 段 → 第 2 段塞不进窗口 → 拆成 8 段 | **是** | **先跑 `--step caps` 拿字数上限表，再写** |
| 10:40–11:00 | 现写跨段撞词检测器、改词、改口径 | 是 | ~~检测器该是现成的~~ **已被取代（11-23 张老师定）：撞词检测整道去掉，解说不原样引用原剧台词就不会撞；关键台词保护一并去掉（解说只落静音垫画面段，结构上盖不到原声）。别再自己挖坑自己查。** |
| 11:00–11:08 | 装配底片 | 否，必要 | — |
| 11:08–11:20 | 发现时间轴差 0.45s → 重排 8 段落点 | **是** | **时间轴算法只留一份**（`timeline.py`） |
| 11:20–11:25 | 配音 8 段 | 否，必要 | — |
| 11:25–11:26 | 第 8 段超窗 → 压缩 → 重配 | **是** | **配音前先校验，超了就不配** |
| 11:26–11:28 | 修两个路径 bug、叠音、出片 | 部分 | 路径规则统一到一处 |

**四条根治措施（已落地）**：

1. **顺序不能错**：装配 → 拿时间轴 → 出字数上限表 → 写文案 → 校验 → 配音 → 叠音。
   `build_trailer.py` 把这个顺序固化了，校验不过就停在配音之前。
2. **时间轴只留一份**：`skills/short-drama-trailer/scripts/timeline.py` 是唯一真源。
   装配器、话/静分布工具都 import 它。
   （11-23 之前这段算法抄了三份，改一处忘一处，踩了三次。）
3. **语速基准放数据里**：`assets/voice_assets/<音色>/rate.json`。
   语速是「音色 + 变速档」的属性，写死在代码里换音色就忘了改——
   11-23 按「含标点」算出 6.506 字/秒，字数上限松了 22%，两段白配。
   **口径必须是纯字，不含标点。**
4. **文案配之前先看表**：`--step caps` 出一张「每段能写多少字」的表。
   照上限写，超了就拆块——这一步省掉的是最贵的一轮返工。

**成本参照**：装配 167 秒片子约 130 秒；8 段配音 API 约 150 秒；叠音约 20 秒。
**一条片子正常出片应该 5–8 分钟**，超过 15 分钟就是哪里又返工了。

### 第二轮又踩了三个坑，都已修（2026-11-23 下午）

| 坑 | 现象 | 修法 |
|---|---|---|
| **不支持断点续跑** | 会话被掐断后重跑：底片重装（白花 131 秒）、已配好的段没记账（白花钱） | 底片不比清单旧就复用；配音**每完成一段就增量落盘**，重跑时「文案没变 + mp3 还在」就沿用 |

| **解说的覆盖区间＝原声被删掉** | 8 块解说盖掉 22 句原声，含两句命门 | **v0.6.3 根解**：解说改配 `broll` 静音垫画面段，与主线原声零重叠（`narration_fit.py` 旧治法保留备查） |

**第二轮的实测耗时**（底片复用 + 只重配 1 段 + 叠音）：**13.9 秒**。

## 工序（四步，每步有判据）

> **一条命令能跑完，别手工串**（2026-11-23 建，见下面「出片时间账」）：
> ```bash
> python3 skills/short-drama-trailer/scripts/build_trailer.py \
>     --plan runs/<剧>/<任务>/plan.json \
>     --narration runs/<剧>/<任务>/build/解说配置.json
> ```
> 它按固定顺序跑：**装配 → 字数与落点校验 → 配音 → 叠音**，
> 校验不过就停在配音之前（不花钱）。
> **v0.6.3：撞词检测、关键台词保护两道已摘掉**——解说不原样引用台词就不会撞，
> 解说只落静音垫画面段就盖不到原声；这两道是自己挖坑自己填，不再跑。
> 想只拿「每段能写多少字」的表：
> ```bash
> python3 skills/short-drama-trailer/scripts/build_trailer.py --plan ... --step caps
> ```
> **写文案之前必须先拿这张表**——11-23 那次文案返工三轮，根因就是先写后算。


> **编排在上游**：定轴 / 三拍选段 / 五幕重排由 `short-drama-script` 完成并产出 plan.json。
> 本技能从「拿到 plan.json」开始，不重新选段。

1. **复核 plan.json**：每段 `beats` 三拍注释齐不齐、`选段说明.md` 有没有五幕归属与
   But/Therefore 连接、砍场前因复述在不在；缺任一项退回 `short-drama-script`，不自己补。
   **存量批次例外（11-10 口径）**：`选段说明.md` 未落盘时，明确报「存量批次未落盘」并继续装配，
   不静默放行、也不倒推退回上游——定版用例 D5 属此情形，已在台账标注。
2. **装配**：跑 `scripts/mix_trailer.py`。它装前自动查两件，不合格**拒装**并说清哪一段：
   ① 出点 ≤ 视频流时长（防段尾黑帧）；
   ② 每个刀口落在原片停顿里（读 `assets/short-drama/<剧>/cuts/`）。**出点**差 0.3 秒以上判
   「切在说话中间」拒装，并给出「往前到 X / 往后到 Y」两个候选；**入点**只警告。
   没有停顿表时只提示不拦，`--no-cut-check` 可整体跳过。
   明知道有半句要削还非装不可，用 `--allow-mid-speech`。
   **段间转场**：段上的 `"out"` 字段（cut/black/card）由编排技能定，本技能照单执行——见下节。
   **字幕随转场自动平移**，不用手改 ASS 时间轴。
3. **验证三件**：抽单帧全尺寸看字幕切点（小拼图会看串行）；段界帧查黑帧；
   AI 织入段加 ASR 逐字比对台词。
   **解说形态**：原声保护靠结构——核对解说区间全落在 `broll` 垫画面段、与主线 ep 段零重叠，
   不用再做留白电平比对（D11 第四轮用时间轴比对代替）。有条件再做解说配音 ASR 逐字比对
   （查念错字，纯剪形态不用这一步）。
4. **（可选）王婶织入**：见 `references/wangshen-weave-in.md`。织入位首选
   第一场后的黑场位（消化位+导航位），插完整 AI 段后原黑场取消。
5. **（可选）解说轨**：人明确要解说时才做。拿第 3 步验完的成片，跑
   `scripts/duck_narration.py` 叠解说——解说响时原声自动压低，说完回来，画面不动。
   先 `--dry` 核对落点，再正式出片。插哪、文案怎么写、音色怎么挑、情绪指令怎么传、
   语速怎么实测、改一段怎么只重配那一段，见 `references/解说轨_音频闪避.md`。
   **不默认加，也不为加解说回炉改清单**——解说救不了一条讲不通的段子。

   **配音用通用工具，别手写脚本**：`scripts/gen_narration.py --spec <配音表.json>`
   会把「情绪指令走顶层 instructions」「变速只做一次」「字���上限按实测语速」三个坑固化，
   跑完顺带出一份能直接叠轨的 `解说配置.json`。

## 硬纪律（违反必翻车，全部实测换来的）

| 纪律 | 原因 |
|---|---|
| 出点上限 = **视频流时长**，不是 format 时长 | 每集视频流比音频短 0.6–0.7s，超切带黑帧 |
| 刀口必须落在原片**停顿**里，不许靠「这句大概念完了」估 | 段表两头原来只按镜头切，跟这句话说完没说完毫无关系。实测三条片子 44+34+30 个刀口，一半下在说话中间 |
| 「这句说完没有」问**停顿表**，不问台词表 | 台词表只有「第几秒出现」，没有「说到第几秒」，且每秒采一帧、时刻晚半秒到一秒 |
| 切台词边界用原片硬字幕出现/消失（±0.3s） | silencedetect 在田间底噪下测不出人声 |
| 抽帧验证用**单帧全尺寸** | <300px 拼图看串行，误报时间戳错位 |
| 分段 loudnorm 后必须全局 alimiter | 叠化交叉区叠加超峰（实测 TP+1.24dB 削波） |
| **各段响度要压动态（加 compressor）** | 只 loudnorm 不压动态，段与段差 2.8dB，人批「有气无力」（D6）。压动态后差 1.6dB，成片明显有劲 |
| **变速只做一次，别叠 `atempo`** | 二次加速成片发飘 |
| **解说语速按实测算，不拍脑袋** | 说书人C 真实 4.52 字/秒；按 5.75 估偏快 27%，第一轮 4 段超上限 |
| SAR setsar=1 放 scale 之后；48k/fltp 统一 | concat 段间 SAR 不一致输出花屏 |
| 黑场/字幕卡先落地成图片文件 | lavfi 源不能直接进 concat |
| 砍场必须复述砍掉的前因 | 完整性 vs 时长是硬兑换，取舍要显性 |
| ffmpeg 版本必须是 8.0.1，放数据目录 `bin/` | 2018 老版读不了中文路径字幕（libass fopen failed），装配必炸；查找顺序已设为数据目录优先 |

## 刀口被拦了怎么办（2026-11-14 加）

装配器报「切在说话中间」，是**上游段表的问题，不是装配的问题**。三条路：

| 出路 | 怎么做 | 适合 |
|---|---|---|
| 自动挪 | `cut_index.py --snap <plan.json> --out <新清单>`，按停顿重定每个刀口，另存一份不动原件 | 批量、明显差半秒的 |
| 人定 | 看装配器给的两个候选（往前到 X / 往后到 Y）挑一个 | 挪一下会改段意的 |
| 放行 | `--allow-mid-speech` | 明知这点半句不影响，或者原片本身就这么切 |

**别在本技能里手改 a/b。** 选段与段表归 `short-drama-script`，装配技能只报不补——
自己改等于装配侧替编排侧做决定，出了错分不清是谁的。

**只有出点会被拦。** 入点落在连读中间（上一句尾接下一句头）只警告——原片自己就这么切，
观众不觉得断。真正难听的是「话没说完画面就换了」，那是出点。实测被指出的三处全是出点。

**贴边警告（差 0.3 秒以内）不用管**，那是刀口擦着停顿边下的，多半是浮点或采样抖动。
但里头会混进「婚礼音乐当成人声」的误报——那个得靠耳朵，程序分不出音乐和人声。

## 段间转场执行（2026-11-17 加）

转场的**决策**在 `short-drama-script`（选哪种、哪处加），本技能只**执行**段上的 `"out"` 字段。
装配器把转场段展开进时间轴（黑场/文字卡都是无声段），淡入淡出加在相邻段上，
**字幕事件按转场累计时长自动平移**（T1 实测：不平移的话黑场上会飘着字幕，已修）。

三种模式（缺省 `cut`，行为与以前完全一致）：

| `out` | 装配器做什么 | 注意 |
|---|---|---|
| `cut` | 什么都不加 | 默认 |
| `black` | 前段尾淡出(video 0.25s/audio 0.30s) → 0.45s 纯黑静音 → 后段淡入 | 时长 +0.45s |
| `card` | 1.2s 黑底文字卡淡入淡出 | 见下「文字卡」；段级可写 `out_title`（大标题）、`out_sub`（副句）、`out_card_d`（这张卡停多久），渐变时长 `fade_in`/`fade_out` 可配 |

装配器完整字段说明（含 `plan.transitions` 默认值）见 `scripts/mix_trailer.py` 头部注释。
**改转场只重拼成片，不重跑素材段/台词库**。

**文字卡渲染（2026-11-23 改，v0.6.3）**：预渲染成 PNG 再进 concat。
用 **PIL 画字**，不用 ffmpeg 的 drawtext——本机 ffmpeg 很多是没编 drawtext 的，
先探 `ffmpeg -filters | grep drawtext` 再决定；没编就一律走 PIL，别在这卡住。
字体要在 `plan.transitions.font`（写绝对路径）或 fontsdir 里有 `SourceHanSansSC-Heavy.otf`；
缺失会明确报错，四款中文字体需自己拷进 `修饰/字体/`（不随包分发）。
**描述时间跳转的文字卡**（如钩子后跳回过去）：段上写 `out:"card"` +
`out_title:"几天前……"`、`out_card_d:1.8`、`out_sub` 留空——只有大标题时单字居中。

## 垫画面段 `broll`（2026-11-23 加，v0.6.3）

**解决什么**：解说形态原来把解说压在主线画面上，叠音时原声被静音，
解说覆盖区间＝那段原声被删掉（D11 第二轮 8 块解说盖掉 22 句原声）。
现在改成——**主线原声一句不动，另剪一组相关镜头垫在解说下面放（这段本来就静音）**。
解说和主线在时间轴上零重叠，是结构上保证的，不再靠人标保护区。

清单写法（type 为 `broll`，镜头从画面打标 `shots/` 里挑，取非说话镜头）：

```json
{"label":"B01_垫画面_婚礼", "type":"broll",
 "clips":[{"ep":1,"a":17.2,"b":20.3},{"ep":1,"a":20.3,"b":24.8}],
 "beats":"垫画面（xx 秒，静音）：配第1块解说，同场景镜头，不跨集混搭"}
```

- 时长＝各镜头 `b-a` 之和，`timeline.py` 的 `seg_duration` 与装配器共用这一个算法。
- **解说落点写在垫画面段的起点**（`解说配置.json` 的 cues），字数上限按垫画面段时长算：
  先跑 `build_trailer.py --step caps` 拿表，照上限写。这解决了「解说想写丰满但没地方放」——
  垫画面段多长自己定，解说就能写多长。
- **选镜头要跟解说内容对得上、别跨场景乱跳**（D11 第三轮教训：按「家庭/职场」两大组
  顺序取镜头，观众觉得乱）。按 8 个场景各配一组，每块只取同一类镜头。
- 垫画面段一样走刀口体检：镜头落在说话中间会报（画面静音但口型还在动）。
- `check_repetition.py` 找宿主段时要认 `broll`；解说落在垫画面段上时同期原声是静音的，
  不算复述。

## 出片速度优化（2026-11-17 实测，20 条批量必读）

出一条 6 分钟片子的时间账：老单进程 medium 约 4 分钟。慢**不在画质档位**——
720p medium 和 360p veryfast 全片耗时几乎一样；瓶颈在「几十路 1080p 原片解码 + 滤镜链」。
据此定下的规矩：

| 项 | 结论 |
|---|---|
| **别指望降画质提速** | 360p 预览不比 720p 快多少，省不了时间还降质量。直接出 720p |
| **ffmpeg 版本** | 必须用 8.0.1（放数据目录 `bin/`，优先级最高）。插件目录那份是 2018 老版，**读不了中文路径的字幕**（libass fopen failed），装配必炸。5 个技能的查找顺序已改成数据目录优先 |
| **`--preset`** | 本机 `veryfast` 比 `medium` 快约 20%、体积还略小；要更快用硬编码 |
| **`--vcodec h264_nvenc --vq 21`** | 硬编码，30s 样片 2s 编完（软编 34s）。**单条只快约 10%**（编码本来只占几秒，瓶颈是解码/滤镜），需驱动 ≥570 |
| **`--jobs` 并行** | 本机（16 vCPU 无 AVX2）**默认关**——单路 x264 已吃满 CPU，4 进程并行反而慢一倍多。留给核多/硬编码的机器 |
| **批量真正解法** | 硬编码把编码甩给显卡后 CPU 腾出来，**多条片子并行**才划算：本机 3 路并行吞吐 2×（36s/条 vs 单条 72s），一条批 20 条约 35 分钟（串行 1 小时+）。甜点位 3 路是按本机性能标定的，**换机器要重新测** |

**测速度的规矩**：一律用 2 分钟级短片（前 10 段）对比，别跑全片——全片单次计时受后台
扫描干扰极大（同一配置 229s/448s 都出现过），不可比。音画校验用
`short-drama-supervisor/scripts/verify_fast.py`（自动找 ffmpeg、从清单读源片目录、
会跳过转场段；1 分钟跑完 29 段），别用老的 verify_strict（低对比度画面会锁错峰报假偏差，
得抽帧复核）：

```bash
python3 skills/short-drama-supervisor/scripts/verify_fast.py <plan.json> <成片.mp4> [--jobs 6]
```

> 实测详情：`WorkBuddy/2026-11-16-13-35-04/并行渲染实测_2026-11-17.md`、
> `bug修复清单_v0.4.1.md` K 类。硬编码、并行两个开关都已预埋进装配器，默认不影响现有出片。

## 输入 / 输出

| 项 | 说明 |
|---|---|
| 剧集包 | `packs/short-drama/<剧名>/drama-pack.json`（story_arc / finale 门禁） |
| 台词库 | `assets/short-drama/<剧名>/lines/lines_epNN.json` |
| 停顿表 | `assets/short-drama/<剧名>/cuts/epNN.json`（`short-drama-asset-index/scripts/cut_index.py --build` 产出；装配前体检刀口用，缺了只提示不拦） |
| plan.json | **由 `short-drama-script` 产出**；字段见 scripts/mix_trailer.py 头部注释。允许版本化命名 `plan_<tag>.json`（存量 `plan_v3ws.json` 即此） |
| 解说配置（可选） | 人明确要解说时才有；起点从清单段位推算+抽帧确认，文案由编排环节写。格式见 `references/解说轨_音频闪避.md`。**含 `texts` 字段才能做字数校验和配音** |
| 解说音色（可选） | 共用层 `assets/voice_assets/narration_说书人C/`（MiMo 语音克隆）。`voice.mp3` 当声音样本；配置读 `.env` 的 `MIMO_BASE_URL` / `MIMO_API_KEY`。**按 token 计费** |
| 输出 | 成片 mp4 + 段落表打印 + （织入时）ASR 比对记录；要解说时另出一条带解说成片，画面不变。文件名自定义，台账写实际路径 |

**时长预期（11-11 按主/副线分档）**：主线每场自洽的诚实代价是 4–6 分钟、五幕齐；
**副线 2–3 分钟、只取 Tease ＋ 三拍拒绝 ＋ Button 三幕**。
「占原片 40–50%」没写分母，实测同一条片子换分母能从 19% 跳到 41%，**不再当合格线**。
压时长的刀序：先砍功能重复场 → 再砍标签来源场（须用户拍板，前因会缺）。
砍场是编排决策，归 `short-drama-script`；本技能只报装配后的实际时长账。
