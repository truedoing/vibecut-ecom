## 一句话说清这套方案

画面还是原剧画面，一像素不动。
**解说负责讲清这条片子的故事线，原声负责提供证据。**
解说一说，原声让开；解说一停，原声自己回来。

它解决的是：光靠剪片段，观众看不懂这条片子在讲什么。
《以真心守护至亲》D7 的实测——解说稿第一版同步复述率 37%，
观众等于把同一句话听两遍；改成「说画面／说内心」之后降到 1.6%，成片才立住。

## 跟「纯剪形态」的关系（别搞混）

| | 纯剪形态 | 解说形态（现在的主方向） |
|---|---|---|
| 谁讲故事 | 原剧人物自己的台词 | **解说讲主线，原声给证据** |
| 解说出现的地方 | 一处都没有 | 全片铺开，关键处**留白**给原声 |
| 解说篇幅 | 无 | 按片子长度走（D7：2 分 47 秒里 85 秒） |
| 什么时候用 | 片段自己讲得清 | 换视角讲同一部戏、多条片子并行时 |

**判断口诀**：能靠选段讲清的，别加解说。加了解说还讲不清的，是选段的问题，回去改清单。

## 三种手法，各管一段（不许每段都一种）

| 手法 | 干什么 | 正例 |
|---|---|---|
| **说画面** | 讲画面里有、但没被说出口的：动作、表情、空间、物件 | 「戒指被她推回去，指尖在盒沿上停了半秒才松开」 |
| **说台词** | 只在原声此刻没说、说了听不清、或要提前预告时 | 「她接下来这句话，说完这场婚礼就散了」（然后切原声） |
| **说内心** | 讲观众看不见的：动机、言外之意 | 「她终于听懂了：对方给的每一样，都是拴她的绳」 |

**反例**：画面里周承正说「就看你今天懂不懂事」，解说词也跟着写一遍。
这就是「太机械感」的病根。

> 下面检测器命令留着是历史记录，出片流程不调用。

**定义**：解说的字句中，与该段画面**同期正在说的原话**重合部分，占解说总字数的比例。

检测工具（`short-drama-script` 目录）：

```bash
python3 skills/short-drama-script/scripts/check_repetition.py \
    --plan runs/<剧>/<任务>/plan.json --narration runs/<剧>/<任务>/build/解说配置.json
```

- 判据：连续 ≥3 字相同即算命中；换说法讲同一个意思**不算**（那叫解读）。
- 退出码 0＝过，1＝有超标段。
- **配置里必须带 `texts`**（解说词原文），只有音频文件测不了。
- **检测器靠 cue 起点落段**：`at` 必须是真实成片起点，填错了检测结果就是错的。
- **检测器有洞**：同音／近音字差异会漏判（「证都没领」vs「证还没领」）。
  引用原话要回原片逐字核，别只看检测器报「过」就放心。

## 留白：关键处不配解说

解说不是从头铺到尾。三处必须留白，让原声自己说：

| 位置 | 放什么 |
|---|---|
| 开头钩子 | 冲突最硬的那句原声 |
| 题眼 | 全片那句话（钉子句）——**谁盖谁废** |
| 落点 | 结尾最有余味的那句 |

**验收必查**：留白区电平必须与底片一致（底片和成片同一处音量相同），
证明原声没被盖住。D7 实测三处：-17.5/-17.6、-18.6/-18.6、-20.1/-20.1 dB，完全一致。

**每段解说必须在本段画面内结束**，不许压到下一段留白上（留白是原声区，一压就废）。

## 解说词怎么写（写的人是编排环节，配音是这一步）

1. **解说不是创作，是翻译。** 输入是已经排好的清单，任务是「观众看到这里会冒出什么问题，
   提前答掉」。每写一句问自己「观众这儿会问啥」，答不上来的删。
2. **接住钩子往下拧，别回答问题。** 钩子刚抛「我妈十七年前就没了」，解说别接
   「这是被赶走的儿媳，她忍了三年」——谜底全泄了。
3. **只说画面没说的。** 她在哭、他很得意、门被摔上，这些眼睛看得到，解说别复述。
4. **不泄底。** 最狠的那一击留着让原剧结尾自己揭。
5. **落点原声留给画面说**（11-22 实测的取舍）：把落点那句原话一字不差写进解说，
   检测器立刻判它复述（实测 0% → 12.9%，单段直接超线）。
   解说只补画面没有的：动作、心理。

语气：用「什么都知道的讲书人」口吻，句子短、带点悬念劲。
不用第一人称「我觉得」「大家看」，别模仿演员腔。

## 插在哪（位置比文案更关键）

| 位置 | 放什么 | 为什么 |
|---|---|---|
| **每段画面内** | 这段画面配套的解说 | 解说形态下解说铺全片，靠留白调节节奏 |
| **钩子刚说完** | 一句「这老太太是谁、为什么闹」 | 观众最需要背景的一刻；同时当转场，省掉黑场过渡 |
| **题眼、落点** | **不配解说，留白** | 这两处原声一出，谁盖谁废 |
| **结尾字幕卡** | 一句点题 | 黑场本来静音，不压任何台词，白捡的位置 |

**每段解说起点从清单段位推算，再抽帧看画面确认。**
脚本会自动探测解说音频有多长、算出该压原声的区间，不用手算（手算就是以前最容易错的地方）。

## 怎么用脚本

```bash
# 先看计划，不出片（核对起点、时长、压原声区间）
python3 skills/short-drama-trailer/scripts/duck_narration.py \
  --video 成片.mp4 --out 带解说.mp4 --spec 解说配置.json --dry

# 确认没问题，正式出片
python3 skills/short-drama-trailer/scripts/duck_narration.py \
  --video 成片.mp4 --out 带解说.mp4 --spec 解说配置.json
```

配置文件长这样（相对路径相对配置文件所在目录）：

```json
{
  "voice": "zh-CN-YunjianNeural",
  "duck": 0.15,
  "gain": 1.25,
  "cues": [
    {"at": 13.9, "text": "满屋子人都笑她。没人知道，这位老太太找了两个女儿，整整十七年。"},
    {"at": 140.9, "audio": "结尾点题.mp3"}
  ]
}
```

只想临时加一句，也可以不写配置文件：

```bash
python3 skills/short-drama-trailer/scripts/duck_narration.py \
  --video 成片.mp4 --out 带解说.mp4 \
  --cue '13.9:满屋子人都笑她。没人知道，这位老太太找了两个女儿，整整十七年。'
```

`--cue` 里写 `@文件名` 表示用现成音频，不写 @ 就是文案（脚本自动调配音生成）。

**`duck` 怎么定**：闪避式（`duck` 0.15）＝解说响时原声压到一成五，能听见底；
**解说形态常用 `duck: 0`**（原剧完全静音，解说停后原声自动恢复），
避免两层声音打架。D7 用的是 `duck: 0` + `gain: 1.32`。

**`texts` 字段**：解说形态下必须写上（`cues` 的顺序与 `texts` 一一对应），
复述率检测靠它。只有 `text` 或只有 `audio` 都能出片，但**测不了复述率**。

## 音色

**现在默认用「说书人C」（MiMo 语音克隆），不是 edge-tts。**

音色资产在共用层：`assets/voice_assets/narration_说书人C/`
（`voice.mp3` 是克隆用的声音样本，配新解说拿它克隆；`card.json` 有接口与边界）。
张老师 11-20 从四个候选里挑定。

| 项 | 说明 |
|---|---|
| 引擎 | MiMo 语音合成（`mimo-v2.5-tts-voicedesign` 造锚 → `mimo-v2.5-tts-voiceclone` 克隆） |
| 配置 | 读 `.env` 的 `MIMO_BASE_URL` / `MIMO_API_KEY`，**别写死** |
| 成本 | 按实际 token 计费。**「不花钱」只对 edge-tts 成立，这个音色不适用** |
| 声音样本 | `voice.mp3`（base64 后放进 `audio.voice` 字段） |

**当前做法（11-22 实证流程）**：
① 用 MiMo 克隆接口把每段解说生成 mp3 → ② 用 ffmpeg 处理（变速＋响度）→
③ 把 mp3 路径写进解说配置的 `audio` 字段 → ④ 用 `duck_narration.py` 叠进去。

> ⚠️ **`duck_narration.py` 目前只认 edge-tts**（配置里的 `voice` 字段）。
> 用 MiMo 音色要**先克隆好 mp3、再用 `audio` 字段叠进去**，走上面第 ①–④ 步。
> 「配解说自动用这个音色」需要改脚本支持 MiMo，**尚未做**（见音色卡 `_known_issues`）。

### 配音生成用通用工具（11-22 加，别再手写脚本）

```bash
python3 skills/short-drama-trailer/scripts/gen_narration.py \
    --spec <配音表.json> [--out-dir <目录>] [--only 2,3,8,9]
```

**这个工具把三个坑固化了**，手写脚本每次都会重踩：
① 情绪指令走顶层 `instructions`（不会念出来）；
② 变速只做一次（叠两次会发飘）＋ loudnorm 后加 alimiter；
③ 字数上限按**实测语速**算，超限直接报错、不许截断。

**配音表格式**：

```json
{
  "task": "D7_锁链",
  "voice_asset": "narration_说书人C",
  "tempo": 1.28,
  "segments": [
    {"idx": 1, "tier": "深", "instructions": "语气冷静克制，像一个看明白了的人慢慢讲",
     "text": "第一道绳，是她丈夫递的。",
     "limit": 13.85, "at": 5.35, "seg_label": "S02_如果我不送呢"},
    {"idx": 2, "tier": "留白", "instructions": null, "text": null,
     "limit": 0, "at": 0, "seg_label": "S01_你高兴就够了"}
  ]
}
```

| 字段 | 含义 |
|---|---|
| `text` 为 null | **留白段**（不配解说，留原声），不占 token |
| `at` | 这段解说的**成片起点秒数**，从清单段位推算。**填错会导致复述率检测结果错误** |
| `limit` | 该段画面内可用秒数上限，超了必须改文案 |
| `instructions` | 情绪指令，**只传给模型，不念出来** |
| `tempo` | 变速倍率（默认 1.0）；**只做一次** |

跑完会同时产出：`配音输出/第NN段.mp3`（成品）、`配音输出/raw/`（原始）、
`配音输出/manifest.json`（每段时长与 token 消耗）、
**`配音输出/解说配置.json`**（直接给 `duck_narration.py` 叠轨用，已带 `texts`，能测复述率）。

### 情绪指令：唯一正确的传法（11-22 实测）

情绪指令**只传给模型，不念出来**。传法只有一种是对的：

| 传法 | 结果 |
|---|---|
| 把情绪前缀拼在朗读文本前 | ❌ **会被念出来** |
| `messages` 里用 `system` 角色 | ❌ 接口 400（`system role is not allowed for TTS model`） |
| `【不朗读】`标记 | ❌ 无效 |
| **顶层 `instructions` 字段** | ✅ **有效，且不进朗读文本** |

```python
body = {
    "model": "mimo-v2.5-tts-voiceclone",
    "messages": [{"role": "assistant", "content": text}],   # 只放要念的
    "instructions": "（压着，一字一顿，替这老太太说句话）",   # 情绪走这里
    "audio": {"format": "mp3", "voice": "data:audio/mpeg;base64," + b64},
}
```

**分三档**：深（情绪峰值，写演法＋立场）／中（推进叙事，写语气＋速度）／浅（交代性一句）。

**指令要写「怎么演」，不是「演什么情绪」。**「悲伤」是标签，「压着，一字一顿」才是演法。

### 语速必须实测（11-22 踩过）

「说书人C」克隆的**真实语速是 4.52 字/秒**（9 段 565 字 / 124.99 秒原始音频，逐段 4.19–4.99）。

按 5.75 字/秒估会**偏快 27%**，第一轮 9 段里 4 段超上限。

- 字数上限按**实测语速**算，留 5% 余量。
- **换音色必须先实测**：配 3 段，算「总字数 ÷ 总秒数」，用这个数往下推。
- 超上限的处理是**改文案**，不是截断音频。

### 只重配改动的段（省钱）

配音是按量计费的，改一句不用整条重配。工具支持 `--only`：

```bash
python3 skills/short-drama-trailer/scripts/gen_narration.py \
    --spec <配音表.json> --only 2,3,8,9
```

没在 `--only` 里的段沿用已有的 mp3（读 `配音输出/manifest.json`）。
D7 实测：只重配 4 段花了 909 tokens，比整条重配省一半以上。
**没在 `--only` 列表里、又没有旧产物时，脚本会直接报错**——不静默跳过。

## 响度：压动态，不是压死

D6 批过「有气无力」——**各段响度差 2.8dB**（-16.7 ~ -19.4）。
D7 压动态后齐到 -16.0 ~ -17.1，差别缩到 1.6dB，成片明显有劲。

处理链：**分段 loudnorm 之后加 compressor + 全局 alimiter**。

| 坑 | 表现 | 规矩 |
|---|---|---|
| 二次加速 | 用 `atempo` 叠在已有变速上，成片发飘 | 变速只做一次 |
| 只 loudnorm 不压动态 | 段与段之间音量忽大忽小 | 加 compressor |
| 不加 alimiter | 交叉区叠加超峰（实测 TP +1.24dB 削波） | loudnorm 后必加 |

**测法**：`ffprobe` 读成片各段响度，跟底片比。**峰值反而变低不是异常**——
原声那段有个响的重音被压了，总峰值自然下来。

## 验证到什么程度（别过度验证）

- **落点对不对**：抽帧看画面——解说起点那一帧，画面应该已经切到解说要讲的那场戏。
- **声音进没进去**：抠解说那一段和相邻段比音量包络，或者人耳听。
- **留白区有没有被盖**：抽帧＋比电平（底片 vs 成片同一处）。
- **念得对不对**：**ASR 逐字比对**（11-22 做的，也是查出两处念错的手段）。
  解说形态下要做这一步——纯剪形态不用（画面与原声同源）。
- **不做逐字验证只对纯剪成立**：解说形态下配音是独立生成的一路音频，
  必须自己核对。

## 已知边界

- 画面完全不动，只重编码音频；所以**改解说不用重拼画面、不用重跑素材段**。
  （但改了解说稿的**落点归属**时，留白位置要跟着变，`plan.json` 要改。）
- 两段解说重叠会直接报错（没人听得清重叠的解说）。
- 解说超出成片尾部会报错——改起点或缩短文案，不截断。
- 解说只补画面没说的，不承担「把一条讲不通的片子讲通」的责任。讲不通就回去改清单。
