# 什么时候用

钩子 AI 视频人审通过后，要给同角色配解说旁白时。它解决一个实测坐实的问题：

> **造锚流程（voicedesign 现造 voice.mp3）出来的锚是"标准朗读"，会 MiMo voiceclone
> 压在 ≈13 半音/0.5 跳变的念稿水平，提示词怎么写都顶不破。瓶颈在锚，不在模型。**

AI 钩子里角色"演"出来的声音天然带表演性，拿它当锚：克隆输出表现力明显更高（T2_005 实测
4.8s 女主锚 → 14.1 半音/0.542；混段锚最高到 21.9/0.644），且**音色与钩子天然一致**——
旁白和钩子是同一个人，省掉 138 元复刻，也没有"前后两个人"的穿帮。

# 不做什么

- **不合成旁白**。合成走 `ecommerce-narration`（MiMo voiceclone + 标签法）。
- **不动 card.json、不覆盖 voice.mp3**。换锚是显式决策：换锚 = 本地 + 云端所有依赖点一次换完。
- 不处理没过人审的钩子（钩子重出，锚就得重抽——锚跟着钩子走）。

# 用法

```bash
# 自动：从脚本 JSON 找说话人的台词句，静音分段一一对应
python3 scripts/extract_voice.py --video AI1_v1.mp4 --script-json 脚本.json \
    --speaker 妻子 --out 女主锚.mp3

# 手工：自动对位失败时，人工对时间轴后直接给段
python3 scripts/extract_voice.py --video AI1_v1.mp4 --spans "3.53-6.67,8.87-10.53" --out 女主锚.mp3
```

输出：锚 mp3 + `.report.json`（每段与整体的 F0 跨度/跳变/时长/来源时间，留档对比用）。

# 两条硬规则（已写死在脚本行为里，别绕）

1. **按台词位置截取说话人，禁止凭信号特征猜人**。男女声靠音高分不出来（男声段实测也有
   267Hz 中位）；静音分段数 ≠ 台词句数时脚本直接报错，要求人工 `--spans`，绝不静默猜。
2. **锚总长 < 10s 会向模型先验回归**（脚本会警告）。同一角色台词不够长时，先考虑钩子
   里有没有可加的句，别拿"短但够用"自我说服——实测 4.8s 锚把跨度拉回 13-14。

# 已知特性（用之前要有预期）

- **锚的情绪底色会带进克隆输出**。锚录在冲突/抬杠语境里，输出会整体偏冲偏高亢；
  合成时靠标签法往回调（`(亲切)` 收尾、段落标签降档），收不住就换更平静的句当锚。
- 锚来自成片，可能混着 BGM 的影子；试听时专门留意背景残响。
- 抽卡方差大：同一锚同配方多抽几条，按 `report.json` 的 F0 跨度/跳变挑，再人耳定。

# 指标口径（与 narration / mix 同源，别单改一处）

F0 跨度 = p5–p95（半音），帧间跳变 = 半音/10ms 均值（<6 半音截断防八度误判）。
参考线：造锚流程产物 ≈13/0.5；豆包预设最好 15.4/0.773；AI 视频原声 20.4/0.723。
