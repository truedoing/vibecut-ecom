# ecommerce-video-gen

description: "用 Seedance 2.0 系列出带货短视频（apiyi 网关）：参考图锚场景光线、参考音频锚声音风格、五拍正反打一条 15 秒。内置真人审核规避、异步轮询断点续查。出片是唯一花钱的环节，所以提交前必须先过提示词关卡。触发词：出视频、生成视频、Seedance、AI 钩子、出片。"

## 本技能只做出片，到此为止

```
提交前   提示词关卡（prompt_lint，不通过不许提交）  ← 零成本，拦在花钱之前
            ↓
Stage A  出 AI 钩子（480p，一条 15s）              ← 约 10 元，一次一条
            ↓
         人工审核（五官/第三人/虚焦/台词/撞脸）
            ↓  通过
之后      配旁白 → 混剪  ⇒  不在本技能，见 ecommerce-narration / ecommerce-mix
```

**为什么混剪要拆出去**：出片约 10 元一条、混剪本地免费、旁白按钩子实际时长配。三件事的时间点和失败代价完全不同，塞在一个技能里，Agent 听到"合成一下"就可能往出片那条路走。

**为什么关卡必须在提交之前**：写提示词的人不承担出片成本，承担成本的人没机会改提示词——历史上三次返工（台词念不完、反转没落到最后一拍、情绪平淡）全是提示词层面的问题，每一次都是 10 元。

**执行纪律**

- 提交前先跑 `ecommerce-script-gen/scripts/prompt_lint.py`，有 ERROR 不许提交。
- 提交前先 `--dry-run` 打印请求体，核对参考图/音频顺序与时长。
- 出片后只做到"文件落盘 + 抽帧联系表 + ASR 转录 + 指标表"，然后**停下等审核**。
- 没拿到明确"通过"，不做混剪、不重出。
- 一条片子只出一版钩子；要改就明确说改哪一点，重出一次。

## 脚本

`scripts/seedance.py`（基于 apiyi 官方脚本改造，补了三个能力）：

| 参数 | 说明 |
|---|---|
| `--prompt-file` | 从文件读提示词（长提示词带 `{}` 台词，shell 转义必翻车） |
| `--ref-image` | 参考图，可重复，顺序对应 @Image1/2/3（最多 9 张） |
| `--ref-audio` | 参考音频，可重复，顺序对应 @Audio1/2（最多 3 个、合计 ≤15s，**必须搭配图片**） |
| `--dry-run` | 只打印请求体不提交——先核对顺序和音频时长，不花一分钱 |
| `--task-id` | 续查已提交任务（轮询中断不重新计费） |

模型：`mini`（默认，15s 上限）/ `fast` / `std`（1080p）/ `sd25`（30s、1080p、mov）。

**分辨率默认 480p**（2026-11-04 定）：480p 竖屏是 480×854，混剪时 `scale=720:1280` 放大，
手机端 6 寸屏看不出差别，成本比 720p 低一大截。只有要投大屏/信息流高清位才上 720p。
计费按 token，提交被 400 拒不扣费；直链 24h 过期，脚本自动下载。
key 在仓库 `.env` 的 `APIYI_API_KEY`（令牌须勾 SeeDance2 分组）。

## ⚠️ 真人审核：写实人物参考图必被拒（实测）

提交人物参考图（哪怕是我们 AI 生成的写实定妆照）会报：

```
InputImageSensitiveContentDetected.PrivacyInformation
... may contain real person
```

**判定与图的真实来源无关，只看像不像真人。** 我们的定妆照做得越"生活感"越过不了。
环境图（无人）不触发。规避方式：

- **人物改纯文字描述**（角色卡 look 六维 + wardrobe 直接抄进提示词），场景/光线继续用环境参考图锚定。
- 文字描述里加「不是模特、不是明星脸」，负面词加「明星脸、模特脸」——但**无法完全避免撞脸**，
  出片后必须人工看主角是否像具体演员（撞脸有平台风险）。
- 若后续需要跨片人物一致（同一角色演系列），出路：① BytePlus 官方渠道的真人参考授权流程；
  ② 风格化参考图；③ 接受每条重新生成人物。**实测追加（11-03）：② 已否决**——
  胶片颗粒+柔焦+降饱和+轻微虚化的处理图照样被拒，审核看的是人脸特征本身，与风格无关。
  **③（文字锚）是当前唯一通路**：同 seed + 同一段 look 描述文字 = 人物近似一致（实测 v3/v4
  两次出片人物相近）。角色卡在 Seedance 链路的价值 = look 文字 + voice 锚，定妆照用不上。

## 一条 15 秒四拍正反打的实测结论

单条视频内让模型自己切四个镜头**是可行的**（首测四拍全中、切点约在 5/10/13s），
提示词写法：每镜头独立一段（秒数 + 景别 + 机位 + 动作 + `{台词}`），结尾锁
「两人五官不要混淆、不要第三人」。风险仍要核对：切点漂移（±1s 属正常）、人物跨镜头换衣、
手部畸形。抽帧核对命令：

```bash
ffmpeg -i in.mp4 -vf "select='eq(n,24)+eq(n,96)+eq(n,144)+eq(n,216)+eq(n,264)+eq(n,336)',scale=360:-1,tile=3x2" -frames:v 1 sheet.jpg
```

## 节奏：台词字数是唯一杠杆（11-03 v3/v4 实测）

Seedance **不遵守提示词里的时间码**——它按文本顺序念，念完就停，留尾巴给画面。
两次实测规律：

| 台词量 | 实测念完用时 | 语速 | 结束点 |
|---|---|---|---|
| 45 字 / 15s | 9.7s | 4.6 字/秒 | 65% 处，后 5s 空转 |
| 68 字 / 15s | 11.4s | 6.0 字/秒 | 76% 处，后 3.7s 咀嚼声填充 |

- **想让对白铺满时长，就按 ~4.5–6 字/秒 × 时长 给字数**；字少了必然前段挤爆后段空。
- **提示词里的语速词响应极强**：写「咬字很快/抢话」模型真的会冲到 7 字/秒（听不清），
  要控语速直接写「语速中等，像日常说话」。节奏快 ≠ 语速快：切镜快靠「动作一到位立刻切镜」，
  语速快靠字数密度。
- 「行」这类单字台词会被吸附进上一镜结尾——单字开头换成「我不吃，一口都不碰」这类双字起。
- 反问句容易被念成陈述句：在提示词里写「语气是反问，句尾上扬，带着 X 的得意」，
  并在负面词里加「台词被截断」。
- **验证工具链**：抽帧联系表（画面）+ `AudioTranscribe`（转录对白核对完整性/吞字/粘连）
  + `silencedetect`（对白/静音分布）。三者合用比肉耳精确。

## 音频（实测）

- 对白写进 `{}`，模型自己配音；参考音频只给**风格**（音区/语速/节奏），**不是音色克隆**——
  输出声音"像"参考但不精确一致。要绝对一致的音色：出片后整轨替换（口型会有偏差）。
- 成片响度 -14.8 LUFS 正合适；**LRA 6.8，比 MiMo TTS（约 3）的动态好一倍**——
  AI 钩子的对白不用再过响度处理。
- 参考 audio 的 data URI（`data:audio/mpeg;base64,...`）apiyi 接受，与图片同法。

## 出片后核对清单（五条）——这就是 Stage A 的验收

1. 人物长相是否符合设定、**是否撞脸具体明星**（最高风险）
2. 手部：手指数量、持物是否正常
3. 罐子全程虚焦、标签不可读（假包装穿帮线）
4. 四句台词念清没有、男女音色有没有互换、有无背景音乐混入
5. 光线是否左窗暖白（与混剪桌拍素材同色温）

## Stage A 一次完整调用

```bash
python3 skills/ecommerce-video-gen/scripts/seedance.py \
  --prompt-file <prompt.txt> \
  --ref-image <环境图.jpg> \
  --ref-audio <夫.mp3> --ref-audio <妻.mp3> \
  --duration 15 --ratio 9:16 --resolution 480p --seed 20261103 -o out.mp4
```

出片后到 `出片后核对清单` 为止，**停**。混剪等审核。

## 下游（不属本技能）

钩子过审后：旁白见 `ecommerce-narration`，句边界与混剪见 `ecommerce-mix`。
本技能不生成旁白、不切画面、不合成。

## 别做

不在 Stage A 里顺手把混剪也跑了。
提示词 lint 有 ERROR 就提交（那 10 元买的是教训，不是片子）。
一次改多个变量再重出——重出一次只能改一个点，否则学不到是哪条改动起的作用。
