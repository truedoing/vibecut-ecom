## 开工三问（v0.3，别拿轻食六型角度来问）

1. **先给方向，不选技术参数**：派 `short-drama-script` 出一张选题单（2–3 条故事线、
   各一句角度、推荐哪条和理由，**每条标明主线还是副线、打算多长**），**人圈定一条才排段表**。
   别一上来就问「重复型还是弧线型」——那是选定线之后才判的内部参数，用户不替我们做这个判断。
   主副线定性要跟选线一起点头：它决定这条片子做 4–6 分钟还是 2–3 分钟、抽几场（11-11 补）。
2. **这条片子用哪种 AI 玩法**：同一张选题单上一起圈。默认「不点菜＝纯剪」；
   点了玩法才留插入位、才有出片费用（10s/480p ≈ 2 元）。
3. **本批几条**：成本闸门按批报。

## 链路不是七步排成一队，是三层 + 一个小循环（11-10 20:1x 张老师定）

| 层 | 内容 | 改得多不多 |
|---|---|---|
| 慢层：剧包 | 选片 → 建包 → 素材索引，一部剧做一次 | 很少，改了才动 |
| 共用层 | AI 玩法菜单、角色与场景资产，所有剧共用 | 偶尔微调 |
| 快层：一条片子 | 选题单+清单 → 按玩法生成素材段（可跳过）→ 拼成片 | 反复跑，构成小循环 |

- **一部剧能有好几条片子**（婆婆线、标签线…），各记各的进度，改一条不牵连另一条。
- **快层是个小循环**：人看成片提意见 → 回清单改 → 再拼一遍。每轮留一版成片，旧版标
  `superseded`，绝不拿旧版当下一步推荐。**一条片子反复改版** 和 **两条并列片子** 是两回事，
  进度别混记。
- **循环里最要紧的省钱规矩**：改清单 ≠ 重做出片。只改选段/顺序 → 只重拼成片，
  已生成的素材段留着换插入位；改的是那段素材的台词或上下文 → 才重新出片。
  出片是唯一花钱的环节。
- **换剧包＝挂起，不是作废**：上一部的进度留在原处，切回来接着走。

改动频率不同，影响范围就不同，详见「改动影响表」。

## 状态台账：唯一真源是文件，不是记忆

```
runs/工作台.json                  # 当前选中哪部剧、哪条片子 + 共用层当前版本（唯一一处）
runs/<剧名>/<任务>/状态.json      # 一条片子一份进度，模板见 references/状态模板_短剧.json
```

**开工第一件事读工作台**：不指定剧名/任务就沿用 `active`；说「换到 X 剧」才改 `active`，
只改这一处，不删不搬任何历史。新会话读错表＝把 A 剧进度报成 B 剧，
所以「当前选中」必须落在文件里，不靠对话记忆。

工作台的 `dramas` 表是**全产线唯一的目录对照**：一部剧对应三处目录（剧集包 / 台词与索引 / 各条片子），
而且包和素材用全名、片子目录用短名（`八零憨妻`）。换剧包后按这张表找资料，别靠拼名字。
各份资料第几版仍以 `shared.drama_base` 为唯一真源，不在 `dramas` 里另记一份。

v0.2 七个环节：`select → pack → asset_index → ai_assets(可选) → script → weave_video(可选) → trailer`。
**旧键名不迁移**：11-09 电视框三拍的 `hook_frame_spec` / `hook_frame_video` / `narration` 等
遇到只报「旧形态，不计入进度」，不猜、不补。

```bash
python3 skills/short-drama-supervisor/scripts/status_overview.py --root runs --detail
python3 skills/short-drama-supervisor/scripts/status_overview.py --stale-only
```

### 要重做是算出来的，不是人写进去的

两套比对，都只读派生、不改状态文件：

1. **文件内**：每个产物写 `depends_on`（依赖谁）+ `depends_rev`（建它时各依赖的版本快照）。
   脚本比对当前版本与快照，上游一改，下游一条链自动判要重做。`superseded` 明确跳过。
2. **跨文件（共用层）**：工作台 `shared` 记剧包/玩法配方/共用资产当前版本；
   每条片子的状态文件记 `shared_snapshot`（建它时的版本）。脚本比对两者，
   共用层一改，只把**用到它的**片子标出来，不是全剧全批一起重做。
   旧台账没有 `shared_snapshot` 时自动跳过，11-10 已验收结果不变。

状态值定义域：`pending / in_progress / done / approved / stale / superseded / blocked`，越界会标出来。

> 这套修的是 11-10 三测试查出的机制缺失：旧主管 SKILL.md 承诺「自动传播」，脚本里
> 却没有任何版本比对逻辑，状态文件里的 stale 全是人手工写的。新主管不背这笔旧账。

## 改动影响表（改前先查这张，改后按第三列重验）

| 改了什么 | 影响范围 | 要重验 |
|---|---|---|
| **换剧包（切换工作对象）** | 只改工作台 `active`；**挂起，不改任何片子** | 切回来能接着走 |
| 剧包 / 台词库 / 素材索引改了 | **这部剧下**每条片子的清单要重看；别部剧不受影响 | 该剧清单与成片 |
| 换了一条故事线（选题单） | **这一条片子**整张清单重排 → 成片重拼 | 按新一条片子跑 |
| **主/副线定性改了**（11-11 新增） | **这一条片子**的取段密度与时长整张重排，不是加减两段 | 清单 + 成片；剧包、索引、素材段都不动 |
| 这条片子换了 AI 玩法 | 清单重排（留不留插入位）→ 成片重拼；剧包不动 | 该条片子 |
| 某道玩法卡 / 配方 / 共用角色资产改版 | **只影响点了这道玩法的片子**；纯剪和别道菜不受影响 | 那些片子的素材段 + 成片 |
| 菜单上新增一道玩法 | 已有片子一条都不动 | 只是多一个可选项 |
| 剪辑清单改了（选段 / 顺序） | 成片重拼；**已生成的素材段可复用，别重跑花钱那步** | 成片 |
| 成片人不满意 | 只在快层三步里转，**不回到底层** | 新一轮留版 |
| 装配脚本 | 所有切点与时长 | 定版用例 + 织入版（334.84s） |
| 状态台账 / 本入口表 | 所有线的「下一步」 | 三测试 + `--stale-only` |

**任何改动从本入口登记**：改动方报「改了哪个产物、版本从几到几」，由脚本传播，
不在下游技能里各自记一笔。共用层改版由主管同步写进 `runs/工作台.json` 的 `shared`。
这是「一个入口、更好测试调整」的落点。

## AI 玩法菜单（现在只留位置，不建空技能）

**一本菜单 + 每道菜一张卡 + 一次选择**，不是流水线上的新环节：

- 菜单 `runs/工作台.json` → `shared.ai_strategies` 只记三样：名字、状态、**版本**，
  加一个 `recipe` 指向玩法卡。**卡的内容不复制进菜单**（同一件事记两处必落后）。
- 玩法卡放 `runs/玩法菜单/<玩法 id>.md`，一道菜一张，只写六件：什么片子适合用、
  要准备什么、生成出来的东西插在哪、花多少钱与哪几处人过目、三层说明各在哪份文件、
  什么时候把版本加一。**三层（角色资产 / 生成 / 插入）各管一段，卡只做指针，不合并内容**。
- 选题单照卡里「什么片子适合用」那栏逐条对这部剧，命中哪条写进推荐理由，不凭印象。
- 这条片子点哪道，记在状态文件顶层 `ai_strategy`；**不写＝`none`＝纯剪**（模板默认也是 none）。
- 王婶旁观是第一道菜（`wangshen_weave`），卡在 `runs/玩法菜单/wangshen_weave.md`。
  目前只有这一道做了出来，两个下游技能仍是王婶实现，**别当成已经通用**。
- 装配器只认「哪一段插在哪个位置」，不关心插进来的叫不叫王婶，**加一道玩法不用改流程**。
- 花钱与人审红线挂在卡上，不写死在主流程：不同玩法将来花钱和验收方式不一样。
- **版本怎么加一**：改卡任一栏、或改三层里任何一条硬规矩 → 主管把工作台这道菜的 `rev` 加一，
  进度脚本自动把点了这道菜的片子标「要重做」；只改错别字 / 补例子不加。
  新菜若没登记或没写版本，脚本会明确提醒，不静默跳过。
- **现在不建空的「AI 策略」技能**：空技能会被当成已实现，且没有第二道菜可参照。
  等第二种玩法真做出来、有了两张卡，再收成技能。

选题单必须赶在排清单之前同时圈线和圈玩法：点了玩法，清单就得留插入位；
清单排完再点，整张表要推倒重排。

## 门禁

| 门 | 位置 | 谁放行 |
|---|---|---|
| 选片 | 建包前 | 张老师（做 / 不做） |
| G0 | 剧集包 | 人审 |
| **选方向** | **选题单（2–3 条故事线 + 用哪种 AI 玩法）** | **张老师一次圈定，没圈定不排清单** |
| G1 | 剪辑清单 plan.json ＋ `清单过目.md`（**两份一起给**；11-11 起替代原三件套——过目文档只写要确认的问题，15 行内） | 人审：只看要确认的问题，逐条给结论；由主管记进 `artifacts.script.state`（`done`→`approved`） |
| G2 | 选中玩法生成的素材段 | 台词人审 → 试跑 → 出片 ASR 验收 |
| G3 | 装配成片 | 成片人审 |

> 「选方向」和「交人过目」都是 `script` 环节**内部**的停，不新增流水线环节、不改七环节定义、
> 不进依赖作废链（11-10 22:4x 第五步体检后补第二道）。
> **换了线就当新一条片子**：整张清单重排、成片重拼，不是改几段。
> G1 只查内容，装配器只查技术：能装配不等于剪得对，别拿试跑通过当人审通过。

**出片是唯一花钱的环节**：台词未经人审、未跑试跑，不许提交。

## 素材索引的派生缓存依赖（11-11 定）
`index.sqlite`（查询缓存）依赖台词库与镜头索引的 JSON。**这条依赖由主管盯着**：素材索引环节有任何变更（重抽台词、重打标、改人物规则），缓存必须跟着重建——现已做成自动（两个索引脚本写完 JSON 即自调 build_index.py），主管只需在验收时确认脚本输出里有「SQLite 查询缓存已重建」一行；没有就手动跑一次并记偏差。
