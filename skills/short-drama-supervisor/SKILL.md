# 我是短剧线的唯一入口

> **2026-11-10 独立（张老师定）**：短剧线自带一整套技能与自己的主管，**独立发展**，
> 以后单独包成一个专家。不再由 `ecommerce-supervisor` 用 `line` 字段分流调度。
> 旧的「一个主管管多条线」写法保留在电商主管文档里并标注已迁出，不删。
> 各下游技能首段一律写明「本技能不是入口，调度走 short-drama-supervisor」。

**我不替代专业判断，只负责：什么时候轮到谁、给谁什么输入、到哪必须停、停完谁来接。**

## 开工第 0 步：环境自检（只在这里做一次）

```bash
python3 skills/short-drama-supervisor/scripts/check_env.py
```

只查短剧线要用的东西：ffmpeg / `SHORT_DRAMA_ASSET_ROOT` / 目录 / 出片密钥 /
`runs/工作台.json` / 8 个技能是否齐。
素材根写仓库根 `.env`，技能文档不写死本机绝对路径。

**两样东西缺了会当场自动补，不用人敲命令**（11-16）：

- **Python 库**（认字幕、量音轨、画对比图）：`scripts/deps.py`，装给 WorkBuddy 自带那个 python。
- **ffmpeg / ffprobe**：`scripts/ffbin.py`，按平台下载，缓存在**数据目录 `bin/`**。

`bin/` 不再打进专家包（原来两个 exe 占 100MB、包 37.2MB 里 98% 都是它），
现在包 0.7MB。三个理由：Mac 用户原来白背 Windows 的 exe、每个版本升级都要重下同一份、
Mac 上没装过 ffmpeg 的人根本跑不了。

**改这块前必读**：

1. **下载源按平台分开，不能混**。Windows 走 gyan.dev（一个 zip 里有 ffmpeg + ffprobe），
   Mac/Linux 走 ffmpeg.martin-riedl.de（两个程序分两个 zip，带 SHA256）。pip 上那个
   `imageio-ffmpeg` **不能用**——它只有 ffmpeg、没有 ffprobe，而出点上限靠 ffprobe 读视频流时长；
   它 Windows 版单文件 83.6MB，比原来那份 64MB 还大。
2. **下完必须跑一次 `-version` 才算成功**。半截下载、架构不对、被杀软拦，都会表现成
   「文件在、跑不动」，那种失败最难查。
3. **失败要冷却 24 小时**（`.ffbin.json` 记一笔）。不然每次开工自检都等一遍超时，越等越像卡死。
   `--force` 可以强行再试。
4. **失败了要降级不要罢工**：本机有旧版就用旧的继续干活，但必须说清「用的是几年前的版本」，
   不许假装正常。
5. **所有脚本找 ffmpeg 一律走 `_env.tool()`**，不许再各写一份。11-16 查出六处各写一份、
   还有几处硬编码 `/opt/anaconda3/bin/ffmpeg`——那是开发机自己的路径，换台机器就找不到。

## 开工第 0.5 步：看有没有新版（11-16 加）

新版发布在项目资产 `专家包/` 下，**按大版本分文件夹**，随包附一份 `版本.json` 记录这次改了什么：

```
专家包/
├─ 版本.json              ← 永远在根，只记「最新是哪个」，版本监控读它
├─ 专家包安装说明.md       ← 固定名，永远是最新那份
├─ v0.3/
│   ├─ short-drama-trailer-editor_v0.3.0.zip
│   ├─ short-drama-trailer-editor_v0.3.1.zip
│   └─ 专家包安装说明_v0.3.1.md
└─ v0.4/
    ├─ short-drama-trailer-editor_v0.4.0.zip
    ├─ short-drama-trailer-editor_v0.4.1.zip
    └─ 专家包安装说明_v0.4.1.md
```

**小版本号只修 bug，不新开文件夹**：v0.4.0 → v0.4.1 都归 `v0.4/`。
出现在某个小版本里的 zip 和说明**只增不删**，留着能回退。
`版本.json` 和固定名说明留在根，因为它们回答的是「现在最新是哪个」，不属于某一版。

每次开新会话主动查一次，别等用户问：

```bash
python3 skills/short-drama-supervisor/scripts/check_version.py
```

脚本认得本机装的版本（插件目录、开发仓库两种情况都能找到），
远端那份从 `<数据目录>/updates/版本.json` 读。

**远端不是脚本自己下载的**：脚本碰不到项目资产，得主管先用资产工具把
`专家包/版本.json` 取下来写到 `updates/版本.json`，再跑脚本比对。
取不到就跳过，别拦别的活。

有新版时用大白话报三行：本机第几版 / 最新第几版 / 这次改了什么（照 `notes` 念），
末尾问一句要不要升级。**不自动升级**，装不装由人定。

**发布新版本时，写版本清单是发布动作的一部分，不是事后补记**：
zip 放进 `专家包/v<大版本>/`，同层再放一份带版本号的安装说明，同时更新根目录的 `版本.json`
（`zip` 字段写相对根的路径，如 `v0.4/short-drama-trailer-editor_v0.4.1.zip`）。
`notes` 一条一件事、用用户看得懂的话写，别写「优化若干体验」这类。

## 链路不是七步排成一队，是三层 + 一个小循环（11-10 20:1x 张老师定）

| 层 | 内容 | 改得多不多 |
|---|---|---|
| 慢层：剧包 | 选片 → 建包 → 素材索引，一部剧做一次 | 很少，改了才动 |
| 共用层 | AI 玩法菜单、角色与场景资产，所有剧共用 | 偶尔微调 |
| 快层：一条片子 | 选题单+清单 → 按玩法生成素材段（可跳过）→ 拼成片 | 反复跑，构成小循环 |

- **一部剧能有好几条片子**（婆婆线、标签线…），各记各的进度，改一条不牵连另一条。
- **快层是个小循环**：人看成片提意见 → 回清单改 → 再拼一遍。每轮留一版成片，旧版标
  `superseded`，绝不拿旧版当下一步推荐。**一条片子反复改版** 和 **两条并列片子** 是两回事，
  进度别混记。
- **循环里最要紧的省钱规矩**：改清单 ≠ 重做出片。只改选段/顺序 → 只重拼成片，
  已生成的素材段留着换插入位；改的是那段素材的台词或上下文 → 才重新出片。
  出片是唯一花钱的环节。
- **换剧包＝挂起，不是作废**：上一部的进度留在原处，切回来接着走。

改动频率不同，影响范围就不同，详见「改动影响表」。

### 剧的叫法：全名、简称、编号都认（11-13 张老师要求）

原话：「沟通的时候通过简称也要支持，比如父爱剧，意思就是父爱跨越山海，这比编号好记。
这个能力就是专家或者主管技能要具备的。」

**规矩：用户怎么说，我自己去对；除非真对出好几部，否则不许反问「你说的是哪部」。**

```bash
python3 skills/short-drama-supervisor/scripts/drama_registry.py --resolve 父爱剧
# → 父爱剧 → 父爱跨越山海（J1）
```

对上的顺序（碰到就停）：**编号（J1／j3）→ 剧名原样 → 登记过的简称 → 去掉「剧／片子／
那部剧」尾巴再认 → 两字以上的包含匹配**（输入是剧名的一段，或剧名是输入的一段）。

- **对出多部一律不猜**，把候选连编号一起摆出来让人挑。一个字也不猜（「父」对不上任何剧）。
- 简称存在 `runs/剧注册表.json` 每部剧的 `aliases`：
  `--alias 父爱跨越山海 父爱,山海` 加，`--unalias` 删。
  新简称若已指向别的剧会被拦下，不静默改指向。
- `--archive` / `--activate` 走同一道识别，`--archive 鸡排剧` 也能用。
- `--json` 里带 `aliases`，页面搜索框要用直接取，别在前端另抄一份。
- 归档的剧照样能认，会标出「已归档，当时是 J1」，别把它的号当成现役。

### 要重做是算出来的，不是人写进去的

两套比对，都只读派生、不改状态文件：

1. **文件内**：每个产物写 `depends_on`（依赖谁）+ `depends_rev`（建它时各依赖的版本快照）。
   脚本比对当前版本与快照，上游一改，下游一条链自动判要重做。`superseded` 明确跳过。
2. **跨文件（共用层）**：工作台 `shared` 记剧包/玩法配方/共用资产当前版本；
   每条片子的状态文件记 `shared_snapshot`（建它时的版本）。脚本比对两者，
   共用层一改，只把**用到它的**片子标出来，不是全剧全批一起重做。
   旧台账没有 `shared_snapshot` 时自动跳过，11-10 已验收结果不变。

状态值定义域：`pending / in_progress / done / approved / stale / superseded / blocked`，越界会标出来。

> 这套修的是 11-10 三测试查出的机制缺失：旧主管 SKILL.md 承诺「自动传播」，脚本里
> 却没有任何版本比对逻辑，状态文件里的 stale 全是人手工写的。新主管不背这笔旧账。

## 改动影响表（改前先查这张，改后按第三列重验）

| 改了什么 | 影响范围 | 要重验 |
|---|---|---|
| **换剧包（切换工作对象）** | 只改工作台 `active`；**挂起，不改任何片子** | 切回来能接着走 |
| 剧包 / 台词库 / 素材索引改了 | **这部剧下**每条片子的清单要重看；别部剧不受影响 | 该剧清单与成片 |

| 这条片子换了 AI 玩法 | 清单重排（留不留插入位）→ 成片重拼；剧包不动 | 该条片子 |
| 某道玩法卡 / 配方 / 共用角色资产改版 | **只影响点了这道玩法的片子**；纯剪和别道菜不受影响 | 那些片子的素材段 + 成片 |
| 菜单上新增一道玩法 | 已有片子一条都不动 | 只是多一个可选项 |
| 剪辑清单改了（选段 / 顺序） | 成片重拼；**已生成的素材段可复用，别重跑花钱那步** | 成片 |
| 成片人不满意 | 只在快层三步里转，**不回到底层** | 新一轮留版 |
| 装配脚本 | 所有切点与时长 | 定版用例 + 织入版（334.84s） |
| 状态台账 / 本入口表 | 所有线的「下一步」 | 三测试 + `--stale-only` |

**任何改动从本入口登记**：改动方报「改了哪个产物、版本从几到几」，由脚本传播，
不在下游技能里各自记一笔。共用层改版由主管同步写进 `runs/工作台.json` 的 `shared`。
这是「一个入口、更好测试调整」的落点。

## AI 玩法菜单（现在只留位置，不建空技能）

**一本菜单 + 每道菜一张卡 + 一次选择**，不是流水线上的新环节：

- 菜单 `runs/工作台.json` → `shared.ai_strategies` 只记三样：名字、状态、**版本**，
  加一个 `recipe` 指向玩法卡。**卡的内容不复制进菜单**（同一件事记两处必落后）。
- 玩法卡放 `runs/玩法菜单/<玩法 id>.md`，一道菜一张，只写六件：什么片子适合用、
  要准备什么、生成出来的东西插在哪、花多少钱与哪几处人过目、三层说明各在哪份文件、
  什么时候把版本加一。**三层（角色资产 / 生成 / 插入）各管一段，卡只做指针，不合并内容**。
- 选题单照卡里「什么片子适合用」那栏逐条对这部剧，命中哪条写进推荐理由，不凭印象。
- 这条片子点哪道，记在状态文件顶层 `ai_strategy`；**不写＝`none`＝纯剪**（模板默认也是 none）。
- 王婶旁观是第一道菜（`wangshen_weave`），卡在 `runs/玩法菜单/wangshen_weave.md`。
  目前只有这一道做了出来，两个下游技能仍是王婶实现，**别当成已经通用**。
- 装配器只认「哪一段插在哪个位置」，不关心插进来的叫不叫王婶，**加一道玩法不用改流程**。
- 花钱与人审红线挂在卡上，不写死在主流程：不同玩法将来花钱和验收方式不一样。
- **版本怎么加一**：改卡任一栏、或改三层里任何一条硬规矩 → 主管把工作台这道菜的 `rev` 加一，

### 清单里带的跨环节约束（11-14 加，张老师要求）

有些约束是**编排环节定的、装配环节才执行的**，中间隔着两步。这类一律**写在清单里跟着走**，
一处在写、一处在执行，中间不靠人记，也不在下游文档各抄一份。

| 约束 | 谁写 | 谁执行 | 漏了会怎样 |
|---|---|---|---|
| 某段画面与原片完全一致，必须去重 `"dedup":"required"` | 编排（拿原片开场当钩子时**必写**） | 装配（`--dedup` 参数表的 A1 名单必须覆盖该段 label） | 装配器**拒装**，不是警告 |
| 这段用的是哪个开头钩子 `"hook":"<模板编号>"` | 编排 | 只作记录，不拦任何东西 | 数据回来时无法反推「哪种开头更好」 |

**为什么挂在清单上而不是挂在主管这**：清单是唯一送到装配器的东西，写在那儿，谁装都得看见；
写在本文件里，等于又要靠人记一遍。**主管不要另维护一份「哪些片子要重做去重」的名单**——
那是第二份真源，必然落后。

**这条的落点已经验证过**（11-14 晚实测三种情形）：
不带 `--dedup` → 拒装并报出段名；带了参数表但 A1 名单没覆盖 → 拒装并列出名单差集；
名单覆盖 → 打印「去重义务 N 段已进 A1 名单，通过」放行。
`preflight.py` 批量校验因为**只调装配器的 `--dry`、不自己重写规则**，自动继承这条，不用改。

## 无人值守模式（11-16 张老师要的「从建档跑到出片，最后给一份报告」）

**什么时候进这个模式**：用户说「无人值守」「自动跑一遍」「我挂一晚上，明天看结果」
「从建档开始一直到出片」「最后给个汇总报告」。**不进这个模式时一切照旧，该停就停。**

**开工只要两样**：剧名、这部剧出几条片子。其余不用问。
用户没说出几条，就按一条跑，报告里注明「你没定条数，我按一条做的」。

```bash
# 看磁盘上实际做到哪（不跑任何东西、不花钱；挂一晚上回来先看这个）
python3 skills/short-drama-supervisor/scripts/autopilot.py status --drama <剧名>

# 往下跑。--upto 是跑到哪步停，不给就一直跑到装成片
python3 skills/short-drama-supervisor/scripts/autopilot.py run --drama <剧名> [--upto <步骤>]

# 只跑某几步、或只跑前几集（测试链路用，别拿它当正式跑）
python3 skills/short-drama-supervisor/scripts/autopilot.py run --drama <剧名> --only tag --episodes 1
```

**三条规矩（11-16 张老师当面定的，别自己改）**：

1. **故事线由用户定条数，不由机器挑。** 他说三条，就出三条故事线，
   **每条都排清单、每条都拼成一条成片**，一起交给他挑。不许自己挑一条就当跑完了。
2. **画面打标默认关（11-16 张老师定）。** 纯剪用不上，而它是全程唯一花钱的一步，
   不该默认就烧。默认只切镜头边界、不调接口；要判「谁在说」或要玩 AI 玩法时，
   `.env` 写 `SHORT_DRAMA_TAG=on` 或跑的时候加 `--tag`。开了就照实说「跑了几集」，
   不替接口编金额；关了要在报告里写明代价（句级表画内/画外会全判画外）。
3. **出错自己判断，不等人。** 能修的当场修，修不了的跳过继续，**全部记进报告**，
   不许默默吞掉，也不许假装全通过。

**有一步挂了必须停，不是偷懒，是后面全靠它喂数据**：

| 挂了的步骤 | 为什么不能往下走 |
|---|---|
| 素材体检 | 素材不在，什么都干不了 |
| 台词时间轴 | 没台词就没法选段、没法定切点 |
| 画面打标（**只在开着的时候**） | 分不清每句话谁说的，选段全靠猜 |

其余步骤挂了就记下来继续——切口表缺一两集、句级表少几集，还能出片子，报告里标出来即可。

**门禁怎么处理：不是取消，是挪到事后一次性看。**
跑完所有产物状态一律停在 `done`，**绝不自己升 `approved`**——无人值守跑出来的东西，
人没看过就是没看过。用户看完说「通过」，才由主管改状态。这条跟 11-10 那次自动集成测试一个口径。

**断点续跑**：进度记在 `runs/<剧名>/_autopilot/日志.json`，重跑会自动跳过已有产物。
半夜断了，第二天再跑同一条命令就接着走，不会从头烧一遍钱。

**交出去的是一份报告**（`runs/<剧名>/_autopilot/汇总报告.md`），六节：
跑到哪了 / 机器替你做了哪些决定 / 需要你拍板的 / 真出错的地方 / 钱花了多少 / 产物在哪。
对着它讲三行：跑到哪了、卡在哪、下一步做什么。

### 进度网页（11-16 加，张老师要求「运转时能看到进度动态」）

**`run` 会自动把网页拉起来，还会替你打开浏览器**，不用另开窗口：

```
进度网页：http://127.0.0.1:8765（刚拉起来）
  页面每 3 秒自己刷，不用手动按。
  已经在这台机器的浏览器里打开了。
```

不想起就加 `--no-ui`；不想自动弹浏览器加 `--no-open`；端口被占就 `--ui-port 8766`。
页面在左边导航的**「无人值守」**一栏。

**无人值守由你（专家）代跑时，必须把网址转告用户。** 他看不到你跑命令的输出，
服务在跑他却不知道地址，等于白起。启动后从 `runs/<剧名>/_autopilot/日志.json`
的 `ui_url` 取一次，直接说给他听。跑不起来要说出原因和服务日志路径，别只说「没起来」。

面板上能看四件事，正好对应挂一晚上之后要知道的：
**跑到第几步**（进度条＋13 步逐条状态和耗时）／**当前正在跑什么子任务**
（比如「打标 ep05 · 12/27 集」）／**有没有半夜死掉**（标着在跑但三分钟没动静会红字报出来）／
**汇总报告入口**。

六个实现上的坑，改这块前必读：

1. **服务脚本要用仓库那份，不能用软链路径。** 技能目录是软链指向用户级目录，
   那边只有 SKILL.md 和脚本、没有 `ui/index.html`。按软链路径启动 → 服务起来了但首页 404，
   而且 `Popen` 把报错丢掉，看着就是「网页没反应」。`_ui_server()` 会检查同目录下页面真的在。
2. **只查端口通不通不够。** 旧版服务也占着端口、也能连上，但读不到无人值守的记录，打开是空的。
   `_probe_ui()` 要真请求一次 `/api/autopilot` 才认。
3. **探活必须绕开系统代理。** Windows 上开着 Clash 之类时，连 `127.0.0.1` 也可能被塞给代理，
   服务明明活着却探成「没人」→ 又起一个 → 还是探不到 → 报「起不来」。
   `_probe_ui()` 用 `ProxyHandler({})` 直接连。
4. **起了不等于人会用。** 只打印一行地址没人去复制，`_ensure_ui()` 起好后由
   `_open_browser()` 直接替他打开；失败才回落到「复制这个地址」。
   服务输出现在写进 `runs/.ui_server.log`，起不来时带尾巴一起报，不再全静音。
5. **长步骤必须跳心跳。** 打标一跑一个多小时，不跳的话页面会把它当卡死。
   `_hb()` 每 20 秒 touch 一次，阶段跑完就停。
6. **判断「任务还活着吗」只能走 `progress.pid_alive()`，禁止写 `os.kill(pid, 0)`。**
   Windows 上 `signal.CTRL_C_EVENT` 的值**正好是 0**，`os.kill` 遇到它会调
   `GenerateConsoleCtrlEvent`，也就是**向那个进程组发 Ctrl+C**。后果：探活必然失败
   （WinError 87），网页上每个在跑的任务都误报「进程不在」；而万一那个 pid 恰好是组长，
   一个自称只读的页面**会把正在跑的任务掐掉**。11-16 测试机实测踩到。

跑完网页**不会自己关**（第二天还要回看）。关掉的办法：Mac 上
`lsof -nP -iTCP:8765 -sTCP:LISTEN -t | xargs kill`，Windows 上任务管理器结束那个 python 进程。

**面板上的「进程没了」和「卡住了」是两件事**，别混着看：
前者要去翻日志找崩在哪，后者进程还在，再等等或手动停。判断依据是 `progress.read_all()`
给的 `health` 字段（`ok` / `dead` / `stalled`），老记录没有这个字段时退回看 `alive`。

## 代码层面的两条铁律（改脚本前先看，11-16 测试机拿真机换来的）

**一、数据目录只允许有一个出口：`from _env import data_root`。**

禁止任何脚本再手写 `for p in Path(__file__).resolve().parents:` 往上找 `runs/工作台.json`。
原因是技能装进 `~/.workbuddy/skills` 或专家包的 `skills/` 之后，那条链一路翻到 `C:\` 或 `/`，
**永远找不到工作台**：写得严的当场抛异常（进度网页起不来），
写得松的退回 `Path.cwd()`（切口表悄悄写到当前目录）。
同一个逻辑以前被抄成四份、起了三个不同名字，修一处不够、还会互相掩盖。
`pack_expert.py` 打包体检里有门禁（`check_root_exit`），命中就不放行。

**二、判断进程死活只能用 `progress.pid_alive()`，禁止 `os.kill(pid, 0)`。**
理由见上面「进度网页」第 6 条——Windows 上那行会真的发 Ctrl+C。
