# 我是短剧线的唯一入口

> **2026-11-10 独立（张老师定）**：短剧线自带一整套技能与自己的主管，**独立发展**，
> 以后单独包成一个专家。不再由 `ecommerce-supervisor` 用 `line` 字段分流调度。
> 旧的「一个主管管多条线」写法保留在电商主管文档里并标注已迁出，不删。
> 各下游技能首段一律写明「本技能不是入口，调度走 short-drama-supervisor」。

**我不替代专业判断，只负责：什么时候轮到谁、给谁什么输入、到哪必须停、停完谁来接。**

## 开工第 0 步：环境自检（只在这里做一次）

```bash
python3 skills/short-drama-supervisor/scripts/check_env.py
```

只查短剧线要用的东西：ffmpeg / `SHORT_DRAMA_ASSET_ROOT` / 目录 / 出片密钥 / 7 个下游技能是否齐。
素材根写仓库根 `.env`，技能文档不写死本机绝对路径。

## 开工三问（v0.2，别拿轻食六型角度来问）

1. **先给方向，不选技术参数**：派 `short-drama-script` 出一张方向卡（2–3 条故事线、各一句角度、
   推荐哪条和理由），**人圈定一条才排段表**。别一上来就问「重复型还是弧线型」——
   那是选定线之后才判的内部参数，用户不替我们做这个判断。
2. **要不要王婶织入位**：可选。要就多一道台词人审 + 一次出片费用（10s/480p ≈ 2 元）。
3. **本批几条**：成本闸门按批报。

> **方向卡是「编排」这一环里的第一道停，不是新环节。** 台账仍在 `script` 产物下记一个
> `direction_card` 字段，`STAGES` 七个环节、`status_overview.py` 都不动——
> 11-10 已验收的「5 个必选环节 / 无卡点 / 上游改版连锁重做」不能因为加一道停就重验。

## 状态台账：唯一真源是文件，不是记忆

```
runs/<剧名>/<任务>/状态.json     模板见 references/状态模板_短剧.json
```

v0.2 七个环节：`select → pack → asset_index → ai_assets(可选) → script → weave_video(可选) → trailer`。
**旧键名不迁移**：11-09 电视框三拍的 `hook_frame_spec` / `hook_frame_video` / `narration` 等
遇到只报「旧形态，不计入进度」，不猜、不补。

```bash
python3 skills/short-drama-supervisor/scripts/status_overview.py --root runs --detail
python3 skills/short-drama-supervisor/scripts/status_overview.py --stale-only
```

### stale 是算出来的，不是人写进去的

每个产物写 `depends_on`（依赖谁）+ `depends_rev`（建它时各依赖的 rev 快照）。
脚本比对当前 rev 与快照，**上游一改，下游一条链自动判 stale**，不靠谁记得。
`superseded` 明确跳过，绝不会再报「可开工一个已废弃产物」。
状态值定义域：`pending / in_progress / done / approved / stale / superseded / blocked`，越界会标出来。

> 这条修的是 11-10 三测试查出的机制缺失：旧主管 SKILL.md 承诺「自动传播」，脚本里
> 却没有任何 rev 比对逻辑，状态文件里的 stale 全是人手工写的。新主管不背这笔旧账。

## 改动影响表（改前先查这张，改后按第三列重验）

| 改了什么 | 顺着影响 | 要重验 |
|---|---|---|
| **换了一条故事线（方向卡）** | **整张段表重排 → 成片重装配** | 当新一条片子跑，不是改几段 |
| 剧集包 / 台词库 | 索引 → 选段 → plan → 成片 | 全部预告 |
| 素材索引 | 三拍判据、切点 | 用到该集的 plan |
| 五幕 / 三拍方法论 | 所有段表的 beats | 定版用例 sd_005 v3（325.1s） |
| 装配脚本 | 所有切点与时长 | 定版用例 + 织入版（334.84s） |
| 角色资产 / 音色锚 | 全部已出织入片 | ASR 逐字比对 |
| 状态台账 / 本入口表 | 所有线的「下一步」 | 三测试 + `--stale-only` |

**任何改动从本入口登记**：改动方报「改了哪个产物、rev 从几到几」，由脚本传播，
不在下游技能里各自记一笔。这是「一个入口、更好测试调整」的落点。

## 门禁

| 门 | 位置 | 谁放行 |
|---|---|---|
| 选品 | 建包前 | 张老师（能做 / 不能做） |
| G0 | 剧集包 | 人审 |
| **选方向** | **方向卡（2–3 条故事线）** | **张老师圈定一条，没圈定不排段表** |
| G1 | plan.json 段表 | 人审 |
| G2 | 王婶织入片 | 台词人审 → dry-run → 出片 ASR 验收 |
| G3 | 装配成片 | 成片人审 |

> 「选方向」是 `script` 环节内部的第一道停，不新增流水线环节、不改脚本、不动已验收台账。
> **换了线就当新一条片子**：整张段表重排、成片重装配，不是改几段。

**出片是唯一花钱的环节**：台词未经人审、未跑 dry-run，不许提交。
