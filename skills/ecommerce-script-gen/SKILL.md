# ecommerce-script-gen

给一个轻食品类写一条 60 秒带货短视频脚本。产出两份：`{id}.json` + `{id}_拍摄执行单.md`。
**产物默认落当前工作目录**；调用方指定目录就落指定目录。

## 片子的两段式（记住这一条就够了）

```
0–15s  │ 钩子 · AI 生成
       │   冲突抓眼球，全部人物在这 15 秒出场；产品只当道具露脸
       │   不念卖点 / 数值 / 功效；人物出镜说对白（音画一体）
15–60s │ 混剪 + 旁白
       │   画面全是素材，人物不再出现
       │   证据 → 信任 → 价格 → 转化逼单
```

「创意」只指钩子这 15 秒。默认模式从元素库抽一句钩子；创意模式由用户给
`creative_brief`（人物 / 冲突 / 反转 / 产品道具 / 声音）。15 秒之后两种模式完全一样，
共用同一份产物、同一套合规红线。**别把创意铺成整片剧情。**

### 钩子是微剧情，不是三句话

80 字左右 / 10–15 秒，四拍跑完，缺一拍就没张力：

| 拍 | 干什么 | 例（真香） |
|---|---|---|
| ① 指责 | 有人挑刺，具体到物 | 上个月那罐还没开封，柜子全是你的瓶瓶罐罐 |
| ② 反抗 | 被挑的人不能软，要顶回去 | 我花自己的钱，好东西我就是要买，有本事你别吃 |
| ③ 赌气 | 把话说到绝处，给反转留空间 | 我不吃，一口都不碰 |
| ④ 打脸 | 换场景，用动作收，不用解释 | 自己抹第二片，被一句「你不是不吃吗」戳穿 |

- **冲突要显性**：双方都得开口，不能一个人骂、另一个人沉默
- **反转靠动作**：手伸过去、又抹一片，比台词有力
- **争执段语速可到 5 字/秒**（抢话本来就快），别按 3.8 硬压
- 钩子里不念数值、卖点、功效——那是混剪的事

## 第 0 步：先盘素材，再定结构

**画面从素材里长出来，不是写完文案再编画面。后半段能铺几段，由库存决定。**

```bash
Q=skills/ecommerce-asset-analysis/scripts/query.py
I=assets/{品类}/asset_index.json
python3 $Q $I --list                    # 有哪些文件、各多少镜头
python3 $Q $I --catalog assets/{品类}    # 人读目录，每镜头一行
python3 $Q $I --usage texture,hand --min-len 3 --limit 8   # 按条件取镜头
```

索引不存在 → 先跑 `ecommerce-asset-analysis` 技能；连原片都没有 → 出「素材采集清单」
（要什么镜头、几秒、用在哪段），按清单写，缺项标「待补」。**任何情况下都不许凭空编画面。**

**库存 → 能铺什么**（先数一眼，别硬凑）：

| 库存富余 | 能铺的段 | 例子（虎坚果酱实测） |
|---|---|---|
| origin 产地/田间/沙漠 | 溯源：原料哪来的、怎么收的 | 153 个，够铺两段 |
| hand 使用动作 | 吃法：抹 / 拌 / 蘸 / 空口 | 62 个 |
| texture 酱体质地 | 口感：舀起来什么状态、抹开什么样 | 37 个 |
| process 生产线/灌装 | 信任：怎么装进去的 | 35 个 |
| product 罐体标签配料表 | 依据：翻罐背、看配料、看克数 | 17 个，**少，别连用** |

某一类少就少写那段、靠口播补。**宁可段数少、每段实在，不要为凑结构硬塞。**

## 输入：品类包

读 `category-pack.json`。定位顺序：调用方给的路径 ＞ 当前工作目录 `packs/{品类}/`
＞ 云端「品类包/{品类}/」。找不到就问一句要哪个包，**不要自己编产品事实**。

| 读什么 | 怎么用 |
|---|---|
| `meta.review.human_review` | 不是 `passed` 就只出草稿 |
| `product_facts` | `verified && usable_in_copy && !blocking` 的 `value` 才进口播；`null` 用 `placeholder`，不编数字 |
| `selling_point_map` | `usable_rewrite` 是写作起点，`condition` 是前提，`status: blocked` 不用 |
| `compliance_ext` | 品类专属红线，动笔前扫一眼 |
| `elements` | 钩子 / 痛点 / 举证 / 信任 / 金句 / 转化，直接拿来用 |
| `pending` | `blocking` 项进执行单「待确认」，不进口播 |
| `asset_index` | 包里这块只登记状态；真实镜头走 `assets/{品类}/asset_index.json` + query.py（见第 0 步） |

其余字段（`conflicts`、发布标记等）不用管。

**语速档位**：抖音 4.5 / 视频号中老年 3.8 / 中年女性 4.1 / 给妈妈买 4.3 字/秒。
脚本顶层写 `speech_rate` 声明档位。视频号中老年钩子认人认事认场景（菜市场、遛弯、
配料表），转化走「让孩子们帮你看一眼」；中年女性钩子要「认出自己」，转化落在「允许自己」。

## 步骤

1. **定角度**：六型选一（人群切入 / 痛点命名 / 反常识 / 场景 / 算账 / 信任溯源）。
   换角度就是一条新脚本。`angle_type` 写清是什么即可，不用硬套枚举。
2. **定钩子**：默认从 `elements.hooks` / `pains` 挑本品实例；有 `creative_brief` 就按它
   写 15 秒钩子视频。冲突放第 1 秒，钩子段不举证，人物只在钩子出现。
   卖点过三自测：需要感 / 可信度 / 唯一性（竞品也能说的就是废话）。
3. **写口播 + 同时挂画面**：段 1 是钩子，其余按一条**讲述链**铺，总段数 ≤ 15，按语速控字数。
   钩子段 `shot_source: AI` 挂 `ai_shot_id`；混剪段一律「旁白」，人物不再出现。

   **混剪不是一句一个类型地贴标签。** 每句都要回答观众心里正在问的那句：
   钩子冒出的疑问（「这什么酱」）→ 是什么 → 凭什么 → 会不会又踩坑 → 还能怎么用 →
   值不值 → 该转给谁。写成一条人话；`section_role` 只是内部标记，不念出来。
   混剪与钩子弱相关即可，不必强行呼应，但**句与句之间要接得上**。

   **每个混剪段挂 1–3 个真实镜头**（`visuals`），写完口播立刻挂，别事后配图：
   `shot_id` 用 query.py 输出的（如 `C5396#0`），带 `in`/`out` 秒数。
   素材镜头普遍比需要的长（实测均值 13.5s、最长 85s），**一律写「取 X–Y 秒」，不要整段用**。
   60 秒片子混剪段 10–20 个镜头、平均 3–5 秒一个，别切成碎渣。

   **音画同步三条**（这是混剪不翻车的底线）：

   - 口播提名词 → 画面必须给到。说「罐背配料表」就必须是 product 特写，不能配航拍
   - 口播提动作 → 画面给动作。说「抹开」就必须有 hand/texture 镜头
   - 口播句的起点 ≈ 镜头入点。画面比话晚两秒，观众会觉得错位

   **反单调三条**（防止后半段像 PPT）：

   1. 相邻两个镜头的用途主类不能相同（连着三个罐子摆拍＝灾难）
   2. 连续 3 个镜头里至少 1 个是特写或近景
   3. 每 10 秒画面必须变一样东西：景别 / 主体 / 场景，三者至少变一个
      （素材库常只有一个场景，别硬求换场景；桌拍内部从罐体特写→舀酱→抹面包就已经在动了）

   缺画面：标 `missing: true` 并写替代（用哪类镜头顶），**不许编不存在的素材**。

   **钩子与混剪的衔接**：钩子最后一镜（餐桌/手/人脸）→ 混剪首镜头，用产品特写或同场景
   转场接住；不要从室内对话直接切到航拍沙漠。
4. **定 AI 结构**（和写口播一起做，别事后补）：默认**一条 15 秒**跑完钩子四拍，
   内部切 4 个分镜、正反打各露一人；≤ 2 条只在确需补产品特写时才用。
   定 `sound_plan`（双人对白 / 单人自述，是否留旁白）。
   **人物与场景引用资产库**：`character_ref` / `env_ref` 填 `ch_NNN` / `env_NNN`
   （双人写 `ch_001,ch_002`），用 `ecommerce-ai-assets` 的 registry.py 查库，
   没有合适角色就先建卡再回来写。
   **提示词与音色**：`prompt` 写满（参考图分工 + 分镜 + 台词 + 场景光线 + 约束），
   `prompts_pending: false`；台词不预生成音轨，传角色 `voice_ref_5s.mp3` 作音色参考。
   钩子里的人物可以当后半段解说（声音在、画面不在），比换一个人念更像回事。
5. **出两份产物**，格式见 `references/output-spec.md`。
6. **可选自查**：`python3 scripts/validate.py {id}.json` —— 只查 4 条硬红线（见下）。

## 合规（商家视角：卖点尽量用，只换风险谓语）

普通食品不碰：疾病功效、无依据虚假比较、无认证宣称（有机 / 农残 / 蓝帽子）、
虚假价格稀缺，外加过敏原反向宣称。**「保健品」三字永不进文案**，用「那些瓶瓶罐罐」指代。
身体改善类说法落到口感 / 方便 / 配料 / 数字 / 场景；厂商原话尽量保留，只去风险谓语，
**不要换成另一个不相干的卖点**（「饱腹感强」≠「一勺能抹满一片面包」）。
品类专属红线在包里，更细的口径见 `references/constraints.md`。

## 校验器只查 4 条

段数 ≤ 15 · `hook` 有且仅有段 1 · AI 镜头 ≤ 2 · 禁词命中。
其余（举证配额、角色轮换、语速、两段式、双人参考位）都是**写作时的常识提醒**，
不进机器检查——文案创作不靠校验器出好稿。

## 别做

不问预算、不算抽卡系数、不写成本推演（那是生成环节下游的事）；
不把方法论 / 准则全文抄进产物；产物体积要配得上这条视频本身的分量。
