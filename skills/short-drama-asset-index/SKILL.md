> 本技能只负责「把一部剧变成可检索的冲突段落库 + 锚点池」，不判断现在该不该做、做完该接谁。

# short-drama-asset-index · 短剧素材段落索引

## 为什么不复用轻食版

按行业纵切、不硬合并（11-08 张老师拍板）。轻食版打的是**镜头级**标签
（主体 / 景别 / 画面文字 / 可用用途），给文案选商品画面用。
短剧要的是**能不能拿来做钩子和插解说**，标签族完全不同。

**实测依据**：《八零憨妻》第 1 集 132.9 秒，场景检测得 **54 个镜头**，平均 2.5 秒一切。
短剧自带快切，镜头级索引会产出约 1000 条记录，文案一条也用不上。
→ 本技能的单位是 **conflict_segment（冲突段落）**，一段含若干台词、一个可截断点。

## 核心判断：按集剪不成立，按「主题 + 临界点」剪才成立

（11-08 张老师定，依据见 `docs/短剧技能链磨合记录.md` 第 6 环）

| 旧做法 | 为什么废 | 现行做法 |
|---|---|---|
| 一集对一集出片 | 一集 37–133 秒，凑不满「钩子→递进→截断」三段；顺着发等于替平台把免费集放完 | 从 3–4 集**各取 1 个临界点**，用一个「看法」串起来 |
| 拎「爽点/名场面」当锚 | 把最解气那场放完，等于替观众把爽感兑现完，他反而不点组件 | 锚点是「**结果还没出现**」那一瞬（临界），不是打脸完成的爽点 |
| 靠换剧制造差异 | 只有一部剧，换不了 | 靠**换「谁在看、怎么评」**做区隔（视角 × 主题） |

**「高光 ≠ 已兑现的爽点」是这套索引最值钱的一条。** 所以每段必须判 `critical_state`。

## 输入输出

| 项 | 说明 |
|---|---|
| 输入 | `.env` 的 `SHORT_DRAMA_ASSET_ROOT/<剧名>/`，按集视频 |
| 中间产物 | `lines/lines_epNN.json` —— **台词文字唯一真源**（内嵌硬字幕 OCR，509 句 / 19 集，带秒）。索引与骨架只存时间码，不复制文字；改台词只改这里（2026-11-10 起） |
| 输出 | `asset_index.json`（机读真源，v2.1）+ `素材台账.md`（人看，由 JSON 渲染） |
| 覆盖 | **只做前 60% 集数**（`ceil(总集数 × 0.6)`，且去掉大结局）；预告实际取用范围更小时，按小的来。见下「不剧透铁律」 |
| 台词 | 文字只存 `lines/lines_epNN.json`；索引与骨架只留时间码 `line_times`（2026-11-10 起，见 `lines_ref`） |

沿用两条既有约定：**只读原片零修改**、**明细不进剧包**（包里只登记状态与路径）。

## 查询入口（2026-11-11 加，排清单前必用）

索引落盘后，找句子、对画面**不许再手翻 JSON**，走查询入口（内部查 SQLite 缓存）：

```bash
# 建缓存（JSON 是唯一真源，库只是派生缓存，可随时删掉重建，全量 < 4 秒）
python3 scripts/build_index.py --drama <剧名>     # 产物 <素材目录>/index.sqlite

# 查询：关键词子串（逗号分隔任一命中）、限定人物/集数/时间范围、带上下文
python3 scripts/query.py --drama <剧名> --kw 我们没妈,保安 --ctx 3
python3 scripts/query.py --drama <剧名> --who 许晴 --ep 11 --from 0 --to 15
```

- 返回列：集 | 台词起始秒 | 台词 | 覆盖该秒的镜头（起止/景别）| 画面上的人（按 char_map 规则反推）。
- 人物是机器反推，「分不清」不是错误——那是给人审的。
- 两条纪律：①缓存永不被手工编辑，不放心就重建；②台词唯一真源仍是 `lines/lines_epNN.json`，库里不存第二份文字真源。
- 预留位：库里有空表 `vectors`（BGE 等语义检索参数位），**当前恒不启用**。触发条件：台词库跨剧超 3000 条、或出现真实的"按语义找段落"需求。届时加一个嵌入脚本填表即可，查询接口不改。
- 实测（2026-11-11，以真心守护至亲 552 句 / 288 镜头）：建缓存 3.5 秒；13 段清单所需的全部查询 1.07 秒。

## 不剧透铁律：只解析前 60%（2026-11-11 张老师定）

**整部剧只解析前 60% 集数，后 40% 一集都不碰。** 不是省算力，是方法：

1. **预告本来就不该含结局。** 后 40% 的素材本来就是「不许用」的，解析它等于为废弃素材付费。
2. **不知道结局的人写出的悬念才是真的。** 解析了后面，写悬念时会不自觉地往「其实后面没这么严重」偏。
3. **成本**：60 集全跑台词识别约 75 分钟；选片是漏斗第一道，不可能每部剧都全量解析。

口径：`覆盖上限 = ceil(总集数 × 0.6)`，再去掉大结局那一集。
实际按预告取用范围可以更少（例如《以真心守护至亲》60 集，上限 36 集，但家庭伦理线只到第 19 集，就只做 1–19）。

**后 40% 只在剧包里留一句走向，不带集号、不带台词、不参与分幕。** 见 `short-drama-pack` 铁律 1 的 v1.2 补充。

> **旧口径（已被取代，保留）**：`覆盖 1–19 集；第 20 集/大结局一律排除`——
> 那是《八零憨妻》只有 20 集时的写法，把「集数」和「60%」混成同一个数了。换剧就失效。

## 四层产出（别一步到位做全量）

| 层 | 做法 | 成本 | 现在做到哪 |
|---|---|---|---|
| L1 骨架 | `segment.py` 按台词间隔/段长机械切段 | 全量、秒级 | ✅ 19 集 97 段 |
| L2 语义 | 逐段判读：临界状态 / 主题 / 视角 / 强度 | 全量、人工判读 | ✅ 97 段，45 锚点 |
| L3 边界帧 | 每段**头尾各一帧**（97×2=194 帧）→ `space` / `exit_type` | 全量但只两帧，**一次性** | ✅ **已完成**（11-08 实跑）：19 集 / 97 段 / 194 帧，`manifest.json` 97 条，space 97/97、exit_type 97/97 全填；只有换剧或段落边界改了才重跑 |
| **L3′ 镜头打标** | `tag_shots.py`：每镜头一帧 → VLM 只描述不认人（见下节） | 约 2–3.4 万 tokens/集，**一次性** | 2026-11-11 新增。取代「人看边界拼图」；单集实测通过，批量跑中 |
| L4 锚点精验 | 只对入选锚点逐段看几帧 → 精确截断点 / `visual` | 每条片子约 20 帧 | ⬜ 写执行单时做（97 段 `visual_pending: true`，确实未做） |

**L3 与 L4 的分界是「常量 vs 变量」**（11-08 张老师追问「什么时候 VLM」后定）：

- 出口类型是**整部剧的常量**。第 1 条片子和第 20 条片子判的是同一个「玉米地结尾」，
  所以现在一次算完，后面每条片子直接引用，不用回头再看。
- 精确截断是**每条片子的变量**。同一段素材，「委屈」那条卡 8.2 秒，「婆婆心软」那条卡 9.5 秒。

判据一句话：**跟你要做几条片子无关的，现在做；跟片子有关的，写执行单时做。**

这是从旧影视解说项目学来后**反过来用**的一条：旧项目是「全量 VLM 标注 + 事后治理」，
1589 场戏 460–1150 次调用。短剧按整段盲看约 500 帧；改成「文本粗筛 + 边界帧常量扫描 + 锚点局部精验」
后是 194 + 24×5 ≈ 314 帧，**其中 194 帧只付一次**。
**因为我们要的不是准确还原剧情，是可剪性。**

## 画面打标：AI 先识别，人只审错（2026-11-11 定）

脚本 `scripts/tag_shots.py`（短剧独有，不与 `ecommerce-asset-analysis` 共用一行代码——一套行业一套技能）。

**定位：VLM 只描述画面，不认人。** 短剧演员无名无参考照，让模型认人只会更不准（11-08 定，11-11 复核仍然成立）。
模型输出「老年女性 深色旧棉袄 坐轮椅」这种**特征串**，人名映射由规则反推（服装/年龄/出场顺序），人只看一遍映射对不对。

**为什么不让人肉从零看**：人的时间最贵。正确分工是 AI 出草稿、人审错——不是人从零做一遍。
（11-11 我一度写了「人看 24 张拼图」，被张老师一句「怎么还安排上人看了」推翻。）

**流程**：场景检测切镜头（`scene>0.25`）→ 每镜头抽**中间帧**、缩到 640px → 每 6 帧一次调用 → `shots/shots_epNN.json`。

**字段**（全是短剧要的，与商品字段无交集）：`shot_size` / `people` / `who`（特征串数组）/ `action` / `place` / `props` / `scene_text` / `watermark`。

**两条硬规矩**：

1. **判黑场必须用亮度数值**（`cv2` 均值 < 10 才算黑场），不认模型说的「画面昏暗」——
   实测第 1 集开场 0–7 秒模型报「昏暗模糊」，实测亮度 40–85，是暗调打光不是黑场。
2. **抽帧密了才不漏**。同一部剧，5 秒一帧、缩 120px 做全剧扫描，**整把纯金色轮椅被漏掉**；
   每镜头一帧就标出了「金条货架」。密度不够＝等于没扫。

**实测能力边界（以真心守护至亲 第 1、5 集）**：

| 能做 | 不能做 |
|---|---|
| 道具（轮椅 / 金条货架 / 麦克风 / 红毯 / 高脚杯） | **判断谁在说话**（短剧大量听者反应镜头，切点≠说话人） |
| 靠服装区分同性别角色（白色蕾丝婚纱 vs 浅粉连衣裙） | 判断情感强度（能标「含泪」，标不出多委屈） |
| 景别 / 人数 / 动作 / 场景 | 判断是不是黑场（要靠数值） |
| 水印位置与文字 | 认人（不做，也不该做） |

**「谁在说话」判不出来要不要紧：不要紧。** 纯剪预告原声画面一起走，观众自己听得见。
只有重新配字幕、或把甲的声音接到乙的画面上才需要——这两样纯剪预告都不做。

**成本**：每集约 2 万–3.4 万 tokens（1 集 99 秒 32 镜头 = 34,063；5 集 57 秒 19 镜头 = 19,218）。

## 字段契约

### 每段必填（L1+L2）

| 字段 | 用途 |
|---|---|
| `id` / `ep` / `start` / `end` / `duration` | 段落定位，时间码必须能回到「第几集 + 秒」 |
| `line_times[]` | 本段由哪几句台词组成，**只存秒数**；文字按秒去 `lines/lines_epNN.json` 取（唯一真源）。2026-11-10 起不再把台词文字复制进索引 |
| `conflict.type` / `intensity` | 冲突类型与 1–5 强度 |
| **`critical_state`** | `临界` / `已兑现` / `铺垫` —— 决定这段能不能做钩子 |
| **`themes[]`** | 归属的跨集主题（T1…T8），栏目单元的最小单位 |
| `viewpoint` | 这一段是谁的视角（谁在看、谁在忍、谁在护） |
| `characters[]` | 台词涉及谁。**只回答「王婶这会儿看见的是谁在干什么」**（她只评自己看见的事）；**不再承担合规职责**，理由见下节 |
| **`space`**（L3） | 这段发生在哪：堂屋 / 院子 / 门口 / 田里 / 路上 —— 决定扩出去是「隔壁院」还是「路对面」 |
| **`exit_type`**（L3） | 出口形态，四类见下节 —— 决定这段**从哪儿切得出去** |

### 锚点额外字段

| 字段 | 用途 |
|---|---|
| **`anchor_role`** | `hook`（临界，做钩子/截断）或 `payoff`（已兑现，做举证/收束） |
| `anchor_note` | 一句话说清为什么这段值钱（写执行单时直接用） |
| `visual` | 一句画面描述；**未核验时恒为 null + `visual_pending: true`，不猜** |

### 主题定义（THEMES，8 条）

主题 = **能用一个「看法」把 3–4 个不相邻的画面串起来，且不依赖剧情顺序**。
每个主题带一句 `voice`（王婶的开口方式），写文案时直接可当第一句。

当前 8 个：T1 门槛 / T2 傻子的帽子 / T3 借米不还 / T4 力气换来的位置 /
T5 婆婆心软的三次 / T6 一碗粥的往返 / T7 旧账上门 / T8 从陪嫁到陪嫁。

`enough_for_one_episode` 判据：**锚点 ≥3 且跨 ≥2 集**。不达标就标 `⚠️ 只当段落用`，
不要为了凑数把铺垫段升成锚点。

## 出口与插入策略（11-08 张老师纠正后定）

**先记一条被推翻的判断**：上一版把 `characters` 当合规红线，理由是「王婶不得与剧中人同框」。
这是**把剪辑接口问题误当合规问题**。王婶的镜头是我们自己 AI 生成的，原片里根本没有这个人，
「同框」从源头不存在。真正要判的是**从哪个位置切出去**。

### 出口五类（`exit_type`，L3 边界帧判）

> **2026-11-10 口径**：`space` / `exit_type` 这两项**现在仍要判**，纯剪也要知道这段
> 切不切得出去、和下一场能不能接上。但本节里凡是「扩到王婶」「切到王婶」的解说属于
> 11-08 旧做法，只作历史解释保留；**不要据此去生成或插入王婶镜头**。

| 值 | 画面特征 | 好不好扩 |
|---|---|---|
| `人出画` | 背影、出门、走过田埂、转身离去 | ✅ 最顺，方向和视线都在画面里 |
| `边界物` | 门口、窗、路口、墙头、田埂本身出现在画面 | ✅ 天然是相邻空间的入口 |
| `自顾` | 单人在画面内做自己的事（劈柴、薅草、纳鞋底） | ✅ 切到王婶做同类的事，同一片田野里最自然 |
| `空镜` | 无人无主体：天、地、墙面、关上的门 | ⭕ 最自由，但没给方向，衔接要自己造 |
| `锁空间` | 正反打、双人对话、面部特写 | ❌ 空间锁死在两人之间，切出去就断 |

> 第五类 `自顾` 是 11-08 实跑补的：ep01 p06 是「一个人蹲在田里干活」，没走（非人出画）、
> 画面无门路口（非边界物）、也不是对话（非锁空间），却恰是最理想的二扩点。
> **枚举靠实跑校准，写死的枚举要允许扩展并登记。**

**97 段实测分布**：人出画 14 · 边界物 13 · 自顾 8 · 空镜 2 · **锁空间 60（62%）**。
→ **可二扩只有 37 段（38%）**。所以四个插入策略是**组合，不是四选一**：
剩下 62% 只能走段前立人和画外音插话。设计时若只做二扩，第一条片子就会卡住。

**「玉米地」例子同时命中前两类**：人在往画外走 + 田埂本身就是边界 → 旁边一人抬头看，镜头一切就成立。
**这种切法不需要原片提供空镜**，这是孪生解说相对「借素材混剪」的一个硬优势。

### 插入策略四类（`insert_mode`，写执行单时定）

> **⚠️ 历史做法，已被取代（2026-11-10 标注，原文照留）**：以下两节（插入策略四类、
> 顺序不能反）是 11-08「王婶在旁边接话」那套形态的规则。现在预告片主体是**纯剪**，
> 默认不生成任何 AI 人物镜头；王婶只是 AI 玩法菜单里的一道菜，须由选题单点选才启用。
> 新会话**不要照这两节排插入位**。数据侧对应字段见 `asset_index.json` 的 `legacy_fields`。

| 值 | 位置 | 适用 | 风险 |
|---|---|---|---|
| `开头立人` | 0–3 秒，原片之前 | 原片还没建立空间，王婶先说最容易被接受；新号让观众认人 | 低 |
| `中间插话` | 原片某句台词之后 | 最像「邻居在旁边忍不住说一句」 | 高：打断连贯镜头 |
| `场景二扩` | 段落后，扩一个相邻空间 | 最自然，**跨集拼接能顺下去的关键** | 中：要接得住出画方向 |
| `结尾收束` | 末 3–5 秒回一句 | 留钩子 | 中：容易写成预告，踩任务第 3 条 |

### 顺序不能反

`insert_mode` **依赖** `exit_type`：先知道这段切不切得出去，再说王婶站哪儿。
反过来先定「我要在开头插」再去找素材，只会逼着把「锁空间」的段硬切开。

## 工序

1. **抽台词时间轴**：内嵌硬字幕 OCR（`extract_lines.py`），按集增量、中断可续。
2. **验切分密度**：换剧先场景检测数镜头，确认「段落级」单位仍成立。
3. **机械切段**：`segment.py`，段长落 12–26 秒；段间不重叠；短段标 `head_from_zero` / `tail_to_end`。
4. **逐段判读**：`label_anchor_pool.py` 里的 `L` 表，一段一行，**人工判读不生成**。
5. **出主题覆盖表**：看哪些主题够撑一条片子，哪些只能当段落。这一步决定产能，不靠估。
6. **边界帧扫描**（L3）：`edge_frames.py` 每段取 `start+0.5s` 与 `end-0.5s` 各一帧，
   拼 9 宫格，一次看完打 `space` / `exit_type`；判不准的标 `pending`，**不猜**。
   > 本剧 11-08 已跑完并入库：97 段全部 `edge_verified: true`，space 97/97，
   > exit_type 分布＝锁空间 60 / 人出画 14 / 边界物 13 / 自顾 8 / 空镜 2，
   > 画面 194 张落在 `edge_frames/frames/`，清单 `edge_frames/manifest.json` 97 条。
   > 历史表格曾写「待跑」，**别再重扫一遍**；只有换剧或段落边界改了才重跑。
7. **渲染台账**：`render_ledger.py`，JSON 为源、md 为视图。
8. **锚点精验**（L4）：**写执行单时才做**，只对入选的 3–4 段逐段看几帧，定精确截断点与 `visual`。

> 产能意义：瓶颈从「看片」前移到「选段」，而选段的依据是主题够不够料 ——
> 这比「一天能剪几条」更早、更能预判。

## 边界与红线

- **不判断商业值不值得做**（选片层的事），不写解说词（文案层的事），不生成画面（视频层的事）。
- 台词与画面描述**不得编造**：每句要能回到集数与秒；不确定就留 `pending`，不猜。
- **台词文字只存一处**（2026-11-10 张老师定）：`lines/` 是唯一真源；`asset_index.json`、
  `segments_skeleton.json` 只存 `line_times`，台账等视图渲染时按秒去取，不另抄一份。
  补句后要把秒数补进对应段的 `line_times`——`render_ledger.py` 会打印「未归入任何段落」的提醒。
- **说话人 `speakers` 留空**：字幕只有文字，给不出「谁在说、什么语气、有没有被打断」。
  这三样恰恰是判「临界」最要紧的，需要音频侧补（ASR / 说话人分离）。**不要用字幕硬猜说话人。**
- 不碰大结局、不剧透后续；不把别剧剧情混进来（八零题材同名剧极多，外部搜索会污染）。
- 技能与文档内**不写本机绝对路径**，素材根一律走 `.env`。
