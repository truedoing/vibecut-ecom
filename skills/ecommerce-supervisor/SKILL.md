# 我是这条产线的唯一入口

下游 8 个技能全都写着自己的「何时使用」，Agent 一眼看去**个个都像入口**——用户说「合成一下」，
直冲 `ecommerce-video-gen` 的风险是真实存在的。所以：**用户任何一句话先过这里，由我决定调谁。**

| 用户想干什么 | 我调谁 | 到哪停 |
|---|---|---|
| 建/改一个品类包 | `ecommerce-category-pack` | G0 人审 |
| 分析商家素材、建索引 | `ecommerce-asset-analysis` | 索引落盘 |
| 建角色/环境/锚资产 | `ecommerce-ai-assets` | 卡 validate 过 |
| 出钩子创意 / 写脚本 | `ecommerce-script-gen` | G1 出片前 |
| 出片（花钱） | `ecommerce-video-gen` | G2 钩子人审 |
| 从钩子提本片音锚 | `ecommerce-voice-anchor` | report.json 过 |
| 出旁白 | `ecommerce-narration` | 指标达标 |
| 混剪成片 | `ecommerce-mix` | G3 成片人审 |

这 8 个技能都被要求在自己的 SKILL.md 首段写明「本技能不是入口」。**我不替代它们的专业判断，
我只负责：什么时候轮到谁、给谁什么输入、到哪必须停、停完谁来接。**

**产线不止一条（2026-11-08 起）**：`状态.json` 的 `line` 字段决定走哪套流水线，
缺省或 `light-food` 走上面 8 个技能；`short-drama` 走短剧二创线：

| 短剧这一步 | 调谁 | 到哪停 |
|---|---|---|
| 建剧集包 | `short-drama-pack` | G0 人审 |
| 建孪生解说角色 | `ecommerce-ai-assets`（角色卡） | 人物卡人审 |
| 抽帧/台词索引 | `short-drama-asset-index`（11-08 已拆，按冲突段落建库） | 索引落盘，形态人审 |
| 文案 / AI 出镜 / 旁白 / 混剪 | 短剧专属技能**未建**，暂由执行单承载 | 逐段人审 |

**第一节「开工三问」是轻食专属**（single_hook / 六型角度 / 批数）。短剧线改问：
① 解说形态（原生段与解说段如何交替、孪生角色出镜几段）② 钩子结构与本批唯一变量
③ 本批条数。**别拿六型角度去问短剧**——那是商品带货的角度库。

## 开工第 0 步：环境自检（只在我这里做一次）

```bash
python3 skills/ecommerce-supervisor/scripts/check_env.py
```

查 python / ffmpeg / numpy / 密钥 / packs / **所有 `*_ASSET_ROOT`**，缺什么直接打印修法
（Windows `winget install Gyan.FFmpeg`，Mac `brew install ffmpeg`）。

**这是入口职责，个体技能一律不写「前置依赖」。** 这条线要升级成专家——全局判断
（环境检查、入口路由、门禁、状态台账）必须收在入口一处，改一处即全局生效；
撒进个体技能，升专家时就得逐个收割，收割不掉的就成了孤儿规则。

**建新品类必须同时登记素材根目录**：`ASSET_ROOT=<本机素材目录>` 写进仓库根 `.env`。
素材目录是**环境**不是知识——不进品类包（包只放索引），check_env 检查它存在且有效。
别人安装技能后跑不起来，八成是这一项没填。

**每条产线各有自己的素材根**（11-08 起）：轻食 `ASSET_ROOT`、短剧
`SHORT_DRAMA_ASSET_ROOT=<短剧素材目录>`（本机实际值只写在仓库根 `.env`，
**技能文档不写死绝对路径**）。check_env 会逐个检查所有 `*_ASSET_ROOT`，
不再只认单值。新增产线照 `<LINE>_ASSET_ROOT` 命名即可，**不用改脚本**。

# 一、开工前必须问清的三件事

顺序不能乱，**第一个答案决定后面全部**：

1. **结构**：`single_hook`（单钩子）还是 `hook_plus_convert`（主副双塔）。
   不静默默认——它决定要不要多一条 AI 副视频（约 2 元）、转化段怎么写、旁白怎么分段、
   混剪要不要接 `--tail`。写进 `状态.json` 当第一个 artifact（`structure`，无 depends_on），
   脚本及以下全部 `depends_on` 它。
2. **角度**：六型（人群切入 / 痛点命名 / 反常识 / 场景 / 算账 / 信任溯源）里选，且**查重**——
   先读 `runs/*/状态.json` 找同类片的 `angle_type`，别同型连发。
3. **线数**：这一批跑几条（并发见第五节）。一条线也要问，因为成本闸门按批报。

**别在开工时问预算**。预算在 G1 报（出片前那一刻），且只报「这一步要花多少、失败要重花多少」。

# 二、状态台账：唯一真源是文件，不是记忆

```
runs/{品类}/{task}/状态.json     ← 每条片子一份
```

模板见 `references/状态模板.json`。五个值，判据写死：

| 值 | 判据 | 谁能依赖 |
|---|---|---|
| `draft` | 产物在，自检没跑 | 只有写它的技能 |
| `ready` | 自检 0E，人还没判 | 机器能用，**人不能依赖** |
| `approved` | 人说过一句明确的话 | 全链路可用 |
| `blocked` | 缺上游 / 有 blocking 冲突 / 缺关键事实 | 谁都不能用，**必须写清卡在谁** |
| `stale` | `depends_on` 的上游 rev 变了 | 谁都不能用，必须重跑 |

**两个字段撑住整套机制**：

- `depends_on`：失效自动传播。钩子重出（rev+1）→ 片内锚 stale → 旁白 stale → 成片 stale。
  一条链自动标完，**不靠谁记得**。
- `evidence`：迁移的唯一凭证。**没有证据不迁状态**——这条堵的就是「我说做完了」。

**各阶段的最小证据**（缺一条不算过）：

| artifact | 证据 |
|---|---|
| `structure` | 用户一句话选了哪个 |
| `pack` | validate_pack 0E/0W + G0 人审 + 上传记录 |
| `asset_index` | 视频数/镜头数 + 台账生成时间 |
| `script` | validate 0E + `prompt_lint` 0E + 角度查重结论 |
| `hook_AI{n}` | mp4 + 抽帧联系表 + ASR 转录 + 指标表 + **人一句「可以」** |
| `anchor`（片内锚） | report.json 指标 + 采样段位置 |
| `narration` | 时长/字每秒/LUFS/峰值 四项 |
| `final_mix` | 总时长 + LUFS/TP + 音视频同长（差 <0.1s） |

**谁写谁不写**：技能只做两件事——注册自己的产物、标初始状态（`draft`/`ready`）。
**技能绝不许改 `task.status`**（那是给看板用的进度轴），也绝不许把别人的 artifact 改成 `approved`。

**总台账现算，不建第二份**：要一张全景就扫 `runs/*/*/状态.json` 现场算，
不维护 `台账.json`——第二份真源迟早过期。等扫一次超过几秒再谈升级。

`status_overview.py` 按 `line` 分派流水线（11-08 适配短剧）：
`script_inputs` 声明 script 开工前必须就绪的品类级资产（短剧为素材索引）——
**人审门禁（gate）与开工依赖（script_inputs）是两个维度，别混**。
`--line short-drama` 只看短剧线，`--detail` 展开 G0 品类级资产证据。
短剧模板是 `references/状态模板_短剧.json`；**旧状态文件没有 line 时一律按 light-food 算**，
不用回填、不会报错。

# 三、四个门禁：按成本放，不按阶段放

出片一次约 3 元且决定后面全部 → 出片前必须停；混剪零成本可重跑 → **混剪中途不许停**（停了就试不出十版）。

| 门 | 位置 | 停前必须备齐（一次给全，别挤牙膏） |
|---|---|---|
| **G0** | 品类包落地前 | pack 校验结果 + 冲突清单（多来源不一致的原始值）+ 人审问题列表 |
| **G1** | 提交出片前 | 提示词定稿 + `prompt_lint` 0E + dry-run 请求体（参考图/参考音频/分辨率/时长/花费）+ 失败重花多少 |
| **G2** | 钩子出完 | 成片 + 8 帧抽帧联系表 + ASR 逐字稿 + 指标表（时长/分辨率/语速/停顿） |
| **G3** | 成片合成后 | 成片 + 切点抽帧 + LUFS/TP + 与上一版的 diff（改了什么） |

其余全部自动通过。**门禁不是给人添麻烦，是把「只有人眼看得见」的判断留在人手里**
（五官崩脸、第三人闪入、标签变实、口型错位、情绪劈叉）。

**G0 在短剧线是组合门禁**（11-08 定）：`pack` 人审 **+** `g0_category_assets` 里
`gate: hard` 的品类资产全部 `approved`，才算过门。当前硬卡只有**孪生解说人物卡**——
没有角色就没有解说段。`gate: soft` 的抽帧索引、孪生场景只显示不拦下一步，并带 `due`
（第 3 条前 / W2 融入前）。理由：把可延后项设成硬卡，会把第一条试水盘直接拖死。

# 四、调度循环（一条线也走，多线更是靠它）

```
1. 扫 runs/*/*/状态.json（现算）
2. 逐条线推「下一步」：
     - 有 stale/blocked → 优先解，写清卡点，不动手
     - 下游依赖已 approved 且自己 draft/缺失 → 这一拍可走
3. 可走的一拍里再分两类（见第五节）：
     - 远端异步（出片）→ 全部并行，后台提交
     - 本地吃 CPU（混剪/抽帧）→ 排队，一条一条来
4. 跑到下一个门禁就停，把**所有线的停点汇成一张清单**（不是每条线各问一次）
5. 人一次批完 → 各线同时继续
```

**汇报格式固定三句**：演到哪（最后一个 approved 是谁）／卡在哪（blocked 卡谁、stale 因谁）／
下一步的选项（最多两个，各带代价）。**不写长篇过程流水账。**

# 五、并发策略：机器并行，人审排队

并发的瓶颈不是算力，是**人审带宽**——3 条线并行 = 你要同时审 3 个钩子。所以：

- **出片（远端 API）全额并行**：Seedance 是网络等待（实测 157s/条），N 条并行总耗时不变、
  产出 ×N。后台提交、各写各的 `-o` 路径、各拿各的 task_id，互不干扰。
- **混剪（本地 CPU）排队串行**：ffmpeg 并行会争核心，2–3 路互相拖慢，总吞吐反降。
  一条 3 分钟，排队就好。
- **成本闸门按批报一次**：「这一批 3 条 × 3 元 = 9 元，失败重花同样」——批量批准，不逐条骚扰。
- **片内锚天然支持并发**：每条线从自己的钩子提锚，不共享资源、不抢嗓子。
- **等待窗口预做后手**（单片提效的大头）：出片 157s 里同步做掉这些不依赖结果的事——
  ①旁白文本先写好（只依赖钩子过审，不依赖出片结果）②`segs` 骨架按分句预算好
  ③抽帧命令与 ASR 命令备好 ④`状态.json` 先写好 `hook` 的 `draft` 条目。
  钩子一到、人审一过，直接全速跑，零准备。
- **草稿用快档**：审结构阶段 `preset fast`，定稿再 `medium` 重渲——混剪零成本，重跑随意。

# 六、效率账：机器只占 6 分钟，24 分钟在等人

实测一条 15s 钩子 + 30s 混剪的片子（T2_006）：

| 段 | 耗时 | 性质 |
|---|---|---|
| 出片 | 157s | 远端，可并行 |
| 旁白 | ~15s | 机器 |
| 混剪 | ~3min | 本地 CPU，可排队 |
| 抽帧+ASR+指标 | ~1min | 机器 |
| 四个门禁等人 + 每步往返 | **~24min** | 人 |

所以提效只有三条路，**别去优化那 6 分钟**：
① 停点打包（一次给全材料，减少往返轮次）
② 等待窗口预做后手（把串行变重叠）
③ 多线并发（把等人的时间摊到 N 条片上）
**创作时间不许砍**——角度、钩子、心理动线是质量所在，省下来的是废片。

## 耗时台账（2026-11-06 起，每条线必记）

每个 `runs/{品类}/{task}/耗时.md`，一行 = 一段「指令 → 产物落盘」：

| 列 | 填法 |
|---|---|
| 阶段 | 用人话：写全片 / 提示词 / 出片 / 混剪 |
| 起 · 止 · 用时 | 只写有证据的（文件 mtime、task_id、消息时间）；估的加 `~` |
| 性质 | **M** 机器等待（出片/TTS/转码）· **W** 生成与工具（写稿/校验/抽帧）· **H** 人等（门禁/挑候选） |

**为什么按这三分**：提效只能动 M 和 W，H 要靠「停点打包」和「批处理」压；混在一起就分不清
是流程慢还是人慢。每次报进度时附一句「本轮 M/W/H」，不要写总时长糊过去。
回溯记录允许估算，但要标 `~`——**台账的价值在趋势，不在精确到秒**。

# 七、常见修补（都是真踩过的，见到就修）

| 症状 | 修法 |
|---|---|
| 提示词台词与脚本台词不一致 | **以实拍为准回写脚本**，`content_note` 记翻案原因，复跑 validate |
| 素材文件找不到 | 索引 ≠ 本体：素材本体在 `ASSET_ROOT`（建品类时登记进 .env），`segs.src` 填该目录下的绝对路径 |
| 镜头组数对不上句数 | `align_bounds` 的实测句数才是准的（分句会合并短句），按它给 `--shots` |
| 解说音色与钩子不像 | 用了跨片旧锚：钩子过审后先跑 `ecommerce-voice-anchor` 提**本片锚**，`narration.py --sample` 指进去，情绪档跟随钩子弧线 |
| 成片尾部多出静音黑尾 | `mix_final` 的 `-shortest` 在 filter_complex 下失效，已改 `-t total`（2026-11-06 修复） |
| 供给器报「已用格子：无记录」 | 老脚本丢失导致查重瞎了：人工翻台账避开已用原型，并在 evidence 里记一笔 |
| 状态 `ready` 被下游当 `approved` 用 | 证据不足：`ready` 只表示机器自检过，人没点头不许往下走 |

# 八、阶段图（两层、两个节奏，别混）

```
品类级（一个品类做一次，低频高杠杆，审得严）
  category-pack ──> asset_index ──> 角色/环境资产 ──> 片内锚（每片，属片子级）

片子级（每条片子做一次，单条错代价有限）
  structure ──> script ──[G1]──> hook_AI ──[G2]──> narration ──> final_mix ──[G3]
                                   └──> voice-anchor（片内锚）
```

**注意它不是严格 DAG**：`narration` 和 `final_mix` 都回读 `script`（跳过 `hook` 的画面）；
`voice-anchor` 的输入不是 mp4，而是**「钩子过人审」这个人的判断**——
**人的结论是技能之间的一种输入类型**，所以门禁不能省。

**短剧二创线（`line: short-drama`）**：

```
品类级（一部剧/一个角色做一次）
  剧集包 ──> 抽帧·台词索引 ──> 孪生解说人物卡 ──> 孪生场景参考图
                                    └── 跨剧复用，不进任何剧集包

片子级（每条片子）
  structure(原生/解说交替) ──> script(执行单) ──> 孪生解说段(AI出镜)
       ──> 音色锚 ──> 解说旁白 ──> final_mix ──[G3]
```

片级七段**键名沿用轻食**（`hook_AI1_v1` 在这里是「王婶出镜的解说段」），
语义差异写在 `status_overview.py` 的 `stage_labels` 与模板 `_note` 里，
**不改键名**——下游短剧技能还没建，现在改名只会让已有状态文件失真。
品类级资产放 `g0_category_assets`，**不占片级 stage 位**（11-06 实测：挂进去
每条线都误报「待人审 asset_index」），由扫描器单独汇总并参与 G0 判断。

# 九、别做

1. **不做工作流引擎**。这仓库 48 小时翻过三次案（MiMo→豆包→回 MiMo、A 方案推翻、单钩升双塔）。
   写死的阶段顺序三周后就是阻力。**只固化「有哪些状态 + 什么证据能迁移」，不固化「先做什么」。**
2. **不建第三套记录系统**。素材、版本、花费归台账；状态归 `状态.json`；别的都不许新开一份。
3. **不让技能自己改 `task.status`**。技能只注册 + 标初始状态，流转是人或我的事，否则跟团队看板打架。
4. **不为了效率拆门禁**。要省时间就省往返、省串行，不省人眼。
5. **不在 `prompt_lint` 有 E 时提交出片**。3 元一次的门票，写提示词的人自己先关门。
6. **不凭记忆挑镜头**。挂画面前必须跑 `query.py`（`--kw` / `--usage` / `--category`），
   否则永远只用熟悉的十几个镜头，200+ 镜池等于白建。

# 十、新会话恢复现场（三句话内接上）

1. `ls -lT runs/*/*/状态.json` 看哪些线在动（先看时间戳，别猜）
2. 读对应 `状态.json` → 报「演到哪 / 卡在哪 / 上一版为什么被打回」
3. 给两个选项：继续下一拍（带代价），或先修卡点（带修法）

**接得上 = 骨架对了；接不上 = 缺的是证据字段，不是流程引擎。**
