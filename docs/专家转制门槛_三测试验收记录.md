### 偏差 1（T3）：是机制缺失，不是没跑

`status_overview.py` 全文搜 `rev`，只命中三处：198 行注释、145 行 `pending_review` 函数名、
203 行 `pend = pending_review(...)`。**没有任何 rev 读取或比对逻辑**。`stale` 完全来自
`状态.json` 里静态写死的 state 字段——`blockers()` 第 140 行只判 `a.get("state") == "stale"`。

SKILL.md 第 98 行承诺「`depends_on`：失效自动传播…一条链自动标完，**不靠谁记得**」，
实际未实现：11-09 台账里那句「上游 script rev 3→4，按规则自动标 stale」是人工写进
evidence 的，不是脚本算出来的。

复现方法（零风险，业务文件未动）：复制 `状态.json` 到 `/tmp/three_test/A`、`/tmp/three_test/B`，
仅把 B 的 `artifacts.pack.rev` 由 1 改 2，分别跑 `--root <A|B> --line short-drama`，
两次 stdout 逐字一致，`script` 及其下游没有任何一项变成 stale。

### 偏差 2（T1）：状态值越出定义域，调度层没兜住

`状态.json` 里 `hook_frame_video.state = "superseded"`，不在 SKILL.md 第 88–94 行定义的
五值（draft / ready / approved / blocked / stale）之内。`next_step()` 第 202 行兜底成
`可开工 {k}（{state}）`，于是总览把「可开工一个已被取代的成片」报给下一环。
新会话若照此接续，会直接去做一个废弃产物。

这与磨合记录第 14 环补记是同一类现象：状态/形态翻案后，有一层没跟着改。

### 偏差 3（T2）：形态翻案没传到调度层

`supervisor/SKILL.md` 第 34 行仍写着「文案 / AI 出镜 / 旁白 / 混剪 | 短剧专属技能**未建**，
暂由执行单承载」，而 11-10 `short-drama-trailer` v0.2 已发版（git tag shortdrama-v0.2）。
门禁表本身是过期的——「先查门禁」查到的是旧口径。

第 14 环补记说过「形态翻案要沿 方法论文档 → 执行单 → 资产 → 状态台账 → 总览标签 一路走到底，
漏掉任何一层，下一环都会拿到旧口径」。这次漏的是**入口路由表**，比上次又高一层。

## 四、方法论（一条，教学线）

**凡文档里带「自动」二字的流程承诺，必须有代码证据。**
「不靠谁记得」写在 SKILL.md、「按规则自动标 stale」写在 evidence，都不足以证明机制存在；
只有改上游、看下游变不变才算验收。这次用的副本对比法（改一份、跑两遍、比 stdout）
零风险、可复现、不碰业务数据，以后凡遇「自动传播 / 自动失效 / 自动门禁」都照这个法子验。
