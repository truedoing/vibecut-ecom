## 版本号规则

- UI 版本号独立于技能版本号。技能现在是 v0.4，UI 是 v0.3，两者不互相代表。
- 只在「页面上能看到的变化」或「口径变化」时进一位；纯 bugfix 记在本文件的「修补」里，不单独升版。
- 每个版本必须能回答：**这一版让人多看到了什么，或少犯了什么错。**

## v0.1：先有看板

**背景**：素材和文案的速度都测完了，张老师要「在文案与出片之间加一个预览分镜台」，
又补了「素材处理也需要进度查看」。于是先做一个总 UI。

**这一版解决**：
- 页面能看四个位置：整条管线、素材建库、待审文案、成片。
- 状态仍然由 `status_overview.py` 算，网页只画。
- 长跑任务先补 `progress.py` 落盘（一任务一文件、原子写、带 pid），页面能判「疑似中断」。

**这一版没解决**：
- 总览信息密度太低：3 部剧时一剧一张大卡片，30 部要滚十几屏。
- 成片页把 39 个 mp4 平铺，靠文件名猜哪条是成片。
- 分镜台明确没做。

**验证**：四页签能打开；接口 9.7 秒（后来才知道是磁盘慢）。

## v0.2：一剧一行

**背景**：张老师原话「总览有点太详细了，信息密度太低，这才 3 个片子，要是 30 个怎么看看呀。
就是一条条的，就是管线，多用图形，比如百分比表示。」

**这一版解决**：
- 一剧一行（约 62px）：三段各一条进度条 + 大号百分比，右侧整环（三段平均）。
- 细节收进「点这一行展开」。
- 搜索（找剧名）、只看没做完、排序三件小工具；纯前端过滤，不重画页面，输入框不丢焦点。
- 百分比口径写进页面图例，不让人猜。

**这一版没解决**：
- 素材盘 60 集、页面说 19 集——口径事实没摆清楚。
- `wangshen_v2.mp4` 被多算成一个成片（台账写了要改，代码没改）。

**验证**：3 部剧、19 条清单、17 条等人过目；接口从 9.7 秒降到 0.8 秒。

## v0.3：删电商线 + 预览页重做

**背景**：张老师定「分镜台最后做，先把前面的功能完善」；并且明确「没用到的电商线代码删除掉」。

**这一版解决**：
- **删电商线运行代码 89 个文件**：`src/vibecut`、`web/`、`tests/`、`pyproject.toml`、
  `scripts/migrate_from_vibecut.py`、9 个 `skills/ecommerce-*`、`skills/vibecut`。
  短剧线对它们零依赖；`assets/ai_assets` 保留（短剧技能引用它作历史存量资产）。
- **预览页按「剧 / 片子」分组**。当前成片认 `状态.json → artifacts.trailer.path`，
  D1/D2 的 `build/vN.mp4` 首次被正确认成成片。
- 每条片子显示：状态 / rev、时长、分辨率、大小、改装时间、版本切换（记住播放位置）、
  段落首尾帧、装配自检图、灯箱、键盘快捷键、`#video` 直达。
- **时长读 MP4 盒头**，不跑 ffprobe（65 MB 文件 ffprobe 要 5 秒）。
- **口径统一**：总览「出片」段与预览页同一真源；以真心 0% → 11%（2/19）。
- **风格**：12px 圆角、轻阴影、粘性导航、统一字号与留白；主色 `#2b6cb0 → #2563eb`。

**这一版没解决**：
- 分镜台、原视频预览、深色主题、30 部剧分页。
- `CLAUDE.md` / `README.md` 已在本版改成短剧线；`docs/` 里仍有电商线历史文档（保留作知识资产）。

**验证**：
- `node --check` 抽出内联 JS，通过；`python3 -m py_compile server.py`，通过。
- 无头 Chrome 渲染 `#pipeline` / `#assets` / `#review` / `#video`，四页签都有内容、无报错。
- `/video/` 带 `Range: bytes=0-1023` 返回 206、1024 字节。
- `/api/videos` 6 组、3 条当前成片、3 条旧版、33 个中间文件；`/api/pipelines` 57ms。

## 口径变更历史（最容易记错的部分）

| 项目 | 旧口径 | 现在 | 为什么改 |
|---|---|---|---|
| 剧列表 | 扫 `assets/short-drama/` | 素材根一级文件夹 | 混进 `ai_assets`；同一部剧两个名字算两条管线 |
| 成片判定 | 文件名 `sd_*` | `状态.json → trailer.path` | D1/D2 的成片在 `build/vN.mp4` |
| 素材进度分子 | 三样都齐的集数 | 三份资料按份数 | 台词全齐、只差合表会显示 0% |
| 素材进度分母 | 全剧集数 | 已动工集数 | 19/60 会把做完的活显示成 29% |
| 出片进度 | `sd_*` 数量 | 有 `trailer.path` 的片子数 | 与预览页同一真源 |
| 视频列表 | 39 个文件平铺 | 按剧 / 片子分组 | 靠文件名猜成片 |
| 视频时长 | 无 | MP4 盒头 | ffprobe 5 秒/文件，太重 |
| 总览布局 | 一剧一张大卡片 | 一剧一行 | 3 部舒服，30 部滚不完 |

## 下一版候选（按价值排序）

1. **分镜台**：左镜头清单 / 中竖屏预览 / 右属性 / 底部时间线；需要播原片、对齐原片时间轴、标切点。
2. **原视频预览**：给素材根加白名单 + Range；现在只播 `runs/` 下 mp4。
3. **素材分析页打磨**：按集 / 按人 / 按情绪查台词，接 `index.sqlite` 和 `query.py`。
4. **待审文案页打磨**：版本对比、按剧/片子筛选、文档目录树。
5. **30 部剧分页**：当前靠筛选；到 30 部再说，不提前做。
6. **深色主题**：等页面结构稳定后单独做一版。
7. **提交 `ui/`**：现在还是未跟踪状态，v0.3 适合作为第一个提交节点。
