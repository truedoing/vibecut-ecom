## 版本号规则

- UI 版本号独立于技能版本号。技能现在是 v0.4，UI 是 v0.7，两者不互相代表。
- 只在「页面上能看到的变化」或「口径变化」时进一位；纯 bugfix 记在本文件的「修补」里，不单独升版。
- 每个版本必须能回答：**这一版让人多看到了什么，或少犯了什么错。**

## v0.1：先有看板

**背景**：素材和文案的速度都测完了，张老师要「在文案与出片之间加一个预览分镜台」，
又补了「素材处理也需要进度查看」。于是先做一个总 UI。

**这一版解决**：
- 页面能看四个位置：整条管线、素材建库、待审文案、成片。
- 状态仍然由 `status_overview.py` 算，网页只画。
- 长跑任务先补 `progress.py` 落盘（一任务一文件、原子写、带 pid），页面能判「疑似中断」。

**这一版没解决**：
- 总览信息密度太低：3 部剧时一剧一张大卡片，30 部要滚十几屏。
- 成片页把 39 个 mp4 平铺，靠文件名猜哪条是成片。
- 分镜台明确没做。

**验证**：四页签能打开；接口 9.7 秒（后来才知道是磁盘慢）。

## v0.2：一剧一行

**背景**：张老师原话「总览有点太详细了，信息密度太低，这才 3 个片子，要是 30 个怎么看看呀。
就是一条条的，就是管线，多用图形，比如百分比表示。」

**这一版解决**：
- 一剧一行（约 62px）：三段各一条进度条 + 大号百分比，右侧整环（三段平均）。
- 细节收进「点这一行展开」。
- 搜索（找剧名）、只看没做完、排序三件小工具；纯前端过滤，不重画页面，输入框不丢焦点。
- 百分比口径写进页面图例，不让人猜。

**这一版没解决**：
- 素材盘 60 集、页面说 19 集——口径事实没摆清楚。
- `wangshen_v2.mp4` 被多算成一个成片（台账写了要改，代码没改）。

**验证**：3 部剧、19 条清单、17 条等人过目；接口从 9.7 秒降到 0.8 秒。

## v0.3：删电商线 + 预览页重做

**背景**：张老师定「分镜台最后做，先把前面的功能完善」；并且明确「没用到的电商线代码删除掉」。

**这一版解决**：
- **删电商线运行代码 89 个文件**：`src/vibecut`、`web/`、`tests/`、`pyproject.toml`、
  `scripts/migrate_from_vibecut.py`、9 个 `skills/ecommerce-*`、`skills/vibecut`。
  短剧线对它们零依赖；`assets/ai_assets` 保留（短剧技能引用它作历史存量资产）。
- **预览页按「剧 / 片子」分组**。当前成片认 `状态.json → artifacts.trailer.path`，
  D1/D2 的 `build/vN.mp4` 首次被正确认成成片。
- 每条片子显示：状态 / rev、时长、分辨率、大小、改装时间、版本切换（记住播放位置）、
  段落首尾帧、装配自检图、灯箱、键盘快捷键、`#video` 直达。
- **时长读 MP4 盒头**，不跑 ffprobe（65 MB 文件 ffprobe 要 5 秒）。
- **口径统一**：总览「出片」段与预览页同一真源；以真心 0% → 11%（2/19）。
- **风格**：12px 圆角、轻阴影、粘性导航、统一字号与留白；主色 `#2b6cb0 → #2563eb`。

**这一版没解决**：
- 分镜台、原视频预览、深色主题、30 部剧分页。
- `CLAUDE.md` / `README.md` 已在本版改成短剧线；`docs/` 里仍有电商线历史文档（保留作知识资产）。

**验证**：
- `node --check` 抽出内联 JS，通过；`python3 -m py_compile server.py`，通过。
- 无头 Chrome 渲染 `#pipeline` / `#assets` / `#review` / `#video`，四页签都有内容、无报错。
- `/video/` 带 `Range: bytes=0-1023` 返回 206、1024 字节。
- `/api/videos` 6 组、3 条当前成片、3 条旧版、33 个中间文件；`/api/pipelines` 57ms。

## v0.4：四段进度与深色监看风

**背景**：张老师看完 v0.3 后说「页面比较杂」；他关心的只有四件事：
素材分析完了没（百分比）、文案出了多少条（条数与百分比）、审核到哪了（百分比）、出片多少（百分比）。
另加一句「风格要符合我们的视频行业」。

**这一版解决**：
- 总览从「三段 + 整体环」改成「四段」：**素材分析 / 文案 / 审核 / 出片**。
- **文案与审核拆开**。旧口径把「清单已点头」当成文案进度，19 条里 2 条过审就显示 11%，
  看起来像文案没写。现在：文案 = 有清单的片子 ÷ 片子目录；审核 = 清单 approved ÷ 有清单的片子。
- 顶部四块总览数字；每剧一行四段；去掉底部图例、行内展开说明、排序与筛选工具。
- 深色监看风：近黑底 + 红色品牌点 + 四段各一色（蓝 / 紫 / 琥珀 / 绿）+ 大号等宽数字。
- 素材分析总览只算**已动工集数**：全局 64%，不是把未开工的 45 集算进来得出 29%。
- 素材分析页去掉表头解释，待审文案页把两段说明压成一句数字。

**四段口径**：
- 素材分析 = 已交资料份数 ÷（已动工集数 × 3）
- 文案 = 有清单的片子 ÷ 片子目录数
- 审核 = 清单 approved ÷ 有清单的片子
- 出片 = 有当前成片的片子 ÷ 有清单的片子

**验证**：以真心 素材 93%（53/57 份）、文案 19 条 100%、审核 11%（2/19）、出片 11%（2/19）；
父爱 素材 33%、文案 0 条；鸡排 素材 0%。四页签无报错。

## v0.5：从结果页变成监看页

**背景**：张老师要的不是「最后做完了没」，而是「现在跑到哪了」。
素材处理（字幕识别 / 切镜头 / 打标 / 合表）是分钟级长跑，原来页面 15 秒整页重画一次，
长任务在跑时看不到哪一集、跑了多久、还剩多久；而且只有打标一个工序在上报。

**这一版解决**：
- `progress.py` 增加 `elapsed_sec` / `eta_sec` / `alive` / `suspect`；一任务一文件，
  文件带剧名 + 集号（多部剧同时跑不互相覆盖）。
- **四个素材脚本全部接入进度**：字幕识别（按帧）、切镜头（按集）、合表（按集累计）、
  打标（已有，按帧）；装配（按任务）也接入。异常写 `failed`，进程没了页面判「疑似中断」。
- 装配 / 抽帧这类长阻塞调用每 **30 秒 touch 一次心跳**，不会被 3 分钟阈值误判成卡死。
- 页面顶部增加 **LIVE 徽标**：LIVE / IDLE / ALERT / PAUSED；每 2 秒只刷新监看面板，
  每 6 秒局部刷新总览四段数字，不整页重画。
- 监看面板每行显示：工序、剧 / 集、进度条、已完成/总数、百分比、**已跑时间、剩余 ETA、最后心跳**。
- 素材分析页：正在处理的集在表格里高亮；任务完成时表格才重画一次。
- `runs/进度/` 是运行态，已加进 `.gitignore`。

**验证**：模拟 `tag_shots 24/45 帧`（ETA 2:03）、`mix_trailer 13 段`（无总数时显示处理中）、
`segment` 断心跳（ALERT/进程不在）；素材表 ep15 行高亮；四页签无 JS 报错。

## v0.6：一剧一行，前段没完成后面就是空白

**背景**：张老师看完 v0.5 后说「视觉像表格」：四列逐行、每行重复素材 / 文案 / 审核标签；
10 部剧时看不过来。还指出测试数据里「素材 93% 却已有成片」的倒挂——
理论上前一段没完成，后面不该有数据。

**这一版解决**：
- 每部剧一行，行内一条四段进度条；**阶段名只在顶部图例出现一次**。
- 每行只显示**当前阶段**：素材 93% / 文案 19 条 / 审核 11% / 出片 11% 之一；
  右上角彩色 pill 标当前阶段。
- **阶段门禁**：当前阶段 = 第一个未完成阶段；它后面的段填充 0、变暗，不显示后面数字。
  素材没做完时，文案 / 审核 / 出片就是空白，一眼看出卡在素材。
- 顶部图例同时给「当前阶段分布」：素材 3 · 文案 0 · 审核 0 · 出片 0；
  10 部剧时一眼看批次卡在哪。
- 一行一部剧，10 部剧十行；1360 宽下整页看完，不用横向读列。
- 实时 LIVE 面板保留在行列表上方，最多显示 12 个并发任务。

**验证**：以真心素材 93%、父爱 33%、鸡排 0%；三行都在「素材分析」，
后面 9 段全部 off；图例 3 / 0 / 0 / 0；无 JS 报错。

**代价**：状态文件里已有的后段数据（测试 / 历史）会被门禁隐藏；
要查后段证据去「待审文案 / 成片预览」页，不在总览混看。

## v0.7：剧注册表上页面：J 号、活动/归档子页签

**背景**：`runs/剧注册表.json` 引入 `code` / `status` / `aliases`。
一批一批处理剪辑：只给在做（active）的剧编 J1..Jn；归档后号让出、后面的往前补，
归档那一刻的号记在 `archived_code`。页面不该把归档剧混在当前批次里。

**这一版解决**：
- 顶部加 **活动 / 归档** 子页签，默认活动；计数来自 `/api/registry`。
- 四个页签都按范围过滤：总览 / 素材分析 / 待审文案 / 成片预览。
  活动范围看不到归档剧的素材、文档、成片；归档范围单独看。
- 每行显示 **J 号**；归档行用 muted J + 「归档」pill，子行写归档日期。
- 素材下拉、待审列表、成片列表都带 J 号。
- **素材分析读覆盖率**：`cover_pct` + `target_pct` / `target_eps`；
  当前素材阶段显示覆盖率，进度条上有 60% 目标线。
- **百分比贴在阶段段内**：素材覆盖率显示在素材那一段，文案条数显示在文案段；
  已完成段打 ✓，未到段空白。行尾只留当前阶段 pill 与明细，不再放一个大百分比冒充总进度。
- **阶段完成看 `done`，不是只看 `cover_ok`**：父爱覆盖率 60% 达标，但只有台词、
  没有镜头/合表，所以仍停在素材阶段，明细写「台词 18/30 · 镜头 0 · 合表 0」。

**验证**：活动 3 / 归档 1；活动 J1 父爱 60%、J2 鸡排 0%、J3 以真心 31.7%（19/36）；
归档 J1 八零憨妻；活动视频 2 组 / 归档 4 组；活动待审 17 / 归档 7；无 JS 报错。

## 口径变更历史（最容易记错的部分）

| 项目 | 旧口径 | 现在 | 为什么改 |
|---|---|---|---|
| 剧列表 | 扫 `assets/short-drama/` | 素材根一级文件夹 | 混进 `ai_assets`；同一部剧两个名字算两条管线 |
| 成片判定 | 文件名 `sd_*` | `状态.json → trailer.path` | D1/D2 的成片在 `build/vN.mp4` |
| 素材进度分子 | 三样都齐的集数 | 三份资料按份数 | 台词全齐、只差合表会显示 0% |
| 素材进度分母 | 全剧集数 | 已动工集数 | 19/60 会把做完的活显示成 29% |
| 出片进度 | `sd_*` 数量 | 有 `trailer.path` 的片子数 | 与预览页同一真源 |
| 视频列表 | 39 个文件平铺 | 按剧 / 片子分组 | 靠文件名猜成片 |
| 视频时长 | 无 | MP4 盒头 | ffprobe 5 秒/文件，太重 |
| 总览布局 | 一剧一张大卡片 | 一剧一行 | 3 部舒服，30 部滚不完 |
| 文案进度 | 已点头 ÷ 清单数 | 有清单的片子 ÷ 片子目录 | 旧口径把「审核」当成了「文案」 |
| 审核进度 | 无独立一段 | 清单 approved ÷ 有清单的片子 | 四段拆分后，瓶颈显形 |
| 页面风格 | 浅色通用后台 | 深色监看风 | 张老师：风格要符合视频行业 |
| 总览布局（v0.6） | 四列逐行表格，每行重复四个阶段名 | 一剧一行 + 四段进度条；阶段名只在顶部图例一次 | 像报表；10 部剧看不过来；前一段没完成后面段空白 |
| 页面文字 | 底部图例 + 展开说明 | 只留数字与条数 | 每天看的人不需要解释 |
| 剧的顺序/编号 | 素材根字母序 | 注册表 `drama_order` + J 号 | 一批一批处理，编号要跟着批次走 |
| 活动/归档 | 混在一起 | 顶部子页签，默认活动 | 归档不参与这一批；素材/文档/成片一起过滤 |
| 素材分析展示 | 份数细度（pct） | 覆盖率 `cover_pct` + 60% 目标线；阶段完成看 `done` | 覆盖率是「看了多少集」，不是「做完了」 |
| 进度展示 | 15 秒整页重画、只看最终结果 | 2 秒轮询、LIVE 面板、耗时 / ETA / 心跳 | 张老师要的是工作状态监控 |
