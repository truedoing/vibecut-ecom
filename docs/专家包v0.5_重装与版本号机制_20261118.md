# 专家包 v0.5 重装 + 版本号机制修复（2026-11-18 下午）

> 背景：另一个任务 11-18 13:5x 装过 v0.5，但本会话读到的版本号还是 0.1.0。
> 查下来是"装了新版、登记没跟上 + 安装位被还原成残缺 0.1.0"。本文记录重装与根治办法。

## 一、根因（两处）

1. **安装位是残缺的 0.1.0**：`~/.workbuddy/plugins/marketplaces/my-experts/plugins/short-drama-trailer-editor/`
   只剩 6 个文件、无 skills 目录，plugin.json 写着 0.1.0。改的时间是 11-18 14:52——
   也就是 13:5x 装完 0.5 之后又被改回去了。谁改的、为什么，没查出来（不猜）。
2. **`_setup.py` 写 marketplace.json 时不写 version 字段**：登记那条一直是首次安装时的 0.1.0。
   所以就算装了 0.5，"读版本号"读到登记处还是 0.1.0。

## 二、这次做了什么

| 事项 | 做法 | 结果 |
|---|---|---|
| 备份残缺位 | 复制到 `plugin-backup/short-drama-trailer-editor_残缺0.1.0_20261118-1518/` | 6 文件，可回退 |
| 校验 0.5 包 | `/tmp/expert_v05/short-drama-trailer-editor_v0.5.zip`，84 文件 / 10 技能 / 版本 0.5.0 / sha256 be23ebfc… | 完整 |
| 正确解压 | 包内中文文件名是 GBK，用 Python 按 gbk 解码解压（unzip 会乱码） | `unz_v05/`，中文名正常 |
| 装本体 | 暂存拼好→校验→`rmtree` 旧目录→`mv` 到位（不做先删后拷） | 安装位 84 文件 / 0.5.0 / 10 技能 |
| 修登记 | marketplace.json 的 plugins[] 补 `version=0.5.0`（从 plugin.json 读，不写死） | 三处登记一致 |
| 修安装脚本 | 包内 `_setup.py` 的 entry 加 `"version": meta.get("version","0.0.0")`，并放进安装位 | 下次装不会再残留旧版本 |
| 技能没动 | 用户级 10 个技能是指向仓库的软链，仓库已是 0.5（提交 3c9c67b），复制反而破坏软链 | 保持软链 |
| 写进专家信息 | plugin.json 的 displayDescription 中英文都加了「当前版本 v0.5.0」；人格文件 frontmatter 加 `expert_version: "0.5.0"` | 专家详情里能看到版本 |

## 三、版本号机制（张老师三条要求怎么落的）

1. **装完新版本就更新本地版本号** → plugin.json 是权威源，装的时候就写对；marketplace.json 并排写同一值。
2. **专家信息里写版本号** → displayDescription 带「当前版本 vX」；人格头部带 `expert_version`。
3. **每次生成新视频时，判断资产库有新版就提示升级** → 分两层：
   - 本地能做的：`check_env.py`（仓库 `skills/short-drama-supervisor/scripts/`）加了版本核对——
     读安装位 plugin.json 当权威，并读 marketplace.json 比对，**两处不一致就报警**
     （实测：把登记改成 0.1.0，自检当场报「专家版本号对不上」）。
     函数 `_expert_version_lines()` 支持环境变量 `WB_WORKDIR` 覆盖，便于测试。
   - 本地做不到的：脚本连不上需要登录的资产库。所以自检那行明确写
     「资产库新版核对：助手开工时联网查资产库/专家包/版本.json」——
     由助手每次开工读资产库版本.json 的 `latest`，跟本地比，有新版提示人升级，不自动装。

## 四、当前状态（已验证）

- 安装位：84 文件 / 0.5.0 / 10 技能；plugin.json、marketplace.json 都是 0.5.0。
- 资产库 `专家包/版本.json`：`latest=0.5.0`，与本地一致 → 现在开工提示是「已是最新」。
- 自检：14 项全过，其中「专家版本 v0.5.0」正常显示。
- 仓库改动：只改 `check_env.py`（其余未跟踪目录是之前几轮的试验片，与本次无关，未动）。

## 五、没做 / 待定

- **没重新打 v0.5.1 的 zip，也没动资产库**（写资产库要张老师点头）。
  所以修好的 `_setup.py` 和 `check_env.py` 目前只在本机安装位 + 仓库里；
  下次若从资产库重新下 0.5 原始包安装，那两个修复会丢（除非重装后重新打补丁）。
  要不要发一个带修复的 0.5.1，待定。

  联网核对读的是资产库那份（0.5.0），不读这份，所以不影响升级提示。
- 本会话仍用启动时读到的旧人格；要用到 0.5 的完整人格，需重开会话。

## 六、下次装专家的顺序（避免再踩）

1. 包若含中文文件名，用 Python 按 gbk 解码解压，别用系统 unzip。
2. 先备份现役安装位。
3. 暂存目录拼完整 → 校验（版本号 + 技能目录数 + 关键文件）→ `rmtree` 旧目录 → `mv` 到位。
4. 登记三处版本号都写对：plugin.json（权威）、marketplace.json（必补 version）、experts.json（名字）。
5. 用户级技能若是软链到仓库，别让安装脚本覆盖——先同步仓库，再保留软链。
6. 装完跑自检，确认「专家版本 vX」那行正确、三处一致。
