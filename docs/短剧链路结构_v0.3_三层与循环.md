# 短剧链路结构 v0.3：从「七步排队」到「三层 + 小循环」

> 2026-11-10 晚，张老师一句「现在我们从头梳理一下」引出的结构性翻案。
> 过程文档双目的：技术决策存档 + 教学素材。被取代的旧说法保留原文并标注。

## 一、背景：本来只是想改个名字

第一环原来叫「选品」，第二环叫「建包」，仓库里放「多个品类」。张老师自己先起疑：
「品类这个词也不太适合，是不是改成选片、建片？」

查下来确实对不上：**品类是「一类货」**（羽衣甘蓝是一个轻食品类，下面能出很多条视频），
可短剧库里放的是《八零憨妻》这种**一部部具体的剧**。说「品类库里有多个品类」，
听的人会以为是「婆媳类 / 逆袭类 / 甜宠类」，其实是一部部的片子。

给过三个候选：选片／建片、选片／建档、选片／建包。
**张老师拍板「选片 / 建包」**——跟内部已有的产物名「剧集包」、检查脚本、台账全都对得上，改动最小。
机器字段 `select` / `pack`、存量文件名与历史文档一律不动，只改对外叫法。

## 二、转折一：第 5 步不是走一次，是反复走

本来我把链路画成七个步骤排成一队。张老师指出：

> 「5.这一步是重复的步骤，可能一个剧剪辑多个，也有可能切换剧包来剪辑，
> 要有一个切换剧包的能力，不切换就是默认。」

这一句里其实藏着**两种不同的重复**，后来必须拆开：

- **一部剧剪多条**：婆婆线、标签线是两条并列的片子，各记各的进度；
- **切换剧包**：工作对象从一部剧换到另一部，上一部的进度**挂起，不是作废**。

物理结构其实早就支持：`runs/<剧名>/<任务>/状态.json`，一部剧一个文件夹、一条片子一个子文件夹。
真正缺的是「**现在到底选中哪部剧、哪条片子**」没单独记在任何地方——
新开一轮对话，容易读错表、把 A 剧的进度报成 B 剧的。

结论：补一个 `runs/工作台.json`，只记当前选中对象；不指定就沿用，切换只改这一处。

## 三、转折二：频率分层，且 5/6/7 是个循环

> 「5/6/7 这三步有可能是一个循环调整反馈的小循环。123步频率更低，4步有可能微调。」

这句话把「一队」彻底改成「三层」：

| 层 | 内容 | 频率 |
|---|---|---|
| 慢层：剧包 | 选片 → 建包 → 素材索引，一部剧做一次 | 很低，改了才动 |
| 共用层 | AI 玩法菜单、角色与场景资产，所有剧共用 | 偶尔微调 |
| 快层：一条片子 | 方向卡+清单 → 按玩法生成素材段（可跳过）→ 拼成片 | 反复跑，构成小循环 |

**关键的省钱判断**：小循环里「改清单」不等于「重做出片」。
只改选段/顺序 → 只重拼成片，已生成的素材段留着换插入位；
改的是素材段的台词或插入位上下文 → 才重新出片。出片是整条链唯一花钱的地方。
另外，第 4 步的王婶资产是**跨剧共用**的，不属于任何剧包，所以它微调时不能把哪部剧的底座判重做。

## 四、转折三（最重要）：王婶只是一种玩法

> 「注意王婶只是AI应用策略的一种，我们后期再开发多种，可以预留一个很重要的技能栈，
> 就是应用什么样的AI策略。」

这一句把上一版结构里两处写死「王婶」的地方都推翻了：
共用层不该叫「王婶角色和场景图」，快层中间那格也不该叫「王婶那一小段」。

抽象成「**一本 AI 玩法菜单 + 一次选择**」：

- 菜单在共用层，慢慢攒；每道玩法一份配方（适合什么片子、生成什么、插在哪、
  花多少钱、哪两处必须人过目）。王婶旁观（`wangshen_weave`）是现在唯一做出来的第一份。
- 这条片子点哪道，记在状态文件顶层 `ai_strategy`；**不写＝纯剪＝默认**。
- **选玩法必须赶在排清单之前**：点了玩法清单就得留插入位，清单排完再点要推倒重排。
  所以并进已有的方向卡，人一次圈「讲哪条线 + 用哪种玩法」，**不新增环节**。
- 装配器只认「哪一段插在哪个位置」，不关心插进来的叫不叫王婶 → **加一道玩法不用改流程**。
- **现在只留位置，不建空的「AI 策略」技能**：空技能会被当成已实现，
  且没有第二道菜可参照，写出来的多半是猜的。等第二种玩法真做出来再收成技能。

## 五、结论：影响范围要按层算

| 改了什么 | 影响范围 |
|---|---|
| 换剧包（切换工作对象） | 只改工作台，挂起，不改任何片子 |
| 剧包 / 台词库 / 素材索引改了 | **这部剧下**每条片子的清单要重看；别部剧不受影响 |
| 换故事线 / 换 AI 玩法 | 这一条片子整张清单重排 → 成片重拼 |
| 某道玩法配方 / 共用角色资产微调 | **只影响点了这道玩法的片子**；纯剪与别道菜不受影响 |
| 菜单新增一道玩法 | 已有片子一条都不动 |
| 剪辑清单改了 | 成片重拼；已生成的素材段可复用，别重跑花钱那步 |
| 成片人不满意 | 只在快层三步里转，不回到底层 |

## 八、方法论（可复用到别的产线）

1. **词和东西对不上，就是结构错了的信号**。「品类」不只是名字不好听，
   它暴露了我们一直把「一部剧」当成「一类货」来管。
2. **用户说「这一步是重复的」，先分清是「多条并列」还是「一条多轮」**，
   两者的进度结构完全不同，混记会互相误伤。
3. **频率不同的东西不要排进同一条队**：慢的做一次、快的反复跑、共用的谁都能用，
   影响范围天然按层切分。
4. **花钱那步要单独保护**：循环里最容易顺手全重跑，规则要写成「改 A 不动 B」，
   并且让脚本在输出里明说，不靠人记得。
5. **认出「这只是一种，不是唯一」比多做一种更值钱**：把专有名词从流程位置里拿掉，
   换成「从菜单里选一个」，扩展性就出来了；而**空技能不等于扩展位**，
   没有第二份实例前先留数据结构，别造一个看起来能用的壳。
6. **翻案不删原文**：旧叫法、旧问法、旧结构说明都标注「已被取代」留档，
   翻案过程本身是教学素材。
