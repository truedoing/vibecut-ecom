# 纯剪预告去重方案 v0.1

> 2026-11-14 建。张老师定题：片子是甲方定的，不换剧；只求把平台重复性判定读数往下压，不求百分百。
>
> 硬规矩：**所有手段必须能脚本自动跑，不依赖剪映界面。** 换冷门剧、找花絮这类素材侧建议一概不列（张老师 11-14：「拿花絮这些和技术没关系就不列了」）。
>
> 这套组合同时服务两个用途：算法层降重、甲方肉眼能看见工作量。两边不冲突——平台认的「实质性二创」恰好也是看得见的加工。

## 一、约束与目标

| 项 | 内容 |
|---|---|
| 片子 | 甲方指定，剧不能换 |
| 方法论 | 零解说、零口播、不做片头钩子，五幕结构不变 |
| AI 原创素材 | ≤ 10 余秒，允许有成本 |
| 目标 | 降低查重读数，**不承诺百分比**，效果靠实测 |
| 实现 | ffmpeg 滤镜链 + Python 图层生成，全脚本，不碰剪映 GUI |

## 二、手段总表

### A 组：看得见的（甲方验收用）

| # | 手段 | 怎么自动做 |
|---|---|---|
| A1 | 画中画 + 模糊背景 + 缩放边框 | 原片拆两路，一路 `boxblur` 铺底，一路 `scale` 缩小叠上；圆角/边框用生成 PNG 遮罩 |
| A2 | 分屏 / 多屏错开 | `hstack` / `vstack` / `xstack`，同素材拆两屏、时间错开 |
| A3 | 全片画面参数包 | `crop`（裁 8px 起）+ `eq`（亮度对比度）+ `vignette`（暗角）+ `noise`，全镜头统一套 |
| A4 | 信息图层系统 | Pillow / SVG 渲染成 PNG 或 ASS，用 `overlay` / `subtitles` 叠：角标、进度条、章节条、动态花字、人物关系图谱、剧情时间线、片头片尾卡 |

### B 组：真正起作用的（去重主体）

| # | 手段 | 怎么自动做 | 依据 |
|---|---|---|---|
| B1 | 每个片段 7–12 秒 | 选段时按上限切断，超过就再切一刀 | 「把每一个片段控制在 7-12 秒」——分秒帧 |
| B2 | 全片 5 分钟以上 | 清单总时长校验，不足不导出 | 「做成 5 分钟或更长，重复度就会降低」——分秒帧。**现有定版 325 秒天然满足** |
| B3 | 配乐、字幕、片头尾重做 | 原始音轨全静音后重铺；字幕重生成；片头尾用 A4 生成的卡 | 「静音全部原始音频……不要只调低音量」——易有料 |
| B4 | **自己裁切，入点出点整体错开** | 清单里给一个偏移量参数，所有 in/out 统一前后推，每条片子偏移量不同 | 「入点出点不一样，画面就不一样，这是**成本最低的防重复方法**」——qishijinka |
| B5 | 不按原剧顺序、跨集倒插 | 五幕重排本来就在做，登记为去重手段；跨集片段按清单顺序自动取 | 「不能按着原剧的播放顺序去剪辑」「把第二集的片段放在第一集前面」——分秒帧 |
| B6 | 分段变速 | 每段给一个速率参数（0.98–1.05 区间），音频单独处理不变调 | 「0.98 倍和 1.03 倍之间穿插调节」——今日头条（该文可信度一般，参数需实测校准） |

**B4 是这次最该补的一条。** 前几轮讨论漏了：同一个原片，只要自己裁、进点出点跟别人不一样，就是零成本里效果最实在的一招。而且它完全能自动化——只需要在清单里加一个偏移量字段。

## 三、原字幕怎么清（张老师提的疑问）

**问题**：原剧字幕是烧进画面的硬字幕，不是独立轨，抠不掉。

**结论：不用单独做「清除」这一步，挂在 A1 里顺带完成。**

正确顺序是：

```
先裁掉字幕区  →  再缩小主画面  →  再叠到模糊背景上
```

- **首选**：`crop` 裁掉底部字幕带（一般 10–15%），再放大回原尺寸。字幕区直接出画，干净、不糊、全自动。A1 本来就要缩放，这一步不加额外工序。
- **备选**：ffmpeg `delogo` 滤镜（`delogo=x:y:w:h`），插值修掉字幕区。能自动，但会留模糊痕迹，观感打折。
- **不建议**：蒙版色块 / 局部模糊盖字幕。巨量星图公告把「局部模糊处理」明文列为「简单加工」，属于违规口径；而且挡着画面难看。

**三个要复核的点**：
1. 放大裁切会切掉画面边缘，人物构图要过一眼
2. 字幕若在顶部或中间，裁切方向要跟着改（做成配置项）
3. A1 的模糊底层如果也用同一段原片，字幕会留字影；底层建议用纯色/渐变/暗化，或同样先裁

## 四、自动化实现

| 项 | 内容 |
|---|---|
| 输入 | 剪辑清单（每段含入点出点）+ 一份数据表（人物关系、章节名、花字文案） |
| 引擎 | ffmpeg（滤镜）+ Pillow（画图层）+ Python（读清单、批量调度） |
| 关键前提 | **图层挂在哪一秒，靠清单的时间码。** 现有清单每段都有 in/out，图层能自动对齐，不用人工逐帧标 |
| 需要人给的 | 只有内容数据（人物表、章节名），不是操作 |
| 常见坑 | `drawtext` 渲染中文必须指定字体文件路径，不指定会出方块 |
| 能力边界 | WorkBuddy 可直接写这套脚本，全程不调用剪映预设 |

## 五、落在产线哪一环

**不新增环节，不动七环节结构。**

- A1–A3、B1、B2、B4、B6：装配成片时多挂一层处理链
- A4 的文案数据、B5 的重排：归在清单环节，清单里补字段
- 方向卡、选段、五幕结构、零解说规矩：全不动
- 交付包可选附一份「视觉规范卡 + 前后对照截图」，让甲方验收时直接看见工作量（不进成片，不影响观感）

## 六、验证

出片前走一遍官方预审：

> 巨量创意 → 创意工具 → 素材检测 → **素材投前分析**（巨量千川官方支持页给的路径）

该功能描述含「首发状态检测」「会不会因为内容雷同导致跑量困难」。

建议做一次对照实验：同一部剧出两版（旧办法一版、本方案一版），各测一次读数。**本方案不给任何效果百分比承诺**，读数差多少以实测为准。

## 七、已知带伤与边界

1. **这套组合还没在真实素材上跑过**，全部基于公开资料与技术原理，不是自有验证数据
2. **合规矛盾**：巨量星图公告把「仅添加水印/文字、更换滤镜、局部模糊处理、AI 更换配音」定性为「简单加工」。A3 的调色属于这一类的边缘，用之前心里有数；本方案的重心放在改画面格局（A1/A2）和内容结构（B4/B5），不是靠调色
3. **语义层不变**：台词、剧情、人物仍是那部剧，这一层躲不掉，所以才说「不求百分百」
4. **平台模型会变**，参数要跟着定期复测
5. 前几轮讨论中「原创帧占比 25–30%」「最长连续不超 10 秒」「连续 10 秒是平台红线」等说法无可靠出处，**已撤回，不进本方案**
