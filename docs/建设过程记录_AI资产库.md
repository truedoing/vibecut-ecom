# 从一个角色卡到一套 AI 资产库

> 记录时间：2026-11-03 晚
> 范围：`skills/ecommerce-ai-assets`（技能）+ `assets/ai_assets`（资产）+ tdrive `AI资产库/`

## 元信息

| 项 | 内容 |
|---|---|
| 触发需求 | 素材索引做完，要出 AI 视频，需要定妆图 + 音色 + 环境参考图 |
| 输入 | 一个产品的目标人群（视频号中老年 / 中年女性）、客单价、混剪素材的光线 |
| 产出 | 技能 1 个（4 脚本 + 2 参考文档）、角色 2 个、环境 1 个、音色锚 2 份 |
| 关键外部依赖 | ImageGen（出图）、MiMo TTS（`mimo-v2.5-tts-voicedesign` / `-voiceclone`，限时免费） |
| 纠偏次数 | 人物设定 1 次、构图 1 次、气质 1 次、音色 1 次 |
| 图片成本 | 13 张 ≈ 65–130 积分（含 4 张废稿） |

## 叙事线索（给自媒体用）

「AI 生成的人物为什么一眼假？」这个问题被追问了三轮：
第一轮是**人不对**（太老、太家常，配不上产品客单价）；
第二轮是**姿势不对**（脸看镜头就是摆拍）；
第三轮是**气质不对**（太像电视演员，家太像样板间）。

三轮下来发现，问题不在提示词写得好不好，而在**「生活感」和「年龄感」被塞进了同一个词里**。
把一张脸拆成六个独立字段之后，两个人一次出图就过了。

## 一、起点：技能该不该独立（11-03 晚）

素材分析技能刚收尾，AI 视频的第一道坎不是模型，是资产：**没有人物定妆图、没有固定音色、没有场景参考**，
每次生成都是碰运气。于是先判断这件事该不该是独立技能。

判断依据和建包那次一致——**判据是"换个品类会不会变"**：

| 会变（进品类包） | 不会变（进技能本体） |
|---|---|
| 卖点、配料、价格、竞品 | 定妆图怎么拍、音色怎么锚、编号怎么分配 |

定妆图/音色/环境的规则是**跨品类复用**的，所以独立成 `ecommerce-ai-assets` 技能。
最小单元定为**角色卡**而不是图或音色——**长相和声音是同一个身份，拆开就散了**。

## 二、第一版：技术上全对，人设上全错（21:00）

第一版的做法是「两张图」：

- `portrait_side.jpg`：3/4 侧身全身生活照
- `detail_face.jpg`：正面面部特写，image-to-image 从主图生成锁五官

出发点是避开「三视图 / character sheet」这类会触发真人内容限制的描述，走「手机随手拍」路径。
技术上跑通了，两张图确实是同一个人。

**但人设错得离谱**：`ch_001 王秀兰，50-58，家庭主妇`、`ch_002 李建国，55-62，退休职工`。
给一个 59.9 元/瓶、主投视频号中老年的产品配这对夫妻，等于告诉观众「这是给舍不得花钱的人用的」。
**客单价决定人物气质**，这条在第一版里完全没有考虑。

### 判断错误 1：把「目标人群年龄」直接当成「角色年龄」

目标人群是中老年女性，就造了 50-58 岁的主妇。但**代言角色的年龄不等于观众年龄**——
观众要看的是「比我状态好一点、但又不是小姑娘」的人，50-58 岁且家常感重的形象只会让人划走。

改为 42-46 岁城市教师 + 46-50 岁工程师，夫妻差 4 岁。**年龄是"羡慕区间"，不是"同类区间"。**

## 三、第一次纠偏：一张图两个视图（21:05）

张老师的要求很具体：**定妆照是一张图两个视图，一个侧身加一个衣服的细节，不是两张照片。**

换成单图双联：左格 3/4 侧身半身，右格同套衣服的领口袖口细节，中间一条白缝。
描述路径从「两张照片」变成「**手机相册里拼好的两张照片**」——一个生活场景，不是工作流术语。

这个改动解决了一个之前没意识到的问题：**两张独立图，右边那张面部特写其实没人用**。
Seedance 的人物参考位只需要"这个人长什么样 + 穿什么"，服装细节比正脸特写更有信息量
（面料、褶皱、起球程度直接决定 AI 镜头里的衣服像不像真的）。

同时明确了：**右格只准有衣服，不准有人脸**，否则模型会把两格画成两个人。

## 四、第二次纠偏：不要正脸，再侧一点（21:18）

第一版的 3/4 侧身，脸是**转向镜头**的——结果就是正脸感。张老师一句话点破：「侧身，不要正脸，再侧一点。」

改成接近正侧面，并且发现**光改身体不够**：模型会把头转回来。必须在提示词里同时锁三处：

1. **身体**：接近正侧面，肩膀一前一后，只能看到单侧肩线和背部轮廓
2. **脸**：接近正侧面，能看到单侧的眉骨、眼睛和鼻梁轮廓
3. **视线**：落在手里的东西上 / 望向窗外的光

少锁任何一处，模型就转回来看镜头。这条规则后来直接写进了 `build_prompt.py`。

## 五、第三次纠偏：太演员，太样板间（21:27）

图能用了，但张老师看完说：「太电视演员感了，一样要生活感，烟火气。包括场景，不要太文艺，样板房的感觉。」

复盘提示词，发现三类词是罪魁：

| 写了的词 | 真实效果 |
|---|---|
| 气质清爽干练、皮肤紧致有光泽 | 广告模特 |
| 站在窗边、表情放松自然 | 摆拍 |
| 现代简约风格、浅木色餐边柜 + 绿植 | 样板间 |

改法是把整套词换掉：

- **动作**换成下意识的日常动作：端着白瓷杯刚喝了一口、手搭桌沿；外套敞着扣子、袖子挽起、手插裤兜
- **衣服**写「穿出来的日常褶皱、有点松垮、袖口略微松了、轻微起球」
- **头发**写「有一缕没别好」「鬓角白发没染」
- **表情**写「没在配合拍照的那种」「懒得配合拍照的松弛」
- **反向锁**：「不是电视剧剧照，不是广告片，不是摆拍」
- **环境**从「现代简约」改成「一个住了几年的普通城市家庭」+ 生活痕迹清单：
  砧板上的半头蒜、一排调料瓶、斜放的锅盖、搭在水槽边的抹布、冰箱上的便签、吃了一半的面包

### 判断错误 2：以为「生活感」和「显年轻」是一回事

改完第一版，生活感到位了，但**年龄飙回 50+**——因为「皮肤有真实纹理、不磨皮」和「42 岁」在提示词里互相打架。
被打回重生成一次。

根因是**一个词同时管了两件事**。解法是拆成两个独立维度，各管各的：

- `action`（端着杯子、手搭桌沿）→ 管**生活感**
- `skin`（气色好、饱满、眼角浅细纹）→ 管**年龄感**

这两个字段分开写之后，「有烟火气但看着 42 岁」才第一次同时成立。
**这是本轮最有价值的结构性发现**，后来成了卡的标准字段。

## 六、音色：从播音员到"这个人在跟你说话"（21:11 ~ 21:24）

TTS 链路本身不复杂，两个坑。

### 坑 1：voicedesign 会漂

MiMo 有三个 TTS 模型：`-tts`（内置音色，中文只有冰糖/茉莉/苏打/白桦）、`-tts-voiceclone`、`-tts-voicedesign`。
`voicedesign` 最适合这个场景——**用一段文字描述造音色**，正好和角色卡的 `voice.desc` 对上。

但它**不返回 voice_id**：每次调用都按描述重新生成，音色会漂。直接拿它配音，两条视频里是同一个人还是两个人？

解法是把**样本音频本身当锚**：

```
voice.desc（文字） → voice.mp3（19 秒锚样本，人耳审听）→ 正式配音用 voiceclone 传这份 mp3
```

于是 `sample` 字段从"试听"升级成"角色的嗓子"。**弄丢 voice.mp3 = 这个角色找不回来了。**
这条后来写进了 tdrive 的库说明，因为团队共用时最容易在这里出事。

### 坑 2：TTS 默认是播音员

第一版 `voice.desc` 写的是「中音区偏亮，吐字清晰，语速中等偏快，从容笃定」。
张老师一听就否了：「要有生活感，不要和播音员一样，要与角色般配。」

复盘：**「吐字清晰」「从容笃定」本身就是播音腔的词**，写进 desc 等于要求它播报。
换成六条生活特征：

| 要素 | 写法 | 播音腔的反面 |
|---|---|---|
| 语速不匀 | 语速偏快但不匀 | 「语速适中」= 匀速念稿 |
| 真换气 | 句子之间有自然换气和小停顿 | 一口气到底 |
| 尾音下掉 | 尾音往下掉、不端着 | 尾音上扬 = 播报腔 |
| 近场气声 | 离话筒近带轻微气声 | 演播室距麦 30cm 的干净声 |
| 咬字放松 | 允许连读吞音 | 「吐字清晰」「字正腔圆」 |
| 情绪是判断 | 边想边说自己拿主意 | 「亲切热情」「抑扬顿挫」 |

还发现**样本文本本身也得生活化**：原来那段「人到中年才明白，吃得对比吃得多重要」是标准文案腔，
念出来必然是播音员。换成「哎，你看这个啊……就这么一小罐。我一开始也没当回事，后来一尝，还真行」
——带语气词和省略号，时长从 19 秒掉到 13 秒，语速自然就上来了。

最后是 A/B 选锚：同一个 desc 出两版候选（音色和语气都不同），人耳听、按"两人搭不搭"来选。
张老师选了林岚 B、郑海涛 A。

## 七、固化：把审美判断变成字段（21:36）

图过了之后，张老师说：「把这个资产的技能创建固定了，算法再优化一下。」

这里的关键判断是：**"固定"不是把提示词存成模板，而是把三轮纠偏的结论变成数据结构。**

### 7.1 卡结构升级

```json
"look": {
  "action": "...", "wardrobe_wear": "...", "grooming": "...",
  "skin": "...", "expression": "...", "sight": "..."
},
"garment_detail": {"garment": "...", "fabric": "..."},
"home_env": "env_001"
```

`look` 六维把"一张脸"拆到不能再拆；`home_env` 让定妆照的场景和光线从环境卡取——
**人物图和环境图必须同一套光线语言，混剪才不跳**。

### 7.2 提示词不再手写

`build_prompt.py` 从卡里拼提示词，把三锁、六维、反向锁全写进代码。里面还有一条经验算法：

```python
age = 区间下沿 - 2   # AI 出图系统性偏老，用下沿再降 2 来补偿
```

这条是实测出来的：写 42 出图 50+，写 40 出图 42-45。**与其事后返工，不如一开始就补偿。**

### 7.3 校验器从"查文件"升级成"查规则"

原来只检查图在不在、字段填没填。现在是规则级：

- 播音腔禁词（**按句判断否定语境**，所以「不要…的抑扬顿挫」不会被误杀）
- `look` 缺项（缺项会退化成摆拍/显老）
- 定妆图不是竖版
- 环境卡 `place` 写了「现代简约 / 样板间 / 北欧风」
- 环境卡没有 `props`（生活痕迹清单）

用一张违规卡做负例测试，四类错误一次全抓出来。
**这些规则本来是"人眼验收"，现在变成"提交前必过"——这才是技能真正管住的东西。**

## 八、踩坑清单

| 坑 | 现象 | 处理 |
|---|---|---|
| AI 出图系统性偏老 | 写 42 岁出图 50+ | 年龄取下沿 −2；`skin` 与 `action` 分离 |
| markdown 加粗进提示词 | `**侧身**` 的星号被当字面发给模型 | 提示词不用 `**`，要强调就重复关键词 |
| 双联图右格冒出人脸 | 模型画成两个人 | 右格明确「这一格里没有人脸，只有衣服局部」 |
| 图片右下角水印 | 「AI生成 WORKBUDDY」 | `ffmpeg crop=iw:ih-60:0:0` |
| voiceclone 报 400 | `audio.voice must be a DataURL` | 必须 `data:audio/mpeg;base64,…`，裸 base64 不行 |
| 校验器误杀否定句 | 「不要广告配音的抑扬顿挫」被判违规 | 按句判断，句中含"不要/别/不是/禁"则放过 |
| 归档后编号撞车 | `next-id` 按"现存卡数+1"算 | 改成全树扫最大号 |

## 九、关键决策点（案例用）

1. **角色卡是最小单元**，不是图也不是音色——长相与声音是同一个身份
2. **客单价决定人物气质**：59.9 元的产品配的不是主妇，是有消费能力、状态好一点的城市中产
3. **年龄是羡慕区间，不是同类区间**：观众年龄 55+ ≠ 角色年龄 55+
4. **单图双联胜过两张图**：服装细节比正脸特写更有信息量，且少一张图的成本
5. **侧身要锁三处**，少一处模型就转脸看镜头
6. **生活感与年龄感必须分开写**，混写必翻车
7. **音色的锚是音频文件，不是文字描述**——voicedesign 会漂，voiceclone 才是生产路径
8. **样本文本决定语气**：念文案腔的样本，出来的一定是播音员
9. **技能"固定"= 把判断变成字段和校验规则**，不是存模板

## 十、方法论提炼

**AI 生成质量的上限不在提示词技巧，在字段设计。**

同一句"要自然一点"，如果它是一个形容词，模型只能猜；
如果它被拆成 `action`（手在做什么）、`wardrobe_wear`（衣服皱不皱）、`expression`（配不配合拍照）三个字段，
模型就有的放矢了。

**每一次返工，本质上都是某个维度被塞进了别的维度的词里。**
返工一次，就该问：这次翻车是因为哪个维度缺失？把它补成独立字段，以后就不会再错。

这也解释了为什么"技能管不出错，管不了出不出彩"——
出不出彩仍旧靠人判断（角色搭不搭、语速对不对味），
但**一旦某条判断被重复说过两遍，它就该变成字段或校验规则**。

## 十一·补：旁白音色为什么换到豆包预设（2026-11-04 22:50 决策）

角色卡里 `voice.mp3` 是**给视频模型当音色参考**用的；真正念解说的旁白，走的是另一条链
（`ecommerce-narration`）。这一节记录的是旁白那条链的选型，不是角色资产。

**问题**：MiMo 复刻出来的旁白被听成"念稿、没激情"。量化后确认瓶颈在模型本体：
F0 跨度（p5–p95）12.3 半音、帧间音高跳变 0.465；而 AI 视频里 Seedance 演出来的是 20.0 / 0.740。
14 次抽卡验证：方差来自抽卡本身，style 写得越细反而越平——不是提示词能救的。

**四条路，最后选 A**：

| 方案 | 音色一致 | 表现力（跳变） | 成本 |
|---|---|---|---|
| **A 豆包预设音色（流畅女声）** | ✗ 换人 | **0.773** | 0 元 |
| B 豆包复刻林岚 | ✓ | 待测 | 138 元槽位 |
| C 让 Seedance 出声 | ✓✓ 同一模型 | 0.740 | 约 30 元/条 |
| D MiMo 复刻（原役） | ✓ | 0.465 | ~0 |

选 A 的判断：**试片阶段，"嗓子像不像"不值 138 元**。代价是旁白与出镜的林岚不是同一个人；
若后续要走"真人出镜 + 本人解说"，得回 B 或 C。这是产品决策，不是技术妥协。

### 三个被证实的事实（下次别再猜）

1. **豆包的情绪不是提示词给的**。同文本带 `context_texts` 13.6/14.6、不带 13.6——噪声带内；
   分段逐句给情绪更差（停顿 14 处、跳变 0.550）。**挑音色比写提示词有效。**
2. **声音复刻按"槽位"收费，不是按次**。138 元/音色买断（存储费 0）+ 字符费 3 元/万字符
   （215 字一条 ≈ 0.065 元）。预付费有 **15 次训练权**可反复重训；后付费注册与试听免费，
   但**首次正式合成即扣 138 且音色锁死、永不能再训**，7 天不调用会被删。
   → 真要复刻买预付费，别走一次性路线。
3. **`403 volc.megatts.timbre not granted` 的原因**：后付费音色要求"开通声音复刻 2.0
   **并单独开通后付费音色服务**"，只开一半就会报这个错。旧版控制台 appid+token 路线
   （`/api/v1/mega_tts/audio/upload`）报 `401 load grant not found`，老 appid 未绑服务，废弃。

## 十一·补二：一场由错误锚点引发的翻案——"MiMo 天花板"被推翻（2026-11-05 晨）

> 这一节是完整的教学叙事：一个被写成"结论"的判断，怎么被两个提问推翻，
> 又怎么在推翻的过程中催生了一个新技能。适合做"AI 时代的调试思维"案例。

### 背景：一个已经"定案"的结论

前一晚（22:50）我们刚拍板：MiMo 的表现力天花板是 13 半音/0.5 跳变，"14 次抽卡验证，
style 写得越细越平，不是提示词能救的"，于是换豆包预设音色（v5 成片）。结论看起来很扎实：
有数据、有对照、有 14 次实验。

### 第一问："MiMo 不是支持 user 人设参数吗？"

张老师给了一个带货主播的人设提示词模板（角色/场景/情绪/语速指导），让我们查文档重试。
查证结果：文档**确实**支持，而且比我们用的更细——自然语言控制放 `role: user`，还有
「导演模式」三段式（角色/场景/指导）；台词里还能嵌音频标签 `(兴奋)`。

实测：导演模式三条 9.0–11.7 半音，音频标签两条 12.8–12.9——**全部落在旧天花板以内**。
到这一步，"模型上限"的结论似乎又被验证了一遍。

### 第二问（翻案的关键）："从 AI 视频里截一段女主的声音当参考试试，是不是参考音的问题？"

换锚重跑，同一配方，唯一变量是锚：**F0 跨度直接从 12.9 跳到 21.9**。天花板不在模型，
在锚——voicedesign 造出来的 `voice.mp3` 是"标准朗读"，它把克隆输出死死压在念稿水平；
而 Seedance 在钩子里"演"出来的声音天然带表演性，拿它当参考，克隆直接继承这份表演。

### 但故事没完：三个连环坑

1. **第一个锚其实是男的。** 我按静音分段切了"前 10 秒"，张老师听出是男主——钩子是
   男女对白，开头是丈夫在说话。用音高中位数去验证，男声段居然也有 267Hz——
   **声学特征分不出说话人，只有台词内容分得清**。
2. **第二次纠正又混进了男声。** 按提示取"后面"的 8.87–15.10s，结果把妻子的第 4 句和
   丈夫的第 5 句拼在了一起。正确做法是把钩子的 5 句对白和 5 个静音段一一对位，
   只取妻子的第 2、4 句。
3. **对了位的纯女声锚只有 4.8 秒，表现力回落到 14.1。** 短锚（<10s）会让模型向自己的
   先验回归——锚的"量"和"质"都重要。

### 最终定案与新技能

张老师从两条候选里选定 cand2（14.1 半音/0.542，41.12s，几乎不用调速），宣布语音问题
告一段落，并拍板：**不再用 voicedesign 造锚，从 AI 钩子视频提取角色音样做锚**，
单独成一个技能——`ecommerce-voice-anchor`（技能矩阵第 8 个）。

这个技能把三次踩坑全部写死成行为：
- 按台词位置截取说话人，静音分段数 ≠ 台词句数就拒绝自动对位（绝不静默猜）；
- 锚总长 <10s 打警告（短锚回归先验）；
- 锚的情绪底色会带进克隆输出（本例锚录在抬杠语境里），合成时用标签法往回调。

### 方法论（值得讲的三条）

1. **"模型上限"可能是"输入上限"的误诊。** 14 次抽卡验证过的结论，换一个输入就翻了。
   控制变量法要用在正确的变量上——我们控制了文本、语速、响度，唯独没怀疑过锚。
2. **提问比实验便宜。** "是不是参考音的问题"一句话省掉的试错，比 14 次 style 调参都多。
   人对声音的听感（"这是男的""这个在抬杠"）是任何指标都替代不了的先验。
3. **错误会连环，但对位关系能兜底。** 静音分段对台词句数，数量不一致就拒绝猜测——
   把"宁可报错让人对时间轴"写成代码行为，比"聪明地猜"可靠。

> 附：这条线还顺手解了个死结——原先"好锚要从已出片的旁白裁，新角色没出过片"是循环依赖；
> 现在锚从 AI 钩子抽，而钩子是每条片的第一个产物，冷启动问题不复存在。

## 附录：复现路径

```bash
# 1. 新建一个角色（自动分配 id、预置生活感默认值）
python3 skills/ecommerce-ai-assets/scripts/new_character.py \
  --name 张秀梅 --gender 女 --age 44-48 --role "小学教师" \
  --wardrobe "浅蓝棉衬衫，米色直筒裤"

# 2. 出提示词，复制给 ImageGen（1024x1536 / high）
python3 skills/ecommerce-ai-assets/scripts/build_prompt.py --card ch_003

# 3. 裁水印
ffmpeg -i in.png -vf "crop=iw:ih-60:0:0" -q:v 2 <角色目录>/portrait.jpg

# 4. 造两版音色候选，人耳选定后改名 voice.mp3
python3 skills/ecommerce-ai-assets/scripts/gen_voice.py --card <卡> -o <目录>/voice_cand_a.mp3 --no-write
python3 skills/ecommerce-ai-assets/scripts/gen_voice.py --card <卡> -o <目录>/voice_cand_b.mp3 --no-write

# 5. 校验
python3 skills/ecommerce-ai-assets/scripts/registry.py validate
```
