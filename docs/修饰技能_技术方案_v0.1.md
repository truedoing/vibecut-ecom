# 修饰技能 技术方案 v0.1

> 2026-11-16 晚建。起因是张老师看了去重收成技能之后，一句「修饰技能也同样要创建，而且进专家包」。
>
> 11-14 立题时就写明了拆两半：**去重技能**（应对平台查重）与**修饰技能**（图层上写文字，锦上添花），
> 「修饰技能另算」。这句话当时的意思不是「不做」，是「不在去重那份文档里做」。
> 结果一等就是两天——去重那半 11-16 晚收成技能，修饰这半还在一条片子的 build 目录里跑。

## 一、管什么、不管什么

| 管（只往画面上叠字） | 不管 |
|---|---|
| 开场悬念句：逐字弹跳，末三字放大变金 | 段序、段长、选段、五幕、原片台词——一个字都不改 |
| 人物名标签：两三个名字依次滑入 | 音频。**一律不做**（零解说纯剪靠原片台词讲故事） |
| 金句上屏：从剧集包金句库自动对齐到已选段 | 画中画、扫光、裁切暗角（去重技能） |
| 收尾句：打字机逐字出 | 原剧硬字幕的重铺或翻译 |
| 左上角剧名角标 + 底部五段纯图形刻度 | 片头片尾整段重做（那是剪辑，不是文字） |
| 一份装配器能直接读的 ASS + 点睛句表 | 自己拼成片、二次编码 |

一句话：**只做「准备」，装配器负责「挂上去」。**

## 二、它和去重是什么关系

**并列，各管一半，一条命令能串起来。**

| | 去重技能 | 修饰技能 |
|---|---|---|
| 产出 | `dedup_spec.json`（画面怎么改） | `全片文字.ass` + `点睛句表.json` |
| 写进装配器的哪一段 | 顶层 `a1` / `global` / `sweep` | `decorate` 段 |
| 一条片子要不要 | 看要不要防查重 | 看要不要标题感 |

串联办法：`make_ass.py --into <dedup_spec.json>` 把自己的 `decorate` 写进那张参数表，
**路径按「相对参数表所在目录」写**（装配器就是这么解析的，写绝对路径换机器就废）。

不去重也要字幕怎么办：随便给一张参数表（去重那份最小配置也行），或者装配时单独读
`decorate.json` 并进参数表的 `decorate` 段。**两个都不做，装配器行为跟以前一模一样。**

## 三、从一次性脚本到技能：三处写死，三处翻案

原脚本 `runs/以真心守护至亲/D3_…/build/去重预览/全片版/生成全片素材.py`，
开头六行全是本机绝对路径加写死的剧名任务名，跟去重那份一样是一次性作业。
搬的时候有三处不能照抄：

### 3.1 金句 DROP：硬编码一条金句 id → 一条可重复的判据

原脚本里：

```python
DROP = {"gq_003": "与上一条只隔 2.16 秒，同属开场第一拍，叠字会糊成一片"}
```

这是人看着画面手工删的一条。收成技能后不能带这个人名答案，但**它背后的判断是可以规则化的**：

> 与上一条已上屏的金句间隔小于 **2.5 秒**，就不上屏。

实测结果：同一份 `plan.silence.json` 跑下来，自动删掉的**就是 gq_003**，
理由也还是「只隔 2.16 秒，同属一拍」。**这不是巧合，是把人的判断翻译成了阈值。**
另外加了一条同段去重（同一段只留一句），防止两种叠字。

### 3.2 五幕边界：写死 23 段的分界 → 四层取值

原脚本：

```python
ACT = [(1, 4), (5, 8), (9, 12), (13, 18), (19, 23)]
```

这是这条片子的五幕（22 段实拍 + 1 张卡）。换片子就不对。现在按顺序取：

1. `--acts "1-4,5-8,…"` 命令行
2. 剪辑清单里的 `acts` 字段（**推荐**：五幕本来就是剪辑时定的，该记在清单里）
3. 配置文件
4. 按段数等分五组（兜底，跑的时候会打印提示）

**坑在「4」上**：清单现在普遍没有 `acts` 字段，所以多数时候走等分。
23 段等分是 1-5 / 6-10 / 11-15 / 16-20 / 21-23，人工是 1-4 / 5-8 / 9-12 / 13-18 / 19-23，
底部刻度条的高亮切换点会早几秒。不影响叙事，但**跟定版不一样**。
要精确就补 `acts` 或加 `--acts`，这条写进 SKILL.md 了。

### 3.3 人名/收尾：写死的前三位和前 228 秒 → 开关加兜底

- 人物名从 `characters[:3]` 改成 `--names N`，默认 3。
- 收尾句原来写死第 228.0 秒（因为定版总长 231.73，正好末尾前 3.73 秒）。
  改成 `at_from_end: 3.73`，**换片子长度自动跟着走**，不用改数字。

## 四、最强的一条验证：与定版逐行比对

这是收成技能后唯一能证明「没走样」的办法，比看几张图都硬。

拿 11-14 那份 `plan.silence.json`（定版用的清单）跑一遍，再拿 `--acts` 把定版五幕边界喂进去，
跟当时的 `全片文字.ass` 做 `diff`：

```
最后结果：★★ 与 11-14 定版 ASS 一字不差
```

37 条事件全对——包括：

- 8 个字的逐字弹跳（每个字的 `pos` x 坐标、字号 112/132、倾角 -7…5°）
- 金句的长句自动缩字号（100 → 94）、数字段放大加金（fs116）、`\move` 与四段 `\t` 时序
- 底部 5 格刻度条与高亮切换时刻、左上角角标与竖条
- 收尾 8 个字的打字机（每个字 0.11 秒步进）

**这条验证的价值**：写错一个字号、一个坐标、一毫秒，diff 都会报出来。
反过来，只要 diff 干净，就能确定「技能版 = 定版」。

顺带暴露的一个真问题：中间三次 diff 都只差在金句字号上（94 对 100、94 对 80），
查下来不是算法错，是我把「可用宽度」的算法改了——原式 `画面宽 − 70×缩放`，
我一开始写成 `画面宽 − 左右边距×2`，可用宽度从 1060 掉到 800，字被过早缩小。
恢复原式后一字不差。

## 五、字体：41MB 不进包

四款字，都是开源可商用的：

| 用途 | 文件 | 家族名 |
|---|---|---|
| 开场悬念句 | SourceHanSansSC-Heavy.otf（17.8MB） | Source Han Sans SC Heavy |
| 角标 / 人名 | OPPOSans-H.ttf（2.2MB） | OPPO Sans H |
| 金句 | SourceHanSerifCN-Regular.ttf（14MB） | Source Han Serif CN |
| 收尾句 | SourceHanSansCN-Bold.otf（8.6MB） | Source Han Sans CN Bold |

**不进专家包。** 11-16 白天刚为了体积把 ffmpeg 从包里拿出去（37.2MB → 0.7MB），
转头塞 41MB 字库进去等于白干。放共用层 `assets/fonts/`，一部机器放一次、所有剧共用。

**缺了怎么办**：降级到这台机器自带的中文字体（Mac 苹方/宋体、Windows 雅黑/宋体），
能出片，但**字重字宽跟定版不一样**。脚本会在报告头几行明说，`decorate.json` 里也标着
「系统字体降级」。**不许当定版效果交付**——这是硬规矩，因为观感差得很明显。

量字宽也要字体：有字库用真字体量（准），没字库退到系统字体文件量（还是准），
连系统字体都找不到才按字数估——估的话会在报告里标「位置可能偏，务必抽帧看一眼」。

## 六、抽帧预览：不用装整片就能看

改一版字幕就跑一遍整片装配（十几分钟）不可行。做法：

1. 从字幕里认出上屏事件，逐字动效的（间隔 < 0.4 秒）先串成一处，否则一句话渲十几张
2. 按成片时间轴反查「第几集第几秒」，从原片抽那一帧
3. 把 ASS 里那一刻附近的事件裁成 1.6 秒小窗（时间平移，动效相对位置不变）
4. `overlay` 叠上去 → 出图

**一个坑记下来**：滤镜顺序必须是 `[底][图]overlay, ass`，
写成 `[图]ass, overlay` 会被图片盖住——第一版出图全是黑底，只有字，看不出压脸。
另外 `ass` 滤镜的 `fontsdir` 指向含中文的目录没问题，但**滤镜顺序错了不报错、只是没字**，
这种静默失败只能靠看图发现。

跑《以真心守护至亲》D3 出 9 张：开场句、5 条金句、人物名、收尾卡。
其中收尾句落在字幕卡段（没有原片帧），脚本会用纯黑底渲，只为看字排得对不对。

**看图看到的问题（如实记）**：人物名标签在 `y=350`（540 基准）正好落在人物额头一带，
新娘那一场「林秀兰 许宁 许晴」压在人脸上。这是**定版样式本身**的位置，不是脚本错。
要改就调配置 `人物名标签.names.y` 或 `at`，**还没定案**。
