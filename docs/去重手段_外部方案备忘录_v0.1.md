## 一、先说结论：这份方案有一大半跟我们对不上

它写的是**影视解说**：有解说稿、有配音、可以把原声全部删掉重录。
我们做的是**零解说纯剪预告**：全靠原剧台词讲故事，没有解说稿、没有配音、原声一条都不能删。

所以它不是「我们漏做了很多」，而是**面向另一种片型写的**。真正能直接搬的不多。
本次只取扫光一条，理由在第 4 节。

## 二、逐条判断

「能不能用」三档：**能用**（不碰硬规矩）、**不能用**（直接冲突）、**待议**（技术能做但有代价或跟旧结论打架）。

### 5.1 画面层

| 手段 | 判断 | 原因 |
|---|---|---|
| 放大 105%~112% / 适度裁边 | **能用** | 就是 A3 的裁切缩放，已在跑；v4 实测裁切 8px 单独能翻 1.3 位 |
| 水平镜像 | **不能用** | 画面有烧进去的硬字幕，镜像会把字翻反；星图公告也把这类简单加工列进违规口径 |
| 微旋转 0.8°~1.2° | **待议** | 会让画面歪，且四边要补黑边，跟「观感优先」有摩擦；未测 |
| 分段调色（每段小幅随机） | **待议** | 跟我们「每个账号固定一套参数当风格印记」的旧结论直接冲突，见第 5 节 |
| 低强度动态特效（扫光/水波/粒子/眩光） | **能用（本次只取扫光）** | 见第 4 节 |
| 叠加 5% 以下实拍纹理 | **待议** | 要额外素材源，且「纹理从哪来」没定；未测 |
| 底部 1 像素近乎透明的动态横线 | **待议** | 极轻、能自动画，但会不会被判成噪点未验证；留作备选 |
| 动态贴纸、边框、轻微位移透明层 | **能用** | 归 A4 图层系统，已在跑 |

### 5.2 音频层

| 手段 | 判断 | 原因 |
|---|---|---|
| 删除原视频全部音轨 | **不能用** | 台词就是我们的内容，删了等于把片子删了 |
| 真人 / AI 配音重新解说 | **不能用** | 零解说纯剪，没有解说稿，也不做口播 |
| 换 BGM、多轨混音、环境音 | **不能用（本项目边界）** | 11-14 已定「音频不做」，配乐照老规矩在剪映人工加 |
| 声道不对称、压缩均衡 | **不能用（同上）** | 同上 |

> 这一层整块不适用，不是「以后慢慢做」，是**形态决定的**。

### 5.3 时间与结构层

| 手段 | 判断 | 原因 |
|---|---|---|
| 镜头调序、跨集倒插 | **能用** | 就是 B5，五幕重排本来就在做 |
| 长镜头拆切、插入过渡素材 | **能用** | 归文案侧片段长度约束，且按「只报偏差不拦截」执行 |
| 每片段统一增减 0.3~1 秒 | **待议** | 改段长会撞时长账和台词节奏，属于会伤叙事的那类 |
| 局部变速 1.1~1.3 倍 | **不能用（量级过大）** | 去重技能技术方案 v0.1 已把「分段变速」整条砍掉，理由就是改段时长；1.1~1.3 比原先0.98~1.05 更猛 |
| 掐头去尾、换转场 | **能用** | 切点错开本来就在做（B4） |

### 5.4 文本与字幕层

| 手段 | 判断 | 原因 |
|---|---|---|
| 换字幕字体/颜色/位置/动画 | **不能用** | 我们不去原字幕，原剧硬字幕改不动 |
| 字幕时间轴与人声错开 0.3~0.6 秒 | **不能用** | 同上，没有独立字幕轨 |
| 解说稿改写 ≥45% | **不能用** | 没有解说稿 |
| 标题、简介、标签原创 | **能用（不归剪辑）** | 属发布侧，去重方案 v0.1 已提到「封面/标题/标签不能撞」 |
| 引用原片台词控制比例 | **不适用** | 我们整条片子就是原片台词 |

> 补一句：A4 新加的那些浮层文字（悬念句、人物名片、金句）是**另加给观众看的信息**，
> 不是「改原字幕」，两者别混。

### 5.5 文件与元数据层

| 手段 | 判断 | 原因 |
|---|---|---|
| 重新导出改 MD5 | **基础必做，但不算去重手段** | 只改文件身份，画面结构没动 |
| 随机分辨率/码率、25fps 非标准帧率、清元数据、改名 | **待议（别当主力）** | 前面查证过：重新压制、换码率对画面指纹基本无效（renderio.dev）；这份方案自己也写「不能单独依赖」 |

> 这里有个值得留档的矛盾：资料把「文件与元数据层」列为一个**维度**，
> 但按平台指纹机制（缩成 32×32 灰度、DCT 取低频），改封装和码率在比对前就被抹平了。
> **当基础卫生做可以，别拿它算去重成绩。**

### 六、组合策略 / 七、SOP / 八、检查清单

| 项 | 判断 |
|---|---|
| 「每条随机选 8~12 项组合」「定期换参数」 | **待议**，见第 5 节 |
| SOP 第 2 步「解说文案创作」、第 5 步「音频重构」 | **整段不适用**（零解说、音频不做） |
| 检查清单里「原片音轨已删除」「解说文案原创」 | **不适用**，改成我们自己的验收项 |
| 「成片观感自然、无明显过度特效」 | **能用**，正好就是张老师那条权重红线 |

## 三、一处真冲突，先记着，不自行切换

这份方案的核心原则 3 是「**随机化与差异化，避免形成固定模板指纹**」。
我前面（A 场景那轮）给过一条相反的结论：**每个账号固定一套画面参数，让它变成账号的风格印记**，
理由是平台认得出「这是某个账号的作品」，参数每条乱跳反而像批量洗稿。

**这两条是直接打架的，我不擅自改。** 三种可能：
- 两条都对，只是作用在不同层（结构层随机、视觉层固定）——这个解释最顺，但没证据
- 平台对「模板化」的判定看的是内容不是参数，那固定参数没问题
- 平台确实会抓参数指纹，那固定参数有风险

要分清得靠实测（巨量创意素材投前分析，两版对照）。**在测出来之前，现有「固定参数」口径不动。**

## 四、本次唯一采纳：斜向扫光

**为什么是它**：五维度里唯一同时满足四条——能脚本自动跑、不碰任何一条硬规矩、
只在画面最底层加东西（段序/段长/台词/五幕/原字幕全不碰）、动态且强度极低（观感优先）。
而且它是**每帧位置都不同**的一层，正好落在平台抽帧比对要抓的那一维上。

> **【已被 v4 实测取代 · 2026-11-14，原句保留不删】**
> 上面这句是当时的推断，实测不成立：宽 16% / 峰值 7% 的扫光，84 组「同一场戏换个扫光位置」对照里
> **有 48 组指纹完全一样**，平均只变了 0.6 位。淡到肉眼看不见的变化，算法也看不见。
> 新结论与完整数据见第七节。

| 项 | 值 |
|---|---|
| 做法 | numpy 预生成一个周期的柔光带帧，逐帧按相位复用，叠进 A4 帧序列最底层 |
| 形态 | 倾斜 32°、边缘高斯衰减、带轻微正弦波动，不是死板直线（首版 20° 在竖屏上偏「横」，肉眼读不出「斜着扫」，已改） |
| 强度 | 峰值不透明度 **7%**（资料建议 3%~8% 取中），暖白提亮，不做色块 **【已被 11-14 拍板取代，见第八节：改 12%】** |
| 周期 | 6.5 秒扫过一次全屏，按全局时间算，拼接处不跳变 **【已被取代：改 5.0 秒】** |
| 验证用例 | 「以真心守护至亲」D3 v3 成片，48 秒演示（编排版_v3） |
| 边界 | 只对画面有效；没测平台读数；强度是护栏，别调高 **【已被取代：强度由张老师定，见第八节】** |

**同时砍掉的**：v2 演示里两个角落小辅助窗（段 3「另一个人」、段 4「细节放大」）。
张老师 11-14 判定「小的画中画效果不好，不要了」。
段 2 那个主画面缩小＋模糊背景的大画中画**保留**（上轮确认效果明显）。
这是被推翻的旧决策，按制度保留记录、不删原文：v1 / v2 目录与报告都还在，可对照。

## 五、备选池（慢慢完善，均未验证、均未采纳）

按「离硬规矩远近」排，越靠前越容易加：

## 七、v4 补记：一场由「这么淡能起作用吗」引出的翻案

**背景**：扫光做完 v3 之后，张老师看着成片提了两个问题——「光影太宽了一点吧」「比较淡能起作用吗」。
前几轮我给这类问题的回答一直是**讲原理**：平台每 1–2 秒抽一帧、缩成 32×32 灰度、取低频算指纹，
所以「每帧位置都不同」就该有用。听起来顺，但从没拿我们自己的素材量过。

**转折**：这轮不推了，直接把那一层算法在本机复现，拿「以真心守护至亲」三个不同场景的帧，
把宽度、强度、相位挨个跑一遍，看加了光带之后指纹到底变了几位。脚本留在
`去重预览/编排版_v4/扫光有效性实测.py`，数据可复跑。

| 做法 | 平均变了几位（64 位制） | 同一场戏换相位，84 组里「完全一样」的组数 |
|---|---|---|
| v3 现状 宽 16% / 7% | 0.6 | **48** |
| 收窄 8% / 7% | 0.9 | — |
| 收窄 5% / 7%（v4 旧版，已被取代） | 0.7 | 34 |
| 收窄 5% / 4% | 0.4 | — |
| 收窄 5% / 10% | 1.2 | — |
| **收窄 5% / 12%（11-14 补测，本轮采用）** | **1.5** | **20** |
| 收窄 5% / 15% | 2.2 | **5** |

顺手把 A3 参数包拆开单测，又翻出一条：

| 单项 | 变了几位 |
|---|---|
| 亮度整体 +3% | **0.0** |
| 对比度 1.03 | **0.0** |
| 裁掉边缘 8px 再放大 | 1.3 |
| 暗角 | 1.7 |
| A3 全套合起来 | **3.7** |

**结论（三条，前两条是撤回）**：

1. **「7% 淡扫光每帧位置不同所以有效」——撤回。** 淡到肉眼看不见的变化，算法大概率也看不见，
   因为两边比的就是同一份像素亮度。84 组里 48 组完全一样，等于一半以上白扫。
2. **「整体亮度偏移能改掉好几个比特」——撤回。** 这是前几轮从公开技术文章搬来的说法，
   但那个说法的前提是「非均匀偏移」。整张图一起加亮，明暗的相对次序没变，指纹一个数都不动。
3. **真正干活的是「不均匀的局部变化」**：裁切让画面里的东西挪了位置，暗角让四周变暗中间不变。
   A3 全套 3.7 位，是 7% 扫光的六倍量级。光带收窄之所以反而好一点，也是因为它更接近局部变化，
   而不是像一条又宽又淡的带子近似于整图平移。

**方法论（这条比数据更值得留）**：
判断一个画面手段有没有用，别看它「改了什么参数」，看它**有没有改变画面内部哪块亮、哪块暗的相对关系**。
全局调色、改码率、换封装、加均匀噪点，都是「整张图一起动」，在缩成小图取低频那一步就被抹平了。
另外，**观感和有效性在这类手段上常常是同一个旋钮**——淡到看不见，多半也没用；
要真有效就得让人看得出，那时候又撞「观感优先」。所以扫光的强度不能由我拍板，得张老师权衡。

**处置**：v4 只做收窄（16% → 5%），峰值仍锁 7% 不擅自调高；
12% / 15% 的对照帧放在报告里供选择。**强度待定，未采纳、未进产线。**
> **【已被 11-14 拍板取代 · 原句保留不删】** 张老师看了 12% 的对照帧和实测数字后定：
> 峰值提到 12%、移动速度稍快。新口径与补测数据见第八节。

**边界**：以上全是本地复现的画面指纹算法，**不是平台真实模型，也不是平台公开规则**。
位数只回答「画面有没有被动到」，回答不了「平台会不会判重」。0~5 / 6~10 / 11+ 的分档来自
renderio.dev 那篇技术文章，同样不是官方阈值，只作量级参照。真要知道，仍要走素材投前分析两版对照。

## 八、11-14 补记：强度拍板、文字定版，以及「点睛句该归谁」

**背景**：v4 报告交上去后，张老师回三条——「光影提到 12%，速度稍微快一点」「文字特效不算太优秀，但合格了」「文字特效的文案应该是画龙点睛的金句，是不是在做文案时就能分析出来」。前两条是拍板，第三条是分工判断题。

**转折：查数据的时候，第三条自己冒出答案了。**

先看 v4 现在怎么挑上屏文字，脚本里是四行固定序号：

```
HOOK    = pack["hook_map"][0]["opening_lines"][0]
NAMES   = [c["name"] for c in pack["characters"][:3]]
QUOTE   = pack["elements"]["golden_quotes"][1]["quote"]
ENDLINE = pack["elements"]["ctas"][0]["text"]
```

也就是**永远取金句库第 2 条、钩子第 1 条、CTA 第 1 条**，跟这条片子讲哪条故事线、哪场戏放在第几段毫无关系。所谓「画龙点睛」其实没做到，是碰巧撞上的。

再看文案编排那一步手里有什么（实测，不是推断）：

| 查到的东西 | 数字 / 原文 |
|---|---|
| D3 清单 22 段实拍，`beats` 里带台词引用的段数 | **22 / 22**（每段写清这一拍挑起、交锋、落点，还引了原话） |
| 剧集包 10 条金句，按「同一集 + 时间点落在该段 a/b 内」自动对上的 | **7 条**（如「可我妈妈17年前就没了」→ S01 ep1 13.8~24.8s，金句@23s） |
| 段名本身就是那句金句 | `S06_谁要你的破轮椅`、`S10_你进弘业的事也别想了`、`S22_弘业不是周家开的` |
| 文案技能里早有的规矩 | 「金句抽取 ≠ 场景」「Button 收尾：**全片最好的一句台词放结尾**，不放开头」 |
| 没对上的 3 条金句 | 这条故事线没选那些段（如 ep1@3s 在 S01 入点之前），不是算法漏 |

另外一条得如实记：D1 那份清单只有 **3 / 20** 段 `beats` 带台词引用，D3 才是 22 / 22。所以「靠清单自动挑点睛句」能不能稳，取决于 `beats` 写实这条规矩有没有在文案技能里定成必填——现在没定死。

**结论（三条）**：

1. **扫光已按拍板落地**：峰值 7% → **12%**，周期 6.5s → **5.0s**（快约 23%，周期帧 156 → 120）。宽度 5%、倾角 32° 不变。补测：平均翻 **1.5 位**、84 组里仍完全一样的从 34 组降到 **20 组**——比 7% 明显好，仍不到 15% 那档。7% 旧版成片与抽帧另存 `存档_*_7pct*`，不删。
2. **文字样式定版**：四种动效、四种字体、无卡片底框，判定合格，本轮不再改。
3. **点睛句应该归文案编排那一步，但这一步还没做**：建议文案技能产出清单时顺手出一份独立的「点睛句表」（不往 `plan.json` 塞字段，避免牵动装配器和过目页、触发整套重验），修饰技能只读它、负责怎么显示。**本条是建议，未落文件、未改技能，等张老师点头。**

**方法论（这条比结论更值得留）**：判断一件事该归产线哪一步，别看「哪一步顺手」，看**哪一步握着做这个判断所需的信息**。渲染那一步只有时间码，能回答「这句挂在第几秒」；只有文案那一步知道这条片子讲哪条线、哪段是高潮、哪句是 Button，才回答得了「哪句最该上屏」。
顺带把权重红线往下延一条：**点睛句只能由选段结果推出，不能反过来影响选段**——不能为了有一句漂亮字幕去多选一段戏，那就撞了「去重让位剪辑质量」。

## 九、11-14 再补记：「金句」有两种，别只认原台词这一种

第八节把「点睛句该归哪一步」定了，但当时默认了「金句 = 剧集包里那句原台词」。
全片出片后张老师把这条前提补完整了：

> 「金句如果是从原台词提炼的，当然是强调的效果。但是金句也可以从原剧中
> 概括浓缩升华，不一定要原句。下次生产时再优化吧。」

于是两件事定下来（**本轮只记，不实施**）：

1. **原台词型**：和原剧硬字幕同句不是撞车、是**强调**。全片版画面按原样通过，不改参数、不重跑。
2. **概括升华型**：从整条故事线里提炼一句，不必是任何角色的原话。
   它是另一条正路，不是「为躲重复而手写」的破例，下次生产时试点。

**对自动化的影响（下次动手前先看这条）**：原台词带「集号 + 秒数」，
所以 `点睛句表.json` 能靠 ep+t 自动落到成片时间轴；概括句是人写的、没有集号秒数，
这套自动对齐用不上，落点规则要换成「挂在哪一拍 / 哪一幕收尾」。
这类句子更像短评，别把「零解说纯剪」带出解说味；但它天然不与硬字幕重复。
无论哪种，**都只能由文案编排那一步产出**，修饰技能只读——第八节那条分工判断不变。

> 背景→转折→结论→方法论的完整叙事线见 `docs/建设过程记录_全片一次编码.md` 六·补一。

## 十、11-14 再补记：文字动效要按句子配，别一套用到底

**张老师原话**：「下次多几个文字动效，动效种类也丰富一下，不要总是移入。」

**现状实测**：全片 ASS 37 条事件，带位移 9 条（3 个人物名 + 6 条金句）。
6 条金句全走同一个 `fx_quote`，`\move` 起止坐标、420ms 时长、淡入与缩放回弹节奏一字不差。
v4 / 全片版虽有 4 个动效函数（弹跳 / 人名 / 金句 / 打字机），但那是**按位置分工**，
不是按句子语气挑；全片落地时还把 6 条金句统一成一套，所以观感就是「总是移入」。

**结论（下次生产再做，本轮只记）**：动效扩成一组可选样式，由点睛句表按语气/作用分配，
不再靠固定位置或固定序号。候选：原地落下带轻震、逐字慢显、由糊变清、横向擦开、
整句一次亮住。均在现有字幕渲染标签范围内，**不需新库、不动装配器**，但每种都要实跑再定。

**边界**：动效权重仍小于剪辑叙事；3.2 秒完整落在所属段内不跨段；不压脸、不撞原剧硬字幕。
**本轮动作**：仅记录，成片、ASS、脚本、参数表、三个技能包全部未动。
详见 `docs/建设过程记录_全片一次编码.md` 六·补二。
