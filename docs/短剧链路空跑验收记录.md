# 短剧链路空跑验收记录（2026-11-10 17:09）

## 一、背景 → 转折

技能补齐到 9 个（含独立主管 `short-drama-supervisor`）后，张老师问：「再走一遍技能？还是直接升级为专家来测试？」

核状态文件时出现转折：`runs/` 下 4 份 `状态.json`，唯一标 `line=short-drama` 的 `D1_第1条`
是 11-09 电视框三拍旧键名，新主管读不进去；而 v0.2 定版用例 **D5_婆婆线压根没有状态文件**——
325.1s 定版片、334.84s 织入版、`plan_v3ws.json` 都在硬盘上，进度却只存在对话和文档里。

→ 结论：**直接封专家，测出来的是空壳**。专家比技能多出来的就两样——一个入口、隔几天换会话还能接上；
两样都靠这张进度表。空表会把所有编排能力测成 0 分。
→ 于是决定：不重做片子（省一次出片费用与人审），用存量产物补台账 + 空跑链路，再谈封包。

## 二、做了什么

1. 新建 `runs/八零憨妻/D5_婆婆线/状态.json`，按 v0.2 模板七环节回填。
   原则是 **路径写实、状态不美化**：
   - 没落盘的环节 `ai_assets` 标 `pending` / `rev=0`，注明 registry.json 与角色卡均未生成；
   - 带伤产物 `weave_video` 只标 `done` 不标 `approved`（「王婶说剧」四字道具未生成、
     `report.json` 未落盘、ASR 逐字比对无记录）；
   - 台词库 4 处漏收、plan 由旧流程产出、`src_dir` 写死绝对路径、全剧级选品决策书复用等，
     全部写进 `_note` / `evidence`；人审结论按当时实际回填，不事后补造。
2. 跑 `status_overview.py` 三种视图（基线 / `--detail` / `--stale-only`）。
3. 在**真实台账的临时副本**上验证依赖传播（`pack.rev` 1→2）。

## 五、第三步为什么停在门口

按 `expert-manager` 规范，专家包必须落在
`~/.workbuddy/plugins/marketplaces/my-experts/plugins`，流程是
`init → 填 plugin.json + Agent MD → 生成头像 → validate → register → package`；
资料转化模式还要求**先向用户确认推断结果**（`displayName` / `expertType` / `categoryId`）。
更要紧的是一个架构决定：**9 个技能是复制进专家包，还是引用仓库 `skills/` 路径**——
复制等于两份真相（改仓库不生效，与刚发现的 trailer 复制问题同病），引用则专家离开本机跑不了。

按 11-09 红线「验收发现偏差先报告给用户看，不要自查完自动进入修订」，
本轮停在报告：**未创建专家包、未生成头像、未改全局 marketplace.json**。

## 六、方法论（教学素材）

1. **专家化的前置不是「技能齐了」，是「有一份能被读懂的进度表」**。
   技能数量是静态清单，进度表才是跨会话接续的唯一真源。
2. **补记历史台账宁可标 `pending` / `done`，不要回填 `approved`**——
   人审结论不能事后补造，带伤项写进 evidence 比全绿更有价值。
3. 副本对比法再次生效：改一份、跑两遍、比差异，能零风险验证「自动传播」这类承诺。
