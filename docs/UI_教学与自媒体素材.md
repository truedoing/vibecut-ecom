# 短剧工作台 · 教学与自媒体素材

> 用途：把 UI 建设过程里的工程判断，变成**能讲课、能发内容**的素材。
> 每条写：钩子 → 故事 → 数字 → 可迁移原则 → 内容结构。
> 事实来源：`docs/进度台账.md` 续十一～十三、`docs/UI_技术决策.md`、`docs/UI_版本演变.md`、git 历史。
> 对外使用前先脱敏：不出现客户剧名、真实素材路径、未验收的结论。

## 一、三个用途怎么分

| 用途 | 用这份文档的哪部分 | 产出形态 |
|---|---|---|
| **生成** | 第九节「可引用数据表」、边界清单 | 团队内部复盘、交接说明 |
| **教学** | 每张卡的「可迁移原则」、第十节练习题 | 课程章节、训练营作业 |
| **自媒体** | 每张卡的「钩子 + 60 秒结构 + 画面建议」 | 视频号 / 小红书 / B站 / 公众号 |

## 二、九个可讲的故事

### 1. 进程死了 48 分钟，没人知道

**钩子**：你的脚本在跑，屏幕上一直在打印进度——但没人看屏幕。

**故事**：11-12 打标任务在 20:15 静默死掉，48 分钟后才发现。根子不是模型、不是代码，
是进度只 `print` 到终端。终端是给人「当时看」的，不是给人「事后查」的。

**数字**：48 分钟；修复后一个任务一个 JSON、原子写、带 pid；页面能自己判「标着在跑、但进程查不到或三分钟没动静」。

**可迁移原则**：**先补数据落盘，再画界面。** 没有可读的状态，看板只是给静态报告页套了一层好看的皮。

**60 秒结构**：脚本打印进度 → 进程死了没人知道 → 屏幕不是状态 → 一个任务一个文件 → 页面判疑似中断 → 原则。

**画面建议**：左边终端滚动日志，右边 `runs/进度/*.json` 的文件列表；再切到页面上的红色「疑似中断」提示。

**适合**：B站 / 公众号（工程复盘）；视频号（30 秒版只讲「屏幕不是状态」）。

---

### 2. 同一个进度，93% 还是 29%

**钩子**：同一部剧，同一个页面，换个分母，完成度从 93% 变成 29%。

**故事**：一部剧有 60 集，实际只分析了 19 集。用 60 当分母，做完的活显示成 29%；
用 19 当分母，显示 93%。两个数字都不假，但读的人会得出完全不同的结论。

**数字**：60 集全剧 / 19 集已动工；29% vs 93%。

**可迁移原则**：**口径要写进页面，不能只写在口头。** 数字旁边必须有一句话解释分子分母。

**60 秒结构**：两个百分比 → 分母是什么 → 为什么不能悄悄换 → 页面图例怎么写 → 原则。

**画面建议**：同一页面的两次数字对比；展开细节里的「全剧 60 集」。

**适合**：小红书（数据卡片）；公众号（度量专题）；内训（必讲）。

---

### 3. 9.7 秒 → 0.8 秒，慢的不是 Python

**钩子**：你以为是代码慢，其实是磁盘慢。

**故事**：总览要读 110 个 JSON，接口 9.7 秒。第一反应是优化 Python、换解析库。
实测：`os.stat` 110 个文件只要 1 毫秒，但**打开一个文件要 60 毫秒**——慢在磁盘，
可能是安全软件或同步盘在拦。于是按 `(路径, mtime, 大小)` 缓存解析结果，启动时预热，9.7 秒 → 0.8 秒。

**数字**：110 个文件 / 0.7 MB；stat 1ms；单文件打开 60ms；9.7s → 0.8s。

**可迁移原则**：**先量再改。** 不量就会去优化错误的东西，方向全错。

**60 秒结构**：卡顿 → 直觉是 Python → 拆开量 → 慢在 read 不在 stat → 缓存键怎么选 → 原则。

**画面建议**：一张「stat vs read」的对比条；火焰图不必，终端计时就够。

**适合**：B站 / 公众号（性能专题）；视频号（「别急着优化代码」）。

---

### 4. 台账写了，不等于代码改了

**钩子**：文档里写了「已修复」，代码里还是旧逻辑。

**故事**：上一轮台账写「成片判定改为只认 `sd_*.mp4`」，但代码里 `final` 仍然是 `not in_build`，
一个 10 秒的 AI 验证片被多算成一个成片。文档没错，记忆没错，代码没改。

**数字**：成片数多算 1 个；一条台账记录；一次验收回查才发现。

**可迁移原则**：**验收要回到产物上数一遍。** 台账是索引，不是证据。

**60 秒结构**：台账说改了 → 打开代码 → 没改 → 为什么会被骗 → 怎么验收 → 原则。

**画面建议**：台账截图 + 代码 diff 对照，红笔圈出 `final` 那一行。

**适合**：公众号 / 内训；视频号可以做成 15 秒「文档不是证据」。

---

### 5. 39 个文件 vs 6 条管线

**钩子**：3 部剧的时候，一剧一张大卡片很舒服；30 部就是 30 张大卡片。

**故事**：第一版总览一剧一张卡，信息全但密度低。张老师一句「这才 3 个片子，要是 30 个怎么看看呀」，
把设计从「卡片」推到「一剧一行 62px」：三段进度条 + 大号百分比 + 整环，细节点开。
成片页同理：39 个 mp4 平铺 → 按「剧 / 片子」分组，当前成片、旧版、中间文件分开。

**数字**：3 部 / 30 部；39 个 mp4 / 6 条有视频的片子 / 3 条当前成片。

**可迁移原则**：**当前样本量会骗人。** 用 10 倍数据量检查布局，再决定信息密度。

**60 秒结构**：3 部很舒服 → 30 部会怎样 → 一行一条管线 → 分组与折叠 → 原则。

**画面建议**：前后两版总览截图对比；成片页从平铺到分组的对比。

**适合**：小红书 / B站（设计专题）；内训（信息架构）。

---

### 6. 文件名不是真相

**钩子**：叫 `v1.mp4` 的不一定是中间文件，叫 `sd_006` 的也不一定是成片。

**故事**：旧逻辑按文件名认成片，只认 `sd_*`。但 D1 的成片是 `build/v1.mp4`、D2 是 `build/v2.mp4`，
真正给人看的成片被当成「装配中间文件」。改成认 `状态.json → trailer.path` 之后，
页面才和台账说的一致。找不到时也不猜，直接写「状态说已出片，但记的成片不在本机」。

**数字**：39 个 mp4；3 条当前成片；1 条状态说已出片但文件不在本机（D5）。

**可迁移原则**：**文件名是约定，状态文件才是真相。** 页面要显示「我依据什么这么说」。

**60 秒结构**：文件名误导 → 真实成片在哪 → 改认状态文件 → 找不到时如实报 → 原则。

**画面建议**：文件树 + 状态 JSON 的 `trailer.path` 高亮对照。

**适合**：公众号 / 内训；B站（数据建模）。

---

### 7. ffprobe 5 秒，读盒头 5 毫秒

**钩子**：同样是拿视频时长，一个要 5 秒，一个只要几十毫秒。

**故事**：预览页要列几十个 mp4，第一反应是 ffprobe。实测这台机上一个 65 MB 文件跑 ffprobe 要 5 秒
（磁盘慢），38 个文件预热要几分钟。改成自己跳读 MP4 的 `moov/mvhd` + `tkhd`，
几十字节就拿到时长和分辨率。

**数字**：65 MB / 5 秒 vs 几十字节；39 个文件。

**可迁移原则**：**用得起重工具，不等于该用重工具。** 先问「我到底要哪个字段」。

**60 秒结构**：要时长 → 上 ffprobe → 5 秒 → 其实只要两个字段 → 读盒头 → 原则。

**画面建议**：终端 `time ffprobe` 的 5 秒计时；右边 MP4 box 结构图（moov → mvhd / tkhd）。

**适合**：B站 / 公众号（音视频工程入门）；视频号（「杀鸡不用牛刀」）。

---

### 8. 删掉 89 个文件

**钩子**：产品聚焦有时候不是加功能，是删代码。

**故事**：仓库原来是「电商素材台」，短剧线独立后，电商的 CLI、FastAPI、React、去字幕、
9 个技能全都没人用了。它们不影响运行，但会误导下一个接手的人。一次删掉 89 个文件，
短剧线零依赖；数据和历史文档留在 git 里，需要时能翻。

**数字**：89 个文件；`src/`、`web/`、`tests/`、9 个 `skills/ecommerce-*`、`pyproject.toml`。

**可迁移原则**：**没被引用的代码不是资产，是负债。** 删除前先查引用，删除后靠 git 兜底。

**60 秒结构**：仓库里有两条线 → 短剧线独立 → 旧代码没人用但会误导 → 查引用 → 删 89 个 → 原则。

**画面建议**：`git status` 的 89 个 D；仓库目录前后对比。

**适合**：公众号 / 内训；视频号（「删代码也是功能」）。

---

### 9. 只读工作台：越权比不方便更贵

**钩子**：一个不能点的看板，反而更让人放心。

**故事**：工作台只处理 GET，POST/PUT/DELETE/PATCH 一律 405。页面不启动脚本、不写出片、
不改状态。想看进度、想看成片，页面够用；想点头、想重拼、想出片，回对话里说。
装配和发布是花钱且不可逆的动作，挡在页面外。

**数字**：4 个写方法全部 405；4 个页签；服务只监听 `127.0.0.1`。

**可迁移原则**：**先分清「看」和「做」。** 读接口和写接口的生命周期、风险、权限完全不同。

**60 秒结构**：看板想加按钮 → 按钮背后是出片和改状态 → 不可逆 → 只读 → 原则。

**画面建议**：页面上点不到「通过」；终端里一条 405 响应。

**适合**：B站 / 公众号（AI 工具设计）；内训（权限边界）。

## 六、教学用的三个练习

1. **口径设计**：一部 60 集的剧只分析了 19 集。请设计一个进度指标，要求：
   不能把做完的活显示成 29%，又不能让人误以为全剧完成。写出分子、分母、页面说明。
2. **信息架构**：给你 39 个 mp4、6 条片子、3 条当前成片。设计一个预览页：
   第一屏放什么？旧版和中间文件怎么处理？用户怎么知道哪个是成片？
3. **找欠账**：给一份台账和一份代码，找出「台账写了但代码没改」的地方。
   要求写出验收方法，而不是只说出结论。

## 七、对外边界

- **不出现客户剧名、演员名、真实素材路径**；示例统一用「某 60 集短剧」「D1 / D2」。
- **不把未验收的判断说成结论**：例如「效率提升 3 倍」这种数没有测过，不写。
- **性能数字注明环境**：这台机、这个磁盘、这个文件大小；不要当成通用结论。
- **失败和翻案优先讲**：被推翻的判断比成功结论更有教学价值，也更适合自媒体。
- **不暴露密钥**：`.env`、API key、素材盘绝对路径一律不出现在截图和文稿里。
